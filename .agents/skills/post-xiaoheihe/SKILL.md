# 小黑盒图文/推文创作 + 发布（post-xiaoheihe）

小黑盒图文/文章「选题 → 写作 → 构建草稿 → 检查」全自动流水线。核心风格为**糙汉直球调性 + cube_ 表情体系**，支持全自动上传 16:9 封面、文章激励计划勾选、AI 声明勾选及草稿校验。

---

## 零、可移植脚本结构与环境准备

脚本目录位于本 skill 下，换电脑无需改动代码，仅需调整 `config.json`：

```text
post-xiaoheihe/
├── SKILL.md            ← 本文件（日常操作主干）
├── config.json         ← 【唯一配置】CDP端口(默认9223) / Chrome路径 / Profile路径
├── install.bat         ← 一键装依赖
├── assets/
│   └── cube_emojis.json ← cube 表情全集（88 个实测代码，如 [cube_摸鱼]、[cube_干杯]）
├── references/
│   └── editor_internals.md ← ProseMirror DOM结构、选择器定位与底层报错排查
└── scripts/
    ├── start_chrome.py / .bat   拉起带 9223 端口的 Chrome
    ├── xhh_check.py             检查登录态与编辑器状态（每次必跑）
    ├── xhh_build.py             ★ 长文一键构建（插图/题注/封面/计划/存草稿）
    ├── xhh_fill_text.py         短图文纯文本填充
    └── xhh_verify_draft.py      存完草稿后自动抓包校验内容
```

> ⚠️ 运行命令统一以本 skill 目录为根目录，使用 `.venv\Scripts\python.exe scripts\xxx.py`。

## 一、标准流水线（照做即可）

### 1. 验证登录态（每次必跑）
```bash
.venv\Scripts\python.exe scripts\xhh_check.py
```
判据：右上角是否存在「登录」按钮。若未登录，使用 `start_chrome.bat` 拉起后用手机小黑盒扫码。

### 2. 准备文章素材
推荐使用**结构化区块模式（article_blocks.json）**：
```json
[
  {"type": "h2", "text": "01 工具名：一句话定调"},
  {"type": "p", "text": "正文说明或粗暴甩图流文案..."},
  {"type": "img", "path": "D:/assets/tool_01.png", "alt": "hover原生题注", "desc": "正文显示的补充说明"}
]
```

### 3. 一键构建草稿（核心命令）

```bash
.venv\Scripts\python.exe scripts\xhh_build.py ^
    --title "标题必须在30字内" ^
    --article-json article_blocks.json ^
    --cover "cover_16_9.png" ^
    --plan-article ^
    --declare-ai ^
    --save-draft
```

> ⚠️ **关键限制**：小黑盒文章标题硬性上限为 **30 个字**（若超过 30 字，后台标题栏会变红并彻底禁用「保存草稿」按钮）。建议标题控制在 24~28 字最佳！

**该命令自动执行全流程**：
- 填入标题并获取焦点；
- 按照区块顺序注入文本与分级标题；
- 自动上传 16:9 横版封面，并触发确认裁切；
- 插入图片并逐个填入 hover 原生图片题注；
- 自动勾选创作者激励【文章计划】；
- 自动勾选【包含AI辅助创作】声明；
- 点击「保存草稿」并自动跳转至草稿箱。

> 🚨 **安全提示**：小黑盒创作者后台在网页端直接点「发布」会被拦截或跳回图文编辑器。**用户拍板的唯一稳健路线**：脚本自动保存至草稿箱 → 手机小黑盒 App 确认与发布。

### 4. 校验草稿内容
```bash
.venv\Scripts\python.exe scripts\xhh_verify_draft.py --expect 5
```
脚本通过监听网络接口读回草稿箱内容，断言图片数、段落数与卡片数，确保零丢字、零丢图。

## 二、调性规则与版式规范

1. **版式标准**：
   - 开场破题第一句（不废话、直接甩痛点/动机）；
   - **紧随其后的 16:9 全宽封面图（Hero Banner）**：正文顶端大图直入眼球，且与手机端信息流缩略图完全一致；
   - `<h2>` 分节工具 + 粗暴甩图流 + 真实实操 UI 图穿插；
   - 尾部降维打击预判 + `#话题`。
2. **极简工具粗暴甩图流**：
   - 遇到单功能小工具坚决不写三段假科普，直接甩：“如它名字一样简单，没什么好介绍的。看名字懂的都懂，就一个按钮，按完收工，下面直接放图。”
3. **评论区人机降维打击**：
   - 收尾提前预判：“别天天在评论区当上下文比老旧豆包还短的劣质小模型了，见个排版整齐的帖子就只会复读‘又是AI’，稍微用用脑子，幻觉比劣质AI还重。”
4. **cube 专属表情**：
   - 正经干货少用，情绪翻车/自嘲处放 1~2 个（如 `[cube_摸鱼]`、`[cube_干杯]`）。代码详见 `assets/cube_emojis.json`。
5. **外链处理**：
   - 严禁放可点击原生外链，统一采用**中文句号法**：`github。com/xxx/yyy` 或引导 `GitHub搜索：作者/仓库`。
6. **配图质量与风控铁律（四严禁）**：
   - **严禁超过 8MB**：小黑盒单张硬上限为 10MB，超过 8MB 的 GIF 动图必须剔除或抽帧压缩，防止上传报红 `图片超过10M`。
   - **严禁混入二维码**：开源 README 常含微信群、QQ群、微信/支付宝收款赞赏码。入库必须经 OpenCV `QRCodeDetector` 扫描拦截，彻底杜绝违规引流图。
   - **严禁图标/头像充当实测图**：过滤长宽 < 360x240 或长宽接近 1:1 的应用 Logo、Icon、作者头像，只保留真实软件界面截图。
   - **严禁盲猜题注导致图文错位**：配图题注必须与图片实际显示的界面与功能严格对应，坚决杜绝把图标安上“主界面实时显示”的荒谬错位。

## 三、发布后核验清单

1. **正文与表情**：在手机 App 检查是否有排版错乱，确认 `[cube_xxx]` 正常渲染为小黑盒表情。
2. **封面与缩略图**：确认 16:9 封面无异常拉伸变形。
3. **敏感信息**：确认截图中的个人账号、密钥等已打码。
4. **草稿箱显示**：网页端点开已存草稿为空白是正常现象，内容确认以手机端和 verify 脚本为准。
