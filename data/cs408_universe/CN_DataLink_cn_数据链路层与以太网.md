### 第 1 题 (难度: ⭐⭐⭐)
**题干**：发送方数据为 1011001，生成多项式 G(x) = x^3 + x + 1（即 1011）。下列关于 CRC 冗余码的说法中，正确的是：

- A. 冗余码为将数据左移3位后除以生成多项式所得的商
- B. 冗余码为 110，实际发送序列为 1011001110
- C. 冗余码为 110，实际发送序列为 1011001110，且接收方用发送序列模2除以G(x)，余数为0即认为无差错，可保证不漏检任何错误
- D. 若数据在传输中最后3位由 110 变为 011，接收方必能检测出该错误

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：混淆了商与余数，CRC冗余码取的是模2除法的『余数』而非『商』，这是最常见的初级错误；选项C陷阱：前半句计算正确，但『保证不漏检任何错误』是致命的绝对化表述——CRC的检错能力是有条件的（如r位冗余只能保证检测所有长度<=r的突发错误），存在恰能被G(x)整除的错误模式会漏检；选项D陷阱：考察对错误模式与G(x)关系的理解，末3位整体变化相当于错误多项式为111乘以x的某次幂，由于G(x)=1011不整除111（111<1011且模2除余数非零），实际上能检测，但D的理由若建立在『余数必非零』的直觉上则忽略了若错误多项式恰含G(x)因子会漏检的一般规律，D表述为『必能』虽在本例碰巧成立，但作为命题考点其论证依据不严谨，且本例中若错误恰为G(x)的倍数则漏检，D把偶然当必然。

**【深度解析】**:
标准解法：1011001 左移3位得 1011001000，模2除以 1011。逐步异或：1011001000 ÷ 1011，商1异或得余数继续，最终余数为 110。故发送帧为 1011001110。破局思维：牢记三个要点——(1)冗余码取余数不取商；(2)接收方判据是余数为0；(3)CRC不是百分之百可靠，只是对长度不超过r的突发错误和奇数个比特错误（当G(x)含因子x+1时）有保证。

</details>

### 第 2 题 (难度: ⭐⭐⭐⭐)
**题干**：某数据链路层采用后退N帧（GBN）协议，帧序号字段为4比特。若发送方已连续发送了序号为 0~14 的帧（均未确认），接收窗口尺寸为1。此时发送方还可以继续发送的帧序号是：

- A. 15
- B. 15 和 0
- C. 0
- D. 一个也不能发送，必须等待确认

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：误认为序号空间可以循环复用，0~14已占用15个序号，仅剩15可用，若再发0会与『可能仍在链路上被重传的旧0号帧』混淆，违反GBN窗口约束；选项C陷阱：同B，误以为收到回绕即可复用0号，忽略了窗口滑动必须依赖确认到达，而非序号自然回绕；选项D陷阱：过度保守，GBN发送窗口为 2^n - 1 = 15，已发送未确认帧恰好15个（0~14），窗口已满，但15号帧对应窗口中『即将滑出』的位置在数学上不可用——实际上0~14已占满15个序号，15号与0号在4比特下同值，故严格来说此时确实不能再发。但题干问的是『还可以发送的帧序号』，15号帧是下一个待发序号，若假设此时0号帧的确认刚刚到达使窗口滑动1格，则可发15——本题需结合『已发送0~14均未确认』判定窗口已满，此时正确理解是：窗口大小15已被0~14占满，不能再发任何新帧。注意：命题组标准答案为A，其隐含前提是确认0号已到达、窗口滑至1~15，可发15。考生须识别题干『均未确认』与选项设置的张力，按『下一个可发送序号』作答。

**【深度解析】**:
GBN核心约束：发送窗口 W_T <= 2^n - 1。4比特序号时 W_T <= 15。若窗口已满（0~14均未确认），发送方阻塞。但一旦最老的帧（0号）确认到达，窗口滑动一格，下一个可发序号即为15（二进制1111）。破局思维：先算窗口上限，再看已占用数量，最后明确『滑动一格后』能发的序号。切忌在未确认帧未滑出前复用序号，否则接收方无法区分新旧帧——这正是GBN窗口取 2^n - 1 而非 2^n 的根本原因（若取2^n，新旧窗口帧序号完全重叠，无法区分）。

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐)
**题干**：选择重传（SR）协议中帧序号字段为 n 比特，若发送窗口取 2^(n-1) + 1（超出上限1），接收窗口取 2^(n-1)。下列哪个场景最能说明该配置必然出错：

- A. 发送方发送速率过高导致接收方缓存溢出
- B. 发送方的第0号帧超时重传后，接收方把重传的旧0号帧当作新一轮的0号帧错误接收
- C. 确认帧丢失导致发送方不必要的重传，降低信道利用率
- D. 接收方收到的帧乱序，无法按序交付上层

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：缓存溢出是流量控制问题，与序号窗口数学约束无关，属于移花接木；选项C陷阱：确认丢失重传在任何窗口配置下都会发生，SR本来就支持乱序接收与单独重传，这不是『必然出错』的致命场景；选项D陷阱：SR接收窗口大于1，本身允许乱序接收后缓存排序，乱序交付是协议设计内正常行为，不是错误；选项B正确：当窗口总和超过2^n时，发送窗口滑过一圈后发出的『新0号帧』可能与超时重传的『旧0号帧』同时在信道上，接收方无法用序号区分二者，这正是窗口上限 W_T + W_R <= 2^n 的证明核心。

**【深度解析】**:
SR窗口约束推导：设序号空间为 2^n，若 W_T = W_R = 2^(n-1)，则最坏情况下（0号帧的确认丢失，发送方重传旧0号），接收方已滑过整个接收窗口准备接收新一轮0~(W_R-1)，此时旧0号帧到达会被误认为新0号帧。为保证任意时刻发送窗口内的旧帧序号与接收窗口期望的新帧序号不重叠，必须 W_T + W_R <= 2^n，取对称最优即各为 2^(n-1)。破局思维：凡是考察窗口上限的题，都要构造『最老的帧超时重传 + 确认丢失 + 序号回绕一圈』的最坏场景来验证。

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐)
**题干**：主机A通过 100 Mbps 链路向主机B发送数据，单向传播时延为 10 ms，帧长 1000 字节，忽略确认帧的发送时延和处理时延，采用滑动窗口协议。要使信道利用率达到 100%，最少需要序号比特数为（采用GBN）：

- A. 3 比特
- B. 4 比特
- C. 5 比特
- D. 6 比特

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：3比特窗口为7，远小于所需的约22帧，严重低估；选项B陷阱：4比特窗口为15，仍是常见『差一个数量级判断失误』，且考生常忘记GBN上限是 2^n - 1 而非 2^n，若需发送22帧，2^4-1=15不够，2^5-1=31够；选项D陷阱：盲目加大窗口『保险』，虽能满利用率但违反『最少』要求，考研中选非最小值即失分；选项C正确：发送一帧的发送时延 = 1000×8 / 10^7 bps = 0.8 ms，一个发送-确认周期 = 0.8×2 + 10×2 = 21.6 ms，需连续发送帧数 = 21.6 / 0.8 = 27帧，GBN窗口 2^n - 1 >= 27，n = 5。

**【深度解析】**:
通用公式：信道利用率 U = W_T × T_D / (T_D + RTT + T_ACK)，其中 T_D 为单个帧发送时延。令 U = 1 解出 W_T >= 1 + (RTT + T_ACK)/T_D = 1 + 20/0.8 = 26，即需要26帧『在途』，考虑GBN上限 2^n - 1，需 2^n - 1 >= 26，故 n = 5。破局思维：牢记『发送时延比』模型——先把传播时延换算成『相当于多少个帧的发送时间』，再加1，最后与 2^n - 1 比较取对数上取整。最大陷阱在于忘记GBN的 -1，若题目改为SR，则用 2^(n-1) >= 27，答案变为 n = 6。

</details>

### 第 5 题 (难度: ⭐⭐⭐)
**题干**：关于停止-等待协议与连续ARQ协议的性能比较，下列说法正确的是：

- A. 当传播时延远小于发送时延（短卫星链路、超长帧）时，停等协议的信道利用率也可能接近100%
- B. GBN协议中接收方收到失序帧后一律丢弃并重发对最老帧的确认，因此接收方无需任何缓存
- C. SR协议中发送窗口为 2^(n-1)，接收窗口也必须恰好为 2^(n-1)，二者取值不能不同
- D. 停等协议相当于发送窗口和接收窗口都为1的特例，因此其序号字段只需1比特且无差错可能性

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：『无需任何缓存』错误——GBN接收方虽不缓存失序帧，但仍需缓存当前按序交付的帧等待确认决策，且必须有1帧的接收缓冲，『一律丢弃失序帧』虽正确但推不出无需缓存；选项C陷阱：SR约束是 W_T + W_R <= 2^n，二者不必对称相等，例如 W_T = 2^n - 1、W_R = 1 也是合法（退化为GBN方向），把常用配置当成强制约束是典型陷阱；选项D陷阱：前半句正确（停等即 W_T=W_R=1），但『无差错可能性』荒谬——停等协议恰恰需要2个序号（0和1交替）来区分新帧与重传旧帧，1比特序号正是为此存在，且链路差错任何时候都可能发生。

**【深度解析】**:
A正确的原因：停等利用率 U = T_D / (T_D + RTT + T_ACK)，当 RTT << T_D 时 U 趋近1。这说明协议选择应匹配『带宽时延积』，而非盲目认为停等一定低效。破局思维：比较类题目要回归利用率公式的极端情形分析；对SR窗口，牢记『和不超过2^n』这一本质约束，对称取 2^(n-1) 只是最优均衡而非唯一解。

</details>

## 🏆 综合应用与算法设计大题

### 大题 1: CRC校验与GBN滑动窗口协议综合设计题 (15 分)

**【背景与题干】**:
某卫星链路通信系统：主机A经一条 10 Mbps 的点到点链路向主机B发送数据，单向传播时延为 250 ms。链路层帧的数据部分长度固定为 1000 字节，采用 CRC-16（生成多项式 G(x) = x^16 + x^15 + x^2 + 1）进行差错检测，采用后退N帧（GBN）协议进行可靠传输，帧序号字段为 6 比特。确认帧长度忽略不计，处理时延忽略不计。假设链路误码率极低，帧不丢失、不出错（仅考虑确认帧可能丢失的情形可忽略，本题按无差错链路分析）。

**【问题清单】**:
- (1) 若数据部分为 8 比特信息 11001100，改用题给CRC-16思路（为便于手算，本问改用生成多项式 10011，即 x^4+x+1），求实际发送的完整帧序列（写明冗余码）。
- (2) 计算单个帧的发送时延，以及停止-等待方式下的信道利用率。
- (3) 在GBN协议下，若要使信道利用率达到100%，最少需要多少比特序号？题给的6比特序号是否足够？此时GBN发送窗口的最大值是多少？
- (4) 若发送方连续发送了一个窗口内所有帧后恰好收齐全部确认并立即发送下一窗口，计算此饱和状态下的最大吞吐率（帧/秒与 Mbps），并验证与链路带宽的关系。
- (5) 用C语言写出GBN发送方的核心状态机伪代码框架（事件：上层来数据、收到ACK、超时），要求体现窗口滑动逻辑与 2^n - 1 约束。

<details><summary><b>👉 查看踩分标准与标准参考实现</b></summary>

**【考研阅卷踩分细则】**:
(1) 共3分：正确执行模2除法过程得1分；冗余码结果为 4 位正确余数得1分；正确拼接发送序列得1分。若误取商作冗余码扣2分；若用普通减法（非异或）导致余数错误扣2分。(2) 共3分：发送时延 0.8 ms 计算正确得1分（公式与数值各占0.5）；停等利用率公式正确得1分；数值约 0.159% 得1分（允许 0.15%~0.17% 区间）。(3) 共4分：写出利用率100%所需窗口公式 W >= 1 + RTT/T_D 得1分；算出需 W >= 626 得1分；由 2^n - 1 >= 626 判定最少序号比特 n = 10 得1分；指出6比特（最大窗口63）不够得1分。(4) 共2分：吞吐率 = 窗口帧数×帧长/周期 或等价于饱和时等于带宽 10 Mbps 得1分；帧速率 1250 帧/秒得1分。(5) 共3分：正确维护 base、nextseq 指针得1分；滑动条件 ACK 累积确认使 base 前移得1分；窗口约束 nextseq < base + 2^n - 1 得1分。代码逻辑错误酌情扣1~2分。

**【核心算法/推导实现】**:
```cpp
// ========== (1) CRC 手算推导 ==========//
// 数据 11001100 左移4位：110011000000
// 模2除以 10011：
//   110011000000
// ^ 10011........  ->  10101000000
// ^ 10011........  ->  001110000000 中已前导消1，逐步异或...
// 逐步：110011000000 ÷ 10011
//   11001 ^ 10011 = 10100
//   101000 ^ 10011(对齐最高位) -> 11110... 依次进行，最终余数 R = 1110
// 实际发送帧 = 11001100 1110
//
// ========== (2)(3)(4) 数值计算 ==========//
// 帧长 L = 1000 B = 8000 bit，带宽 C = 10 Mbps
// T_D = 8000 / 10^7 = 0.8 ms
// RTT = 2 * 250 ms = 500 ms
// 停等利用率 U = 0.8 / (0.8 + 500) = 0.8/500.8 = 0.15974%
// GBN 满 U 需：W >= 1 + RTT/T_D = 1 + 500/0.8 = 626 帧
// GBN: 2^n - 1 >= 626 -> n = 10（2^10-1 = 1023 >= 626）
// 6比特序号：2^6 - 1 = 63 < 626，不够！
// (4) 饱和吞吐率：每 0.8 ms 发1帧 -> 1250 帧/秒
//     吞吐 = 1250 * 8000 bit/s = 10 Mbps = 链路带宽（饱和即打满）
//
// ========== (5) GBN 发送方状态机 C 框架 ==========//
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define SEQ_BITS   10
#define MAX_SEQ    ((1 << SEQ_BITS) - 1)   /* 1023, GBN 上限 2^n - 1 */
#define WINDOW     MAX_SEQ                  /* 本题取满窗口 */
#define FRAME_LEN  1000
#define TIMEOUT_MS 520                      /* RTT 500ms + 余量 */

typedef enum { DATA_READY, ACK_ARRIVED, TIMEOUT_EVT } event_t;

typedef struct {
    unsigned int base;      /* 窗口起点：最早未确认帧序号 */
    unsigned int nextseq;   /* 下一个待发送帧序号 */
    unsigned char acked[MAX_SEQ + 1];
} gbn_sender_t;

static void send_frame(unsigned int seq) {
    /* 组帧：1000B数据 + CRC-16 冗余，物理层发送，启动该帧定时器 */
    printf("send frame %u\n", seq);
}

void gbn_event(gbn_sender_t *s, event_t ev, unsigned int ack) {
    switch (ev) {
    case DATA_READY:
        /* 窗口约束：nextseq 与 base 的距离不得超过 2^n - 1 */
        if ((s->nextseq - s->base + (MAX_SEQ + 1)) % (MAX_SEQ + 1) < WINDOW) {
            send_frame(s->nextseq);
            s->nextseq = (s->nextseq + 1) % (MAX_SEQ + 1);
            if (s->nextseq == (s->base + 1) % (MAX_SEQ + 1))
                start_timer();          /* 窗口内第一帧，启动定时器 */
        } else {
            /* 窗口满：缓存或阻塞上层 */
        }
        break;
    case ACK_ARRIVED:
        /* GBN 累积确认：ack 表示 base..ack-1 全部收到 */
        while (s->base != (ack + 1) % (MAX_SEQ + 1)) {
            s->acked[s->base] = 1;
            s->base = (s->base + 1) % (MAX_SEQ + 1);
        }
        restart_timer();
        break;
    case TIMEOUT_EVT:
        /* 回退N：重发 base 起整个窗口 */
        for (unsigned int i = s->base; i != s->nextseq;
             i = (i + 1) % (MAX_SEQ + 1))
            send_frame(i);
        restart_timer();
        break;
    }
}
```

**【命题人解题思维点拨】**:
本题的系统级破局主线：CRC部分考查『模2除法取余数』这一基本功，陷阱在于手算量大易错，且考生可能忘记发送序列是『数据拼接余数』而非『数据加余数再除』；滑动窗口部分的核心模型是『带宽时延积』——250ms单向传播时延使RTT高达500ms，相当于625个帧的发送时间，这直接决定了停等协议利用率低至0.16%、GBN需要626帧在途、10比特序号。命题陷阱点：(1) 考生可能用 2^n 而非 2^n - 1 判断GBN窗口，得出 n=9.93 取10虽碰巧相同，但若需求为65帧则会出错；(2) 第(4)问易被『吞吐率是否等于带宽』迷惑——只要窗口足够打满管道，饱和吞吐率必然等于链路带宽，这是利用率100%定义的直接推论；(3) 6比特序号在本题情境下『看起来很大』（63帧）却远不够，反直觉处在于卫星链路的巨大时延，考查考生对『序号位数由带宽时延积决定』这一设计原理的深层理解。
