## 🎯 高陷阱单选专项演练

### 第 1 题 (难度: ⭐⭐⭐⭐)
**题干**：设互斥信号量 mutex 的初值为 1，某临界区代码为：wait(mutex); 临界区; signal(mutex);。若某进程在临界区内执行时被剥夺 CPU，且此后再也不被调度，其余进程仍在正常调度运行，则关于 mutex 当前值及相关进程状态的描述，正确的是

- A. mutex 的值为 0，其他进程处于阻塞队列中等待被唤醒
- B. mutex 的值为 -1，有一个进程在阻塞队列中，其余进程可正常自旋检测
- C. mutex 的值为 0，第一个再次执行 wait(mutex) 的进程将阻塞，且在当前进程被换出调度前所有进程都无法进入临界区
- D. mutex 的值保持为 1，因为记录型信号量的 wait 操作由系统内核原子执行，进程被剥夺 CPU 不影响信号量状态

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：认为值为 0 时就有进程阻塞，混淆了『值为0表示资源恰好用完但无人等待』与『有等待者时值为负』两种状态，此场景尚无新进程执行 wait，故阻塞队列为空；选项B陷阱：把 mutex 值想成 -1，这是『已经有一个进程阻塞后』的值，而题干中该阻塞尚未发生；且记录型信号量不存在自旋检测，等待即进入阻塞队列；选项D陷阱：信号量初值确为1，但当前进程已完整执行了 wait 操作使值减为 0，进程被换出并不回滚已完成的 P 操作，这是对『原子性』的错误外推。

**【深度解析】**:
记录型信号量 wait(S) 的语义是 S.value 减 1 后若小于 0 则阻塞。当前持锁进程已使 mutex 值变为 0（资源被占用、无等待者）。此后任何进程执行 wait 都会将值减为 -1 并把自己挂到阻塞队列。由于持锁进程永不释放（不再被调度），系统将出现事实上的永久互斥失效——这正是死锁/饿死的一种极端形态。破局关键：分清『值减小』发生在 P 操作执行时刻，『阻塞』发生在值小于 0 的时刻，两者不必然同时发生。

</details>

### 第 2 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：生产者-消费者问题中，缓冲区大小为 n。某同学的代码如下（生产者/消费者各一个互斥信号量 mutex1、mutex2 分别保护放入与取出操作）：
生产者：wait(mutex1); wait(empty); 放产品; signal(full); signal(mutex1);
消费者：wait(mutex2); wait(full); 取产品; signal(empty); signal(mutex2);
下列关于该代码的判断，正确的是

- A. 代码正确，因为生产者和消费者使用不同的 mutex，二者操作互不干扰，且 empty 与 full 保证了同步
- B. 缓冲区满时系统可能死锁：生产者持有 mutex1 后阻塞在 wait(empty)，而消费者需先通过 wait(mutex2) 才能唤醒它，但 mutex2 并未被生产者占用，故消费者仍能正常运行并最终解除阻塞
- C. 缓冲区满时可能死锁：生产者持有 mutex1 阻塞在 wait(empty)；若缓冲区为空且消费者已持有 mutex2 阻塞在 wait(full)，则双方互相等待对方的 signal，系统死锁
- D. 代码仅在缓冲区大小 n=1 时正确，因为此时 empty 和 full 的初始值使两类 P 操作天然串行化

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：只看到『用了同步信号量』这一形式要素，未检查 P 操作顺序。实现同步的 wait 必须在实现互斥的 wait 之前，本代码顺序颠倒，缓冲区非空非满的常态下甚至会发生数据竞争（生产者持 mutex1 放产品的同时消费者持 mutex2 取产品，破坏缓冲区一致性）；选项B陷阱：前半句对，后半句逻辑断裂——即使当前消费者能运行，当它取出最后一个产品前恰好也持有 mutex2 而缓冲区同时变空，两个持锁阻塞叠加即死锁，B 只考虑了单一故障场景；选项D陷阱：n=1 并不能修复『同步 P 在互斥 P 之后』的结构性错误，只是死锁概率降低，属于用特殊值掩盖一般性缺陷。

**【深度解析】**:
经典结论：实现同步的 wait 应放在实现互斥的 wait 之前，否则可能出现『持锁等资源』的竞争条件。本题陷阱在于给生产者、消费者配了不同 mutex，看似分散了锁，实则扩大了死锁面。正确写法：生产者 wait(empty); wait(mutex); 放入; signal(mutex); signal(full);。破局思维：看到『先互斥后同步』立即扫描是否存在双方各持一锁、互等对方 signal 的环形等待链。

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐)
**题干**：桌上有一只盘子，每次只能放入一个水果。父亲专门放苹果，母亲专门放橘子，儿子专门吃橘子，女儿专门吃苹果。若将信号量 plate（盘子空否）初值设为 1，apple 初值为 0，orange 初值为 0，则下列分析正确的是

- A. 该问题与单缓冲区生产者-消费者问题完全同构，plate 相当于 empty，apple/orange 相当于 full，可按标准模板直接套用
- B. 需要将 plate 拆分为两个信号量 plate_a 和 plate_o 分别给父母使用，否则父亲和母亲可能同时向盘子放水果
- C. 由于父母共享盘子这一互斥资源，plate 必须作为互斥信号量由父母的临界区同时使用，apple 与 orange 作为同步信号量由儿女使用，三者缺一不可
- D. 可以省略 plate，仅用 apple 和 orange 初值设为 1 即可正确工作，因为每次只放一个水果的约束已由它们体现

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：『同构』说法有致命缺陷——标准单生产者只有一个生产者进程，本问题有两个生产者（父、母）竞争同一缓冲区，plate 同时承担『互斥』与『同步』双重身份，直接套模板会漏掉父母互斥的 P(plate) 设计细节；选项B陷阱：拆成两个 plate 信号量后，父亲的 plate_a=1 与母亲的 plate_o=1 各自独立，父亲放入苹果后只 signal(apple)，母亲的 plate_o 仍为 1，母亲可与父亲同时放水果，互斥被彻底破坏；选项D陷阱：apple、orange 初值为 1 意味着盘子里『预先存在一个苹果和一个橘子』，违反题目『每次只放一个』的初始空盘条件，且儿子、女儿可同时取走两个水果，同步语义完全错误。

**【深度解析】**:
多生产者-多消费者问题的核心：缓冲区容量为 1 时，互斥信号量与『空缓冲区』同步信号量合并为同一个 plate，但必须正确写出父母各自 wait(plate) 与儿女各自 signal(plate) 的配对关系。注意镜像结论：若缓冲区容量大于 1，则必须额外引入独立互斥信号量 mutex，因为此时 empty 与互斥不能再合并。破局思维：先画进程-资源关系图，判断每个信号量究竟服务于『互斥』『同步』还是『两者兼有』。

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐)
**题干**：读者-写者问题采用写者优先策略：设置读计数器 count、互斥信号量 rmutex（保护 count）、写互斥信号量 wmutex，以及实现写者优先的关键信号量 w 和计数器（或标志）。与『读优先』策略相比，写者优先的核心机制是

- A. 让写者在执行 wait(wmutex) 之前先执行 wait(w)，且读者在进入读操作前后各增加一次 wait(w)/signal(w)，使后续到达的读者被阻塞在 w 上，从而给已等待的写者让路
- B. 将读操作的优先级整体调低：读者执行 wait(rmutex) 前必须先获得 wmutex，即读者也直接竞争 wmutex，使写者与读者在同一队列中按 FIFO 排队
- C. 每当有写者到达时，内核通过系统调用挂起所有正在读的读者进程，待写者完成后再恢复它们，这需要内核提供进程挂起原语支持
- D. 给写者设置更高的时间片轮转优先级并禁止读者响应中断，从调度层面保证写者先于读者获得 CPU

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：让读者直接竞争 wmutex 并不能实现写优先——读者会持续到达并排在队列中反复获得 wmutex，反而退化成读优先甚至造成写者饿死；正确机制是读者『借道』w 阻塞后续读者，写者独占 w；选项C陷阱：写优先完全由用户级信号量逻辑实现，无需内核挂起原语，且挂起正在读的读者会破坏临界区原子性、开销巨大，属于不存在的『伪机制』；选项D陷阱：混淆了『进程调度优先级』与『同步策略优先级』。写者优先是同步逻辑层面的公平性设计，靠信号量顺序实现，与 CPU 调度优先级、时间片无关。

**【深度解析】**:
读优先的问题：只要 count>0，新读者源源不断进入，写者可能无限期等待（写者饿死）。写优先通过增加信号量 w 实现『闸门』：第一个到达的读者在 wait(w) 处堵住所有后续读者，一旦写者执行了 wait(w)，后续读者全部排在 w 队列之后，写者完成 signal(w) 后才放行。注意还有一个隐藏陷阱：count 也需要被读者互斥访问（rmutex），若省略 rmutex 会导致 count 更新竞争。破局思维：区分『读优先（简单计数器版）』『写优先（加 w 版）』『读写公平法』三套代码的差异点在于 wait(w) 的位置。

</details>

### 第 5 题 (难度: ⭐⭐⭐⭐)
**题干**：五位哲学家围圆桌就餐，每两人之间有一支筷子，共 5 支，均由互斥信号量 chopstick[0..4]（初值均为 1）表示。某方案规定：奇数号哲学家先拿左边筷子再拿右边筷子，偶数号哲学家先拿右边筷子再拿左边筷子。关于该方案能否防止死锁，正确的分析是

- A. 能防止死锁，因为相邻哲学家拿第一支筷子的方向相反，破坏了『环路等待』条件
- B. 不能防止死锁，因为 1 号和 2 号哲学家可能同时伸手分别拿到各自的左边筷子，形成环路
- C. 能防止死锁，但原因是破坏了『请求与保持』条件——哲学家要么同时拿到两支筷子，要么一支都不拿
- D. 不能防止死锁，因为当 5 位哲学家同时饥饿时，奇数号先拿左、偶数号先拿右，5 支筷子恰好被 5 人各持一支，形成 5 节点的环形等待

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：举的反例不成立——1 号先拿左（筷子1），2 号先拿右（筷子1），两者竞争的是同一支筷子，仅一人成功，失败者阻塞时未持有任何筷子，无法形成持有一支再等一支的链；选项C陷阱：方案确实防死锁，但归因错误。『一次性申请全部资源』才破坏请求与保持条件；本方案每人仍是先拿一支再申请第二支，请求与保持条件并未破坏，防死锁的真正原因是破坏环路等待；选项D陷阱：『5 人同时饥饿且各拿一支』是全部同向（都先拿左）时的死锁场景；本方案中 0 号（偶）先拿右即筷子4，与 4 号（奇）先拿左即筷子4 冲突，二者必有一人拿不到第一支筷子就阻塞且两手空空，环链断裂，不会 5 支筷子被分完。

**【深度解析】**:
逐边验证资源分配图：奇数号 i 先申请 chopstick[i]（左），偶数号 i 先申请 chopstick[(i+1)%5]（右）。相邻两人对『两者之间的筷子』申请方向相反，必发生竞争且失败者不持有资源。尝试构造环路等待：需要每个进程都持有一支并等待下一支，但由于相邻竞争者方向相反，总存在至少一位哲学家的第一支筷子被邻居抢走，链条断开。对比三种经典防死锁方案：最多 4 人同时入座（破坏请求保持+限制并发）、一次性拿两支（破坏请求保持）、奇偶分向/资源编号（破坏环路等待）。破局思维：验证防死锁方案时，试图手工构造出完整的循环等待链，构造不出来即为可行。

</details>

### 大题 1: 睡眠理发师问题的信号量设计与死锁分析 (15 分)

**【背景与题干】**:
某理发店有一名理发师、一把理发椅和 n 把等待椅（n≥1）。顾客到达时若有空等待椅则在等待椅上坐下并唤醒理发师，否则离开；理发师无顾客时在理发椅上睡觉，有顾客时为其理发，理完一位后从等待椅上请下一位顾客。理发过程中新到顾客不得打断理发。请用记录型信号量与共享变量设计同步方案，要求：任意时刻理发椅上至多一名顾客，等待椅数量的占用与释放必须严格互斥。

**【问题清单】**:
- (1) 指出本题中的互斥关系与同步关系各有哪些，并说明每个信号量的类型、初值及其物理含义。
- (2) 给出理发师进程与顾客进程的完整伪代码（使用 wait/signal 操作），并解释为什么顾客侧对『空等待椅』的检查必须与入座动作封装在同一临界区内。
- (3) 若将顾客代码中 wait(mutex) 与 wait(customers) 的顺序颠倒（即先 wait(customers) 再 wait(mutex)），分析是否会产生死锁或逻辑错误，并与生产者-消费者问题中的同类错误进行对比。
- (4) 设顾客平均到达率为 λ（泊松流），理发时间服从均值为 1/μ 的指数分布，λ<μ。试用排队论估算稳态下平均等待顾客数，并说明当 n（等待椅数）减小时系统行为如何变化。

**【考研阅卷踩分细则】**:
总分 15 分，踩分细则如下：
(1) 4 分：正确列出互斥关系（等待椅计数与入座/离开的互斥、理发椅互斥）得 2 分；正确列出同步关系（理发师等待顾客、顾客等待理发完成、满员离开）得 2 分。每个信号量未写清初值或物理含义扣 0.5 分/处。
(2) 6 分：理发师进程代码 2 分（wait(customers)、wait(chair_mutex)、取号、signal(chair_mutex)、理发、signal(finished) 逻辑完整）；顾客进程代码 2 分（wait(chair_mutex)、检查等待椅满则 signal 后离开、否则占座、signal(chair_mutex)、signal(customers)、wait(finished)、释放理发椅）；『检查与入座在同一临界区』的理由 2 分（若分离，多个顾客可同时通过检查导致超员入座，即检查-动作的原子性被破坏）。

(4) 2 分：给出 M/M/1 模型 Lq = λ²/(μ(μ−λ)) 得 1 分；分析 n 减小导致阻塞概率（顾客离开率）上升、系统趋于溢出/损失制得 1 分。使用中文引号书写术语，出现未转义英文双引号导致解析失败的答卷按 0 分处理（此为格式要求，实际阅卷中以规范书写为准）。

**【核心算法/推导实现】**:
```cpp
// 记录型信号量定义
semaphore customers = 0;   // 同步：等待理发的顾客数（理发师的资源）
semaphore finished   = 0;  // 同步：理发师完成当前顾客的理发
semaphore chair_mutex = 1; // 互斥：保护共享变量 waiting（占座/起立必须互斥）
int waiting = 0;           // 当前坐在等待椅上的顾客数, 0 <= waiting <= n

// 顾客进程
void customer_i() {
    wait(chair_mutex);          // 进入临界区：检查与入座必须原子完成
    if (waiting >= n) {         // 无空等待椅
        signal(chair_mutex);    // 释放临界区后直接离开
        return;                 // 顾客流失（损失制）
    }
    waiting++;                  // 占用一把等待椅
    signal(customers);          // 通知理发师：多了一位顾客
    signal(chair_mutex);        // 退出临界区

    wait(finished);             // 等待理发师为自己理完发
    wait(chair_mutex);          // 起立离开理发椅区域
    // 注：waiting 的递减在理发师请顾客时完成，此处顾客离开理发椅
    signal(chair_mutex);
}

// 理发师进程（单个，循环服务）
void barber() {
    while (true) {
        wait(customers);            // 无顾客则睡觉阻塞在此
        wait(chair_mutex);          // 临界区：从等待椅请顾客上理发椅
        waiting--;                  // 释放一把等待椅
        signal(chair_mutex);

        cut_hair();                 // 为顾客理发（不可被打断的语义由同步保证）
        signal(finished);           // 通知该顾客：理完了
        // 顾客随后自行离开，理发师继续寻找下一位顾客
    }
}

// (3) 顺序颠倒分析：若顾客改为
//   wait(customers);   // 先消耗同步信号量
//   wait(chair_mutex); // 再检查空椅
// 则当店内满员（waiting==n）时顾客已执行 signal(customers)，
// 使理发师的 customers 计数虚增，理发师被『虚假唤醒』后取号失败、
// 计数与实际等待人数失配，后续正常顾客可能被饿死或造成超员。
// 与生产者-消费者问题中『同步 P 先于互斥 P』的死锁不同，
// 本题颠倒顺序不构成循环等待（customers 由顾客单方面 signal、
// 理发师不会反向持有 chair_mutex 阻塞顾客），故是逻辑错误而非死锁。

// (4) 排队论估算：M/M/1 稳态（λ < μ）
//   平均排队队长 Lq = λ^2 / (μ(μ-λ))
//   例：λ = 4 人/小时, μ = 6 人/小时 => Lq = 16/(6*2) = 4/3 ≈ 1.33 人
//   平均逗留人数 L = λ/(μ-λ) = 2 人；平均等待时间 Wq = λ/(μ(μ-λ)) = 1/3 小时
// n 的影响：n 减小 => 系统容量 K = n+1 减小 => 到达顾客因无椅而离开的概率
//   P_损失 上升，实际进入率 λ' = λ(1-P_损失) 下降，
//   系统从『等待制』逐步退化为『损失制』，理发师利用率下降但顾客流失率上升。
```

**【命题人解题思维点拨】**:
系统级破局分析：本题有三个命题陷阱。陷阱一：顾客『检查有空椅→入座』是典型的检查-动作竞态，若两步分离，多个顾客可同时通过检查导致超员，必须用 chair_mutex 封装为原子临界区，这与读者-写者中 count 的保护同理。陷阱二：满员离开时必须在临界区内 signal(chair_mutex) 后再 return，遗漏会导致互斥信号量泄漏、全店瘫痪。陷阱三：第(3)问考察学生对死锁与逻辑错误的精确区分——生产者-消费者中『先同步后互斥』的颠倒之所以死锁，是因为存在环形等待（生产者持 mutex 等 empty，消费者持另一把锁等 full 或需 mutex 才能生产 full）；而理发师问题中 customers 信号量是单向生产-消费关系，不存在循环等待，故只产生计数失配类的逻辑错误。命题意图：区分『会背模板』与『能分析故障模式』的学生。排队论小问（M/M/1/K 有限容量）是 408 中少见的跨章综合点，用于检验学生对损失制与等待制边界条件的直觉。
