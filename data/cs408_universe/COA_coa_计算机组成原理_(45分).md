### 第 1 题 (难度: ⭐⭐⭐⭐)
**题干**：某浮点数格式为：1位阶符、5位阶码（补码表示）、1位数符、9位尾数（补码表示，小数点后共9位）。现要求对两个浮点数执行加法运算，若仅采用「尾数用双符号位补码、运算后左规/右规各一次封顶」的简化策略，则下列关于溢出判断的说法正确的是

- A. 只需看尾数运算后双符号位是否为01或10，若是则浮点数一定溢出
- B. 尾数双符号位为01或10时需要右规处理，仅当右规后阶码发生上溢，浮点数才真正溢出
- C. 尾数双符号位为11表示尾数溢出，此时浮点数必然溢出
- D. 阶码上溢才是溢出，阶码下溢按机器零处理，与尾数符号位无关

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：把『尾数溢出』直接等同于『浮点数溢出』，忽视了尾数溢出可通过右规挽救，这是最高频的反直觉陷阱；选项C陷阱：补码双符号位11实为正常负数，误将其当作溢出特征，混淆了双符号位的判溢规则（仅01/10为溢出）；选项D陷阱：前半句正确，但断言与尾数无关是错误的——右规时阶码加1可能引发阶码上溢，浮点溢出判断是尾数与阶码协同的结果

**【深度解析】**:
浮点加减法的完整流程为：对阶（小阶向大阶看齐，尾数右移、阶码增大）→尾数加减→规格化→舍入→溢出判断。尾数采用双符号位补码运算后，若符号位为01或10，仅说明『尾数溢出』即数值绝对值≥1，此时将尾数算术右移1位、阶码加1即可完成右规。若右规后阶码超出阶码表示范围（上溢），浮点数才真正溢出，需置溢出标志。阶码下溢（运算结果绝对值过小）按机器零处理，不算溢出。破局关键：区分三层概念——尾数溢出（可挽救）、阶码上溢（真溢出）、阶码下溢（机器零）

</details>

### 第 2 题 (难度: ⭐⭐⭐⭐)
**题干**：某计算机主存按字节编址，容量为1MB，Cache数据区容量为8KB，主存与Cache之间采用2路组相联映射，块大小为64B。CPU依次访问主存地址序列（十六进制）：0x3F020、0x3F060、0x3F020。若初始Cache为空且采用LRU替换，则第三次访问0x3F020时

- A. 命中，因为0x3F020与0x3F060映射到同一Cache组，LRU保留的是最近使用的块
- B. 不命中，因为0x3F020与0x3F060映射到同一组，第二次访问已将0x3F020所在块替换出去，且全无第二个可共存位置
- C. 命中，因为两地址块号不同，映射到不同组，互不冲突
- D. 不命中，因为Cache每块64B，0x3F020在块内的偏移量导致其无法与0x3F060共存于同一路

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：臆断『同组必然冲突替换』，忽视2路组相联每组有2行，两个块恰好可共存，这是对相联度意义的理解缺失；选项C陷阱：两地址低位相同（0x3F020与0x3F060组索引字段相同），实际映射到同一组，误判为不同组说明组索引计算错误；选项D陷阱：块内偏移只影响取块内哪个字节，与两块能否共存于同一路毫无关系，属于概念错位式干扰

**【深度解析】**:
块大小64B=2^6，故块内地址6位；8KB Cache、2路组相联，共128行/2=64组，组索引6位。主存地址0x3F020：低6位为块内偏移，接下来6位为组索引。0x3F020 = 0011 1111 0000 0010 0000B，组索引取位[11:6]为000000（第0组），块号=0x3F020>>6=0xFC0；0x3F060块号=0xFC1，组索引同为000000。两块同组，但2路组相联可各占一路：第一次访问装入0xFC0（方式：装入第0路），第二次0xFC1装入第1路，均未发生替换；第三次访问0x3F020直接命中。若为直接映射则B的情形成立，破局思维是先算组数与相联度、再判断冲突

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐)
**题干**：某按字节编址的计算机采用页式虚拟存储器，页大小为4KB，虚地址32位，物理地址28位，TLB为2路组相联、共64个页表项，采用随机替换。进程切换时TLB采用『页表项打全局位清空』方式处理。下列说法正确的是

- A. TLB缺失后必先访问主存中的页表查到页框号，此后CPU一定再访问一次主存取数据，故一次访存指令最少需要2次访存
- B. TLB命中时，若页表项中的有效位（装入位）为1，则只需一次主存访问即可完成取数
- C. TLB缺失且页表项无效时，说明该页尚未调入主存，产生缺页中断，缺页处理期间该进程阻塞，CPU调度其他进程运行
- D. 物理地址28位说明主存最多256MB，页内偏移12位，虚页号20位，故页表共有2^20项，项数为虚页号位数决定，与物理地址位数无关

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：『页表项有效位为0时不会去访存取数据而是触发缺页』被忽略；且TLB缺失时若页表项表明页不在主存，则根本不会完成第二次数据访存，『最少2次』在缺页情形下不成立；此外若TLB缓存的是叶级页表项且命中，无需查页表；选项B陷阱：装入位（valid/dirty区分）通常在页表中描述页是否在主存，TLB项通常缓存了有效位；但更致命的是该表述混淆了『TLB有效位』与『页表装入位』的作用层次，且取指令还可能额外访存；选项D陷阱：页表项数确由虚页号位数决定，但说法『与物理地址位数无关』具有误导性——每个页表项内需存储页框号（16位）及有效位、修改位等，页表项的字节宽度和总容量与物理地址位数直接相关

**【深度解析】**:
地址转换流程：CPU给出虚地址→先行分割页号/页内偏移→查TLB（快表）。TLB命中且有效→直接拼接页框号与偏移形成物理地址，数据访存仅1次（注意取指可能另算）。TLB缺失→查内存页表：若装入位为1，将页表项调入TLB（可能替换），再访存取数；若装入位为0，产生缺页中断，OS将页面从磁盘调入主存（可能换页），期间进程阻塞。缺页处理完成后重新执行被中断指令。破局思维：把TLB视为页表项的Cache，把页表视为页框分配状态的权威记录，层层降级访问

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐)
**题干**：某5段流水线（IF-ID-EX-MEM-WB）中，寄存器写口与读口采用『前半周期写、后半周期读』的内部 forwarding，且硬件已实现 EX 段到 EX 段的定向（forwarding）路径，但未实现 Load-Use 冒险的定向之外的停顿消除。执行如下指令序列：I1: lw R1, 0(R2)；I2: add R3, R1, R4；I3: sub R5, R6, R7；I4: or R8, R5, R9。则该序列相对无冒险理想流水线额外增加的周期数为

- A. 1个周期，仅需在I2的EX前插入一个气泡等待lw数据
- B. 2个周期，因为lw的数据在MEM段末才可用，add需要等待2拍
- C. 1个周期，但若add依赖的是R5（即or依赖I2结果），则需要2个周期
- D. 0个周期，定向路径可完全消除数据冒险

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：经典『Load-Use停顿2拍』的过时记忆——现代5段流水线中MEM段结束、WB段开始前的边界即可完成MEM→EX定向，Load-Use只需停顿1拍，B是很多教材老图导致的以讹传讹；选项C陷阱：I3不依赖I1/I2，无冒险；or依赖的R5由I3在EX末产生，可由EX/MEM→EX定向，同样停顿0拍，C混淆了依赖链的实际段落位置；选项D陷阱：定向不能消除Load-Use冒险，因为数据在I1的MEM段才产生，而I2的EX段在I1的MEM段之前，时间上不可回溯

**【深度解析】**:
关键时间线：I1的lw在MEM段（第4周期）末读出数据；I2的add需要在其EX段（第4周期）开头使用R1。若无停顿，数据尚未产生——这是Load-Use冒险，定向无法凭空造出未来的数据，必须插入1个气泡，使add的EX推迟到第5周期，此时MEM/WB流水寄存器到EX入口的定向路径可将数据送达。I3、I4的依赖（I4的R5由I3产生）均属EX末→EX前的ALU-ALU定向，无停顿。破局口诀：『定向解决ALU依赖零拍、Load依赖一拍』；切勿背『两拍』

</details>

### 第 5 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：某设备通过DMA方式与主存传送数据，系统采用周期挪用（周期窃取）方式，DMA控制器每挪用一个存储周期传送1字节。CPU主频为100MHz，CPU执行程序时平均每条指令需1.8个存储周期，指令平均每10条中有1条需要额外访问主存取数。现DMA以2MB/s的速率持续传送。忽略其他开销，DMA传送期间CPU效率（相对于无DMA时的指令执行速率）降低的百分比约为

- A. 2%，即2MB/s仅占存储周期的约2%
- B. 1%，因为CPU每秒执行约1亿条指令而DMA仅占用200万个周期
- C. 10%，因为CPU每秒所需的存储周期中约有10%被DMA窃取
- D. 无法计算，因为DMA传送与CPU访存的时间关系取决于设备优先级

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：把『DMA速率与总线带宽之比』当作对CPU效率的影响，忽视了CPU本身也要竞争存储周期，比较基准选错；选项B陷阱：以指令数为分母而非存储周期数为分母，遗漏了每10条指令额外1次取数访存，属于隐含条件漏读型陷阱，这也是命题人埋设数字10%的诱饵对应项；选项D陷阱：周期挪用方式的定义已明确每传1字节窃取1个存储周期，优先级只影响挪用的即时性（延迟），不改变每秒被窃取的周期总数，属于『用未知吓退』型伪难题

**【深度解析】**:
CPU每秒执行指令数 = 100MHz / 1.8 ≈ 5556万条/s；所需存储周期 = 5556万 × 1.8 = 1亿个周期/s（主频100MHz即每秒1亿个存储周期，吻合）。再加上取数访存：5556万/10 ≈ 555.6万次额外访存，CPU每秒总共需要约1.0556亿个存储周期。DMA窃取 2M 个周期/s。CPU效率降低比例 = 2M / 105.56M ≈ 1.9%……注意：若无DMA时CPU能完成的存储周期数受限于100M周期/s，而CPU需求105.56M已超100M，说明题设下CPU访存请求存在排队；按标准408解法取CPU每秒占用全部100M存储周期为基准：降低比例 = 2M/100M = 2%？关键辨析：408标准解法通常按『CPU工作周期占满』计算，即每秒DMA挪用2M个存储周期，CPU少做2M个存储周期的工作，效率降低 2M/100M = 2%。但若把额外访存计入CPU需求，分母应为CPU理想所需周期总数。本题设计上取指令周期即存储周期口径（1.8个存储周期/指令已含全部访存），额外10%取数为干扰性次要因素：2M/(100M+5.56M)≈1.9%，最接近C选项的10%？破局提示：命题意图考察『周期挪用下CPU损失率=窃取周期/CPU可利用周期总数』，按标准口径损失率≈2%，故严谨答案应结合选项语义：C的10%是把2M/20M误算……最终以D所否定的口径判断，本题答案取A（2%）更严谨。修正：以每秒1亿个存储周期为CPU可利用上限，DMA挪用2M，降低率=2%，故正确答案为A

</details>

### 第 6 题 (难度: ⭐⭐⭐⭐)
**题干**：补码加减运算与溢出判断的硬件实现是ALU设计的基石。下列关于n位补码加法器溢出检测逻辑的说法，正确的是

- A. 采用单符号位时，最高数值位向符号位的进位与符号位向前进位的『异或』结果为1表示溢出，该方法与双符号位判溢出逻辑等价
- B. 采用单符号位时，只要结果符号位与任一操作数符号位相同就无溢出
- C. 双符号位补码运算中，若运算后双符号位为10，则真实结果为负溢出，且该结果不可通过任何方式挽救
- D. 补码减法统一转换为加法后，减数的符号位必须单独取反，其余各位不变，且需在末位加1，这是行波进位加法器无法直接完成的

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：正确判据是『结果符号与两操作数符号都不同才溢出』（正+正得负、负+负得正），B漏掉了对另一操作数的约束，同号相加得异号才溢出，单看结果符号与一个操作数相同毫无判别力；选项C陷阱：双符号位10表示负数溢出（结果为负且超出范围）没错，但『不可挽救』错误——该溢出是尾数/中间结果级的概念时可通过右规挽救，即便定点补码中结果超范围，双符号位截断后的补码值仍保留次高位信息用于判断方向，绝对化表述是陷阱；选项D陷阱：减数『连同符号位一起取反、末位加1』才是正确变换，D错在『符号位单独处理、其余不变』，且行波进位加法器完全可以通过取反器和进位输入Cin=1实现补码减法，属双重错误

**【深度解析】**:
单符号位判溢出的两种等价方法：(1) 符号位进位Cf 与最高数值位进位 Cn-1 异或 Cf⊕C(n-1)=1 则溢出；(2) 两同号数相加结果符号相异则溢出。二者逻辑等价，可由进位链严格证明。双符号位法：00正、11负、01正溢、10负溢。补码减法 [X]补 - [Y]补 = [X]补 + [-Y]补，其中[-Y]补为Y连同符号位全部取反末位加1（或从右向左第一个1之前不变、之后取反），该操作由『按位加反控制信号 + Cin=1』即可在任意行波/先行进位加法器上完成。破局思维：把溢出检测还原到进位链的位级真相，而非背规则

</details>

### 大题 1: Cache-虚存协同设计与DMA访存冲突综合分析 (15 分)

**【背景与题干】**:
某32位按字节编址计算机，存储层次如下：①主存容量128MB，采用8体低位交叉编址，存储周期50ns，单体带宽8B/周期；②Cache容量16KB，直接映射，块大小32B，写策略为『全写法（write-through）+非写分配（no-write-allocate）』，写缓冲深度为4个块；③页式虚存页大小8KB，TLB共128项、2路组相联；④某I/O设备以100MB/s速率通过DMA持续向主存写数据，DMA采用周期挪用方式，与CPU共享存储总线。<br><br>程序P在运行时，对Cache的统计为：读命中率95%，写指令占总访存的10%，且写操作均为命中于写缓冲（写缓冲从不满）。程序P的CPU时间中，访存指令产生的实际Cache访问次数折合每秒2×10^8次。系统运行P的同时DMA持续工作。

**【问题清单】**:
- (1) 计算主存地址中块内偏移、Cache行号（块号）各占多少位？主存共分多少块？给出主存地址0x0A5C3F88映射到的Cache行号（十进制）。
- (2) 计算在无DMA干扰时，程序P每秒因Cache缺失而引入的主存访问次数（含读缺失与写穿透的访存），并计算Cache-主存层次平均每秒总访存流量（以B为单位）。
- (3) DMA以周期挪用方式占用存储总线。已知CPU与DMA仲裁时DMA优先。若DMA传送期间每挪用1个存储周期可传送8B，请计算DMA每秒挪用的存储周期数占总存储周期数的百分比，并简要说明为何DMA设计上更适于用周期挪用而非CPU停止访存（burst）方式（结合本题100MB/s速率分析）。
- (4) 若某页表项的装入位为0且进程访问该页，写出硬件与操作系统协同处理的完整事件序列，并指出全写法Cache在该过程中可能引发的一致性隐患及一种常见解决方案。
- (5) 【附加编程验证】编写C函数 uint32_t cache_line_of(uint32_t addr)，按本题Cache参数返回主存地址映射的Cache行号，并编写主函数对0x0A5C3F88进行验证。

**【核心算法/推导实现】**:
```cpp
// ===== 手算推导 =====
// (1) 块大小32B -> 块内偏移 log2(32) = 5 位
// Cache 16KB / 32B = 512 行 -> 行号 log2(512) = 9 位
// 主存 128MB / 32B = 4M = 2^22 块 -> 标记位 32-5-9 = 18 位
// 0x0A5C3F88 = 0000 1010 0101 1100 0011 1111 1000 1000
// 行号 = (addr >> 5) & 0x1FF = 0x1FC >> 0 段: addr>>5 = 0x52E1FC, & 0x1FF = 0x1FC = 508
// (2) 读访存 2e8 * 90% = 1.8e8, 读缺失 = 1.8e8 * 5% = 9e6 次/s
//     写访存 2e8 * 10% = 2e7 次/s (write-through 每次写都要访存)
//     总流量 = (9e6 + 2e7) * 32B = 29e6 * 32 = 9.28e8 B/s
// (3) DMA: 100MB/s / 8B = 1.25e7 周期/s；总线周期率 = 1/50ns = 2e7 周期/s
//     占比 = 1.25e7 / 2e7 = 62.5%
// (5) 代码：
#include <stdio.h>
#include <stdint.h>

#define BLOCK_SIZE  32u          // 块大小 32B
#define LINE_COUNT  512u         // Cache 共 512 行 (16KB / 32B)
#define OFFSET_BITS 5u           // log2(32)
#define LINE_BITS   9u           // log2(512)

uint32_t cache_line_of(uint32_t addr)
{
    return (addr >> OFFSET_BITS) & (LINE_COUNT - 1u);
}

uint32_t cache_tag_of(uint32_t addr)   // 附加：直接映射标记位
{
    return addr >> (OFFSET_BITS + LINE_BITS);   // 18 位标记
}

int main(void)
{
    uint32_t addr = 0x0A5C3F88u;
    printf("block offset bits  = %u\n", OFFSET_BITS);
    printf("line index bits    = %u\n", LINE_BITS);
    printf("total blocks in MM = %u\n", (128u << 20) / BLOCK_SIZE); // 4194304
    printf("cache line of 0x0A5C3F88 = %u\n", cache_line_of(addr)); // 期望 508
    printf("tag = 0x%X\n", cache_tag_of(addr));
    return 0;
}
// 输出: cache line of 0x0A5C3F88 = 508
```

**【命题人解题思维点拨】**:
本题考查软硬件跨层的系统级协同：(1)(2)考查地址分割与命中率折算，陷阱在于读占比90%与写占比10%需分别与各自命中率/穿透策略相乘，直接用总命中率5%乘总次数是常见错误；(3)考查周期挪用的定量影响，陷阱是带宽占比与周期占比混淆——DMA速率100MB/s、每周期8B，换算到50ns周期上是1.25e7个周期，占总周期2e7的62.5%，很多考生会误用『100MB/主存峰值带宽』得到完全不同的数；(4)考查虚缺页全流程与DMA-Cache-虚存的一致性交互，这是近年408综合题的命题趋势——不再孤立考某一章，而是让DMA写、页换出、写穿透在同一时间窗内碰撞；(5)以代码固化地址分割的位运算本质，(addr>>5)&511即『取第5位到第13位』，比死记字段表更可靠。破局总思路：先把所有参数化为2的幂，再逐层做地址字段切分与事件时间线排列
