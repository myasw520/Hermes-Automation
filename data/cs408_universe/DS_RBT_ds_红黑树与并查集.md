## 🎯 高陷阱单选专项演练

### 第 1 题 (难度: ⭐⭐⭐⭐)
**题干**：一棵含 n 个内部结点的红黑树，其黑高为 bh。关于该树可能的最大高度 h 与 n 的关系，下列结论正确的是（　）。

- A. h ≤ 2·log₂(n+1)，且最坏情况下树中红结点数可接近黑结点数
- B. h ≤ log₂(n+1)，因为红黑树是平衡二叉树，任何路径长度差不超过 1
- C. h ≤ 2·bh，因此 n ≥ 2^bh − 1，最坏情况下一条路径上红结点占一半且全部位于另一条全黑路径之上
- D. h ≤ log₂(n)，因为黑高相等保证了左右子树结点数之差不超过 1

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：结论 h≤2log(n+1) 本身正确，但后半句『红结点数可接近黑结点数』错误——最坏红黑树（1黑1红交替）中红结点数 n−(2^(bh)−1) 略少于黑结点数，但 A 表述模糊且混淆了『路径上红结点占一半』与『全树红黑数量关系』；选项B陷阱：致命混淆 AVL 与红黑树——红黑树只保证黑高相等，允许最长路径是最短路径的 2 倍，不是 AVL 式的平衡因子约束；选项D陷阱：黑高相等只能推出子树至少含 2^(bh−1)−1 个结点，绝非结点数差不超过 1，这是把『黑路径等长』误当『子树等大』。

**【深度解析】**:
破局点：从黑高定义出发。黑高为 bh 的子树至少含 2^bh − 1 个内部结点（归纳：每层黑结点数至少翻倍）。由性质『无相邻红结点』，任一简单路径上红结点数 ≤ 黑结点数，故 h ≤ 2bh；又 n ≥ 2^bh − 1 得 bh ≤ log₂(n+1)，于是 h ≤ 2log₂(n+1)。最坏情形构造：一侧路径黑红交替、另一侧全黑，此时红结点紧贴地挂在全黑路径之上。命题人常把『路径红≤黑』偷换成『全树红≤黑的一半』来设陷阱。

</details>

### 第 2 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：在红黑树中插入一个新结点时，下列关于初始着色与调整过程的描述，正确的是（　）。

- A. 新结点染黑色插入，若父结点为红则通过旋转让其成为新的根即可结束
- B. 新结点染红色插入，可能引发连续的向上调整；最坏情况下调整（变色+旋转）会沿祖父方向传播至根，使整条路径黑高整体加 1
- C. 新结点染红色插入，调整至多需要 O(1) 次变色，因为红黑树高度为 O(log n)
- D. 新结点染红色插入，若父结点为红且叔叔结点为黑，则必须先连续执行两次变色再旋转

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：染黑插入会立刻破坏『黑高相等』性质（新叶所在路径黑高加 1），需要全树重构修复，代价远高于染红；且『旋转变为新根』的说法混淆了删除情形；选项C陷阱：混淆『树高 O(log n)』与『调整传播长度』——叔叔为红时变色会向上冒泡，最坏（如 1,2,3,...,n 顺序插入）变色次数达 O(log n) 次，只有旋转次数才是至多 2 次（O(1)）；选项D陷阱：叔叔为黑时的标准做法是 LL/LR/RR/RL 单旋转或双旋转，配合 1 次变色即可，先连续两次变色会破坏黑高相等。

**【深度解析】**:
破局思维：染红插入只可能违反『无相邻红』，违反局部性使得修复可自底向上传播；染黑插入违反『黑高相等』且无法局部修复。必须区分三个量级：变色次数最坏 O(log n)（一路双红上溢，等价于 B 树 4 阶结点上裂）、旋转次数至多 2 次（一旦旋转即终止，旋转后子树根变黑吸收冲突）。D 选项的『两次变色再旋转』是典型的伪造流程陷阱。

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐)
**题干**：依次向初始为空的红黑树插入 10, 20, 30, 15。完成全部插入后的树结构，下列描述正确的是（　）。

- A. 根为 20（黑），左孩子 10（黑），右孩子 30（黑），30 的左孩子 15（红）
- B. 根为 20（黑），左孩子 10（红），右孩子 30（红），10 的右孩子 15（黑）
- C. 根为 15（黑），左孩子 10（红），右孩子 20（黑），20 的右孩子 30（红）
- D. 根为 20（黑），左孩子 10（黑），右孩子 30（黑），10 的右孩子 15（红）

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `D`

**【各选项排雷剖析】**:
选项A陷阱：把 15 插到 30 下面后未做调整，直接违反『无相邻红』吗？注意此时 15 的父 30 是黑、插入 15 为红本不冲突——但插入 15 时其初始父结点是 10（红），叔叔 30 是红，触发双红上溢：10、30 变黑，20 上溢变红后为根再染黑，最终 15 挂在 10 右侧。A 选项是忘记 15 属于 10 的右子树（15<20），把它错挂到 30 左侧，属于 BST 性质错误；选项B陷阱：15 的颜色错误且位置错误，把双红变色后的结果与后续插入次序搞反；选项C陷阱：误以为 15 插入后触发旋转使 15 成为根，实际上叔叔为红时只变色不旋转，这是『见双红必旋转』的常见幻觉。

**【深度解析】**:
逐步推演：插 10 → 黑根；插 20 → 20 红，父黑不调整；插 30 → 10 红父、20 黑祖父、叔叔不存在（NIL 黑），RR 型左旋 20，得 20 黑、10 红、30 红；插 15 → 落在 10 右下为红，父 10 红、叔叔 30 红 → 双红上溢：10、30 染黑，20 染红后为根染黑；15 作为 10 的右孩子保持红。最终结构即 D。破局关键：先按 BST 规则确定 15 的落点（在 10 与 20 之间），再判定叔叔颜色选择『变色上溢』还是『旋转终止』。

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐)
**题干**：对 n 个元素使用并查集，仅采用『按秩合并』（不路径压缩），一次 Find 操作的最坏时间复杂度为（　）。

- A. O(1)
- B. O(log n)
- C. O(α(n))，α 为反 Ackermann 函数
- D. O(n)

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：仅当该元素是树根或秩很小才可能 O(1)，按秩合并只约束树高增长速度，不等于常数高度；选项C陷阱：α(n) 是『路径压缩+按秩合并』联合使用的复杂度，去掉路径压缩后该界不成立，这是新大纲最爱考的『协同设计』陷阱——两个优化缺一不可，单独按秩合并只有 O(log n) 界；选项D陷阱：不做任何优化时 Union 随意接树才可能退化成 O(n) 链，按秩合并保证每棵高 h 的树至少含 2^h 个结点，故 h ≤ log n。

**【深度解析】**:
按秩合并的核心引理：当两棵秩相同的树合并时新树秩加 1，树中结点数至少翻倍，因此任意树高 h 满足 2^h ≤ 结点数 ≤ n，得 h ≤ log₂n。而 O(α(n)) 的紧界必须同时依赖路径压缩（Find 时抹平路径）与按秩/按大小合并（Union 时限制树高），二者协同才产生 Amortized α(n)。考试口诀：『单优化 log，双优化 α』。

</details>

### 第 5 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：对同一并查集依次执行操作序列：Union 后再做带路径压缩的 Find(x)。关于路径压缩对『秩』的影响及正确做法，下列说法正确的是（　）。

- A. 路径压缩会改变沿途结点的秩，因此压缩后必须重新计算所有结点的秩，否则按秩合并失效
- B. 路径压缩只修改父指针不修改秩，某些结点的秩可能大于其真实子树高度，但按秩合并仍能保证 O(α(n)) 总复杂度
- C. 路径压缩会把树根的秩减 1，因为根失去了路径上的孩子
- D. 若使用路径压缩则不应再用按秩合并，二者互斥，否则会破坏 Find 的正确性

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：秩（rank）是『压缩前树高上界的历史快照』，设计初衷就是压缩后不回写、不重算，重算反而破坏 α(n) 摊还界；选项C陷阱：路径压缩把路径中间结点直接挂到根下，根的孩子不减反增，且秩根本不因压缩而更新，说法双重错误；选项D陷阱：二者是协同关系而非互斥——按秩合并负责 Union 端防退化，路径压缩负责 Find 端摊平历史债务，联合才是 α(n)；若『秩』换成维护真实高度的『按高度合并』，则压缩时必须做高度修正，这是常考的细分陷阱但 D 的『互斥』结论错误。

**【深度解析】**:
底层机制：rank 定义为『该结点在从未被路径压缩的情况下子树高度的上界』。压缩把链拍扁后，真实高度下降而 rank 保持不变，出现 rank ≥ 真实高度 的现象，这是有意为之的惰性维护。严格证明（Tarjan）：仅用 rank 破坏性较大的合并仍得 O(log n)，加上压缩后每次 Find 的摊还代价进入 α(n)。注意对比：若实现的是『按真实高度合并（union by height）』，压缩时必须沿途把高度减 1 修正，这是 B 与 D 描述之外的第三种实现，命题人喜欢用它做混淆项。

</details>

### 大题 1: 红黑树插入调整过程手工推演 + 并查集最小生成树判环应用 (15 分)

**【背景与题干】**:
某社交平台需维护一个动态好友热度索引（支持快速插入与范围查询），底层采用红黑树；同时其『好友圈合并』模块采用并查集检测两个用户是否已连通（防止朋友圈成环冗余建边）。
第一部分：依次向空红黑树插入键值序列 30, 20, 40, 10, 25, 35, 50, 5。
第二部分：给定 8 个用户（编号 0~7）与候选好友边（按权重升序）：(0,1,4), (1,2,8), (2,3,7), (3,4,9), (4,5,10), (5,6,2), (6,7,6), (7,0,3), (2,5,5)，使用并查集执行 Kruskal 算法求最小生成树（MST）。

**【问题清单】**:
- (1) 画出（文字描述层级结构并标明每个结点颜色）插入 5 之后的最终红黑树，说明每一步插入是否触发调整及触发原因（双红冲突类型：LL/LR/RR/RL，叔叔颜色）。
- (2) 计算该红黑树的黑高 bh，并验证所有根到叶路径上的黑结点数（不含叶哨兵 NIL）是否相等；给出树高 h 并验证 h ≤ 2·log₂(n+1)。
- (3) 按 Kruskal 流程逐步写出每条边的取舍决策、对应的并查集 Find 结果（含路径压缩后的父指针变化）与 Union（按秩合并）后的集合结构变化，给出 MST 的总权值。
- (4) 若并查集仅用路径压缩、不做按秩合并，指出在本题数据规模下哪一步操作会产生最坏树形，并说明理论上摊还复杂度从 O(α(n)) 退化为多少。

**【核心算法/推导实现】**:
```cpp
// ---------- 第一部分：红黑树插入（关键代码框架，C++） ----------
enum Color { RED, BLACK };
struct RBNode {
    int key; Color color;
    RBNode *left, *right, *parent;
    RBNode(int k) : key(k), color(RED), left(nullptr), right(nullptr), parent(nullptr) {}
};
// 左旋：以 x 为轴，其右孩子 y 上提
void rotateLeft(RBNode*& root, RBNode* x) {
    RBNode* y = x->right;
    x->right = y->left;
    if (y->left) y->left->parent = x;
    y->parent = x->parent;
    if (!x->parent) root = y;
    else if (x == x->parent->left) x->parent->left = y;
    else x->parent->right = y;
    y->left = x; x->parent = y;
}
void rotateRight(RBNode*& root, RBNode* y) { // 对称实现，略同上镜像
    RBNode* x = y->left;
    y->left = x->right;
    if (x->right) x->right->parent = y;
    x->parent = y->parent;
    if (!y->parent) root = x;
    else if (y == y->parent->left) y->parent->left = x;
    else y->parent->right = x;
    x->right = y; y->parent = x;
}
// 插入后修复：只可能违反『无相邻红』
void fixInsert(RBNode*& root, RBNode* z) {
    while (z->parent && z->parent->color == RED) {
        RBNode* gp = z->parent->parent;
        if (z->parent == gp->left) {
            RBNode* uncle = gp->right;
            if (uncle && uncle->color == RED) {          // 叔叔红：变色上溢
                z->parent->color = BLACK; uncle->color = BLACK;
                gp->color = RED; z = gp;
            } else {
                if (z == z->parent->right) {             // LR：先左旋转成 LL
                    z = z->parent;
                    rotateLeft(root, z);
                }
                z->parent->color = BLACK;                // LL：变色+右旋后终止
                gp->color = RED;
                rotateRight(root, gp);
            }
        } else { /* 镜像分支，对称处理 RR/RL，略 */ }
    }
    root->color = BLACK;
}
// 依次插入 30,20,40,10,25,35,50,5 后最终结构（颜色标注）：
//               20(B)
//            /        \
//         10(B)        30(B)
//        /    \      /     \
//     5(R)  25(R)  35(R)  40(R)
//                             \
//                             50(R)
// 说明：插30→黑根；插20红；插40→10?否，父20黑不调；插30,20,40 实际触发：
// 插 30 时父 20 黑不调；插 40 时父 30 黑不调；
// 插 10 后结构 20(黑,根) 下 10红,30红 由插 30 时的 RR 左旋得到；
// 插 25：父 10 黑，挂 10 右；插 35,50：父 40 黑（40 此时在 30 右），挂右子；
// 插 5：父 10 红，叔叔 30 红 → 双红上溢：10、30 变黑，20 变红后为根染黑，
// 其间 25 随 10 归位于 10 的右子树，40,35,50 随 30 归位。最终如上图。
// ---------- 第二部分：并查集 + Kruskal ----------
int fa[8], rnk[8];
void init(int n) { for (int i = 0; i < n; ++i) { fa[i] = i; rnk[i] = 0; } }
int find(int x) {                       // 路径压缩（两趟法）
    if (fa[x] != x) fa[x] = find(fa[x]);
    return fa[x];
}
bool unite(int x, int y) {              // 按秩合并
    int rx = find(x), ry = find(y);
    if (rx == ry) return false;         // 已连通，拒绝成环边
    if (rnk[rx] < rnk[ry]) { int t = rx; rx = ry; ry = t; }
    fa[ry] = rx;                        // 秩小挂秩大
    if (rnk[rx] == rnk[ry]) rnk[rx]++;
    return true;
}
// Kruskal 主流程（边按权升序）：
// (5,6,2)取 → (7,0,3)取 → (0,1,4)取 → (2,5,5)取 → (2,3,7)取
// → (1,2,8)取 → (6,7,6)取 → (3,4,9)拒[3,4已连通] → (4,5,10)拒[成环]
// MST 边集：{(5,6,2),(7,0,3),(0,1,4),(2,5,5),(2,3,7),(1,2,8),(6,7,6)}
// MST 总权值 = 2+3+4+5+7+8+6 = 35
```

**【命题人解题思维点拨】**:
