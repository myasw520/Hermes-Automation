### 第 1 题 (难度: ⭐⭐⭐⭐)
**题干**：某系统采用时间片轮转调度。进程P在运行过程中发生了一次缺页中断，缺页处理完毕后P重新进入调度队列。关于P的状态转换，下列说法正确的是：

- A. P由运行态直接回到就绪态，缺页处理属于进程自身代码的执行，无需状态切换
- B. P由运行态进入阻塞态，等待I/O完成后回到就绪态，而非直接回到运行态
- C. P始终处于运行态，因为缺页中断处理是在P的时间片内完成的
- D. P由运行态进入创建态重新初始化，因为缺页相当于进程的部分重启

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：把缺页中断误认为用户态可处理的普通事件，忽略缺页服务需内核介入且CPU会切换到缺页处理线程/内核路径，P本身必须让出CPU；选项C陷阱：混淆了『中断发生在P的时间片内』与『P保持运行态』，中断期间CPU执行的是内核代码，P的PCB状态被置为阻塞；选项D陷阱：缺页是正常异常处理，进程的PCB、地址空间主体均保留，绝不涉及创建态，创建态仅存在于进程新建（如fork）阶段。

**【深度解析】**:
缺页中断的破局关键：谁是被中断者、谁是处理者。P执行指令触发缺页→CPU陷入内核→P无法继续推进（它所需的页面未就绪，等价于等待一次I/O——从磁盘调页）→P进入阻塞态并让出CPU；页面调入完成后，P被I/O完成中断唤醒，进入就绪态队尾，等待再次被调度，不能直接抢占回运行态（除非系统支持抢占式唤醒且优先级最高，但那也是先经过就绪态）。这一『阻塞→就绪→（调度）→运行』的链路与普通I/O完全同构。反直觉点在于：很多考生认为缺页『很快』所以不算阻塞，但状态转换的判定标准是『进程能否继续执行下一条指令』，而非等待时间长短。

</details>

### 第 2 题 (难度: ⭐⭐⭐⭐)
**题干**：关于内核级线程（KLT）与用户级线程（ULT）的对比，下列叙述正确的是：

- A. ULT的一个线程发起阻塞式系统调用后，其余线程仍可继续运行，因为线程调度在用户库中完成
- B. 多核环境下ULT也能真正并行执行，前提是用户线程库足够高效
- C. KLT的一个线程被阻塞时，同一进程内其他内核线程仍可被调度运行，切换需陷入内核
- D. KLT的线程切换开销一定大于进程切换开销的50%，因此操作系统普遍改用ULT提升性能

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：恰好说反，ULT对内核不可见，一个线程的阻塞式系统调用（如read磁盘）会导致整个进程被内核阻塞，所有ULT一起停摆，这正是ULT最大的缺陷；选项B陷阱：内核一次只调度『进程』这个单位，ULT无法被分配到不同核心，无论用户库多高效都只能在一个核上并发（非并行）；选项D陷阱：编造量化关系，KLT切换虽需陷入内核（模式切换+内核调度），但远小于进程切换（还需换地址空间、刷新TLB），『一定大于50%』与『普遍改用ULT』均为杜撰，主流OS恰以KLT为主。

**【深度解析】**:
本题考查两种线程映射模型的本质：ULT是『一个内核进程外壳+用户库自行分时』，内核看不到线程粒度，故无法利用多核、无法细粒度阻塞；KLT是『内核直接以线程为调度单位』，一个线程阻塞不影响同进程其他线程，代价是每次切换需用户态→内核态的模式切换。破局思维：抓住『谁看得见调度实体』——内核看不见ULT，所以ULT的并行性与独立阻塞能力均受限于内核视角的进程粒度。现代方案是多对多模型（如m:n映射），但408大纲层面只需掌握KLT/ULT纯模型的边界。

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：某系统有一批相互作用相同的作业，采用SJF（非抢占）调度。当前时刻t=0有一道长作业（需运行100ms）刚开始运行；t=10ms时到达一道仅需2ms的短作业。若短作业在t=0时已到达，其带权周转时间将比现在（t=10到达）的情况：

- A. 更小，因为等待时间减少了10ms
- B. 更大，因为提前到达会延长其在就绪队列中的排队时间
- C. 相同，带权周转时间只与运行时间有关，与到达时刻无关
- D. 无法确定，取决于长作业的到达时刻是否早于短作业

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：因果倒置——短作业越晚到越『躲过』长作业后面的新排队者吗？不，晚到反而多了10ms真实等待（t=10到t=100才开始，等待90ms；若t=0到则等到t=100，等待100ms，但周转时间分别为92ms与102ms），选项B把『等待』与『周转』的关系算反；选项C陷阱：带权周转时间=周转时间/运行时间，周转时间=完成时刻−到达时刻，显然与到达时刻相关；选项D陷阱：题干已明确长作业t=0开始运行，不存在条件缺失，属于用『不确定论』干扰判断。

**【深度解析】**:
精确计算破局：情形一（t=10到达）：完成时刻=100+2=102，周转时间=102−10=92，带权=92/2=46；情形二（t=0到达）：完成时刻仍为102，周转时间=102−0=102，带权=102/2=51。46<51，故提前到达带权周转时间更小，选A。深层陷阱在于：很多考生直觉上认为『SJF下短作业插队』，但非抢占SJF中长作业已在运行，短作业只能排队；到得早反而『全程陪跑』等待时间更长、周转时间更长——但带权周转时间=周转/服务，分母相同，周转时间短者（晚到者）带权值更小。本题反直觉核心：晚到10ms竟然带权周转时间更优（92/2<102/2），因为到达时刻本身也进入了周转时间公式的减项。

</details>

### 第 4 题 (难度: ⭐⭐⭐)
**题干**：时间片轮转（RR）调度中，若将时间片q从无穷大连续减小，关于系统行为的变化，下列说法最准确的是：

- A. q减小使响应时间单调递减，因此q越小系统性能越好，极限q=1最优
- B. q太大退化为FCFS，q太小则上下文切换开销占比过高，存在使平均周转时间较优的适中区间
- C. q的取值只影响响应时间，对平均周转时间完全没有影响
- D. 无论q取何值，RR的平均周转时间恒小于SJF

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：忽略切换开销——q过小时CPU大量时间耗在上下文切换与调度器上，有效利用率暴跌，响应时间反而因排队切换而恶化；选项C陷阱：q决定作业被切成多少段、与其他作业如何交错，直接影响完成时刻分布，进而影响平均周转时间（例如长作业在q极小时完成时间被大幅推迟）；选项D陷阱：RR以响应时间公平换取周转时间，SJF在平均周转时间上是最优算法（非抢占SJF在给定批内最优），RR不可能恒优于SJF，二者目标函数不同。

**【深度解析】**:
RR的设计权衡：q→∞时RR退化为FCFS（先到者一次跑完），交互响应差；q→0（极限处理器共享）理论响应时间最小但切换开销无穷大。工程上取q使约80%的CPU突发能在单个时间片内完成。破局思维：任何调度参数题都要同时看两个约束——交互性（响应时间）与吞吐/开销（切换成本），单调性结论几乎都是陷阱。另外注意408常考细节：RR中因I/O阻塞而中断的时间片，进程唤醒后进入就绪队尾，而非恢复剩余时间片。

</details>

### 第 5 题 (难度: ⭐⭐⭐⭐)
**题干**：某系统采用多级反馈队列（MLFQ）调度：三级队列，时间片分别为2、4、8ms；新进程进入最高队列Q1，用完当前队列时间片未完成则降级到下一级，在低队列中被抢占时不降级也不升级。进程P总CPU突发需求为11ms，从t=0开始运行，期间系统无其他进程竞争。P完成时的时刻及最终所在队列状态为：

- A. t=11ms完成，完成前最后一次运行发生在Q3，共被降级2次
- B. t=14ms完成，因为Q1、Q2各需补一次切换开销
- C. t=11ms完成，P一直在Q1运行，因为无竞争时不会被降级
- D. t=15ms完成，11ms被按2、4、8分配后尚余不足，需再等一个完整8ms时间片

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：无竞争、无I/O的单进程场景不存在额外切换开销，凭空加入14ms纯属对『时间片边界』的臆测；选项C陷阱：MLFQ降级条件是『用尽时间片仍未完成』，与是否有竞争无关，11>2>4必然降级；选项D陷阱：时间片用满才需等待新时间片，第三段只执行11−2−4=5ms<8ms，用不满即完成，无需凑满时间片。

**【深度解析】**:
逐步推演：[0,2)在Q1跑2ms，用尽片未完成→降入Q2；[2,6)在Q2跑4ms，用尽片未完成→降入Q3；[6,11)在Q3跑5ms即完成（11−6=5<8）。总完成时刻t=11ms，降级2次，最后一次运行在Q3。破局要点：①MLFQ的降级触发条件是『时间片耗尽且进程仍处于可运行（就绪/刚被抢占）状态』，与竞争无关；②时间片是『上限』而非『必须用满』，剩余需求小于时间片时直接完成；③无竞争时MLFQ退化为『分段长度递增的一次性服务』，但队列归属仍按规则变化。

</details>

## 🏆 综合应用与算法设计大题

### 大题 1: 进程状态转换与多级反馈队列调度综合设计 (15 分)

**【背景与题干】**:
某单CPU系统采用多级反馈队列调度，共3级就绪队列：Q1时间片T1=2ms，Q2时间片T2=4ms，Q3采用FCFS（时间片视为无穷大）。规则：①新到达进程进入Q1队尾；②在Q1/Q2中时间片用尽仍未完成则降入下一级队尾；③在Q3中运行至完成；④高优先级队列非空时，低优先级队列队首进程被抢占（可抢占MLFQ）；⑤进程因I/O阻塞后唤醒进入其当前所属最高允许队列Q1的队尾（即唤醒后重新从Q1开始）。现有进程A、B、C：A于t=0到达，CPU需求为：先CPU 3ms，然后I/O 6ms，再CPU 4ms；B于t=1到达，纯CPU需求8ms；C于t=3到达，CPU需求：先CPU 2ms，然后I/O 4ms，再CPU 3ms。忽略调度与切换开销，I/O设备与CPU可并行。

**【问题清单】**:
- (1) 画出（或用表格列出）从t=0到全部完成的CPU调度甘特图，标注每个时间段运行的进程及其所在队列。
- (2) 计算A、B、C各自的周转时间与带权周转时间。
- (3) 若将规则⑤改为『唤醒后回到其阻塞前所在的队列队尾』（不重新从Q1开始），重新计算A的周转时间，并分析该改动对交互式进程响应性的影响。
- (4) 用C语言风格伪代码描述『可抢占MLFQ的调度器核心逻辑』（含时钟中断处理与I/O完成唤醒处理），需体现降级与抢占判断。

<details><summary><b>👉 查看踩分标准与标准参考实现</b></summary>

**【考研阅卷踩分细则】**:
总15分。(1) 甘特图6分：每个CPU占用时间段正确1.5分，共4段（A@Q1 0-2，B@Q1 2-3被C到达不影响队列头判断需正确，B@Q2 3-7，C@Q1 7-9，C@Q2 9-13，A@Q1 13-15，B@Q3 15-19，C@Q1 19-20，C@Q2 20-24，A@Q3 24-26），时段划分与队列归属错误每处扣1分，扣完为止；I/O与CPU并行关系画错扣1分。(2) 4分：周转时间每个1分（A：26；B：18；C：21），带权周转时间（A：26/7≈3.71；B：18/8=2.25；C：21/5=4.2）算错每个扣0.5分；完成时刻错误连带扣分。(3) 3分：正确推演出A第二段CPU 4ms改为在Q2运行（唤醒回Q2队尾，时间片4ms，一次跑完4ms）得2分；定性分析『唤醒回原队列使I/O频繁的交互进程逐渐沉入低优先级队列，响应时间变长，违背MLFQ奖励短突发/交互进程的初衷』得1分。(4) 2分：时钟中断中正确实现『当前时间片减1；为0且未完成则降级入队+调度新进程；高队列非空则抢占』得1.5分；I/O唤醒入Q1队尾并触发抢占判断得0.5分；逻辑与规则①②④⑤任何一处不符酌情扣0.5~1分。

**【核心算法/推导实现】**:
```cpp
// 完整调度过程推演（时间轴，忽略切换开销）
// t=0    A到达入Q1。A@Q1运行[0,2)，用尽2ms片未完成(A需3ms)，降入Q2队尾
// t=1    B到达入Q1队尾（Q1非空，但当前A正在Q1运行，不受影响）
// t=2    A时间片尽→降Q2。此时Q1队首=B。B@Q1运行[2,3)
// t=3    C到达入Q1队尾；B时间片未到(2ms片在t=4用尽)但Q1内仍以RR推进——
//        注意：本题规则③④下Q1也按RR，B在[2,4)应跑满2ms；但C于t=3到达排队，
//        B@Q1[2,4)用尽片→降Q2队尾（此时Q2已有A，A在B前）。
//        修正时间轴：B@Q1[2,4)，A@Q2[4,8)——但A@Q2只需再跑1ms（共3ms）即完成
//        第一段CPU，t=5时A进入I/O 6ms（至t=11）。
//        精确推演：A@Q2[4,5)完成第一段CPU（Q2片4ms只用1ms），A阻塞至t=11；
//        t=5  Q2队首=B，B@Q2[5,9)跑满4ms→降Q3；
//        t=9  Q1队首=C（C纯CPU 2ms段），C@Q1[9,11)用尽片→降Q2，C进入I/O 4ms（至t=15）；
//        t=11 A I/O完成→按规则⑤唤醒入Q1队尾；Q2队首为C？C在I/O，Q2暂空。
//              Q1队首=A，A@Q1[11,13)跑满2ms→降Q2队尾；
//        t=13 Q2队首=A（B在Q3），A@Q2[13,15)只跑1ms即完成第二段CPU(共3+1=4ms？
//              修正：A第二段CPU需4ms，[11,13)跑2ms，[13,15)跑2ms完成）→A于t=15进入终止；
//              （更正：A第二段需4ms，[11,13)+[13,15)共4ms，A完成于t=15）
//        t=15 C I/O完成→入Q1；Q1队首=C，C@Q1[15,17)用尽片→降Q2；
//        t=17 Q2队首=C，C@Q2[17,21)跑3ms（C最后一段需3ms）完成于t=20；
//              （更正：C@Q2[17,20)跑3ms完成，t=20后Q2空，Q3队首=B）
//        B@Q3（FCFS）[15,...)？B在t=9降入Q3，但高队列一直非空；t=20后B@Q3[20,24)跑剩余
//              CPU（B共8ms：已跑[2,4)2ms+[5,9)4ms=6ms，剩2ms）→B完成于t=22。
// 最终精确结果（以严格推演为准）：
//   A: 0-2(Q1) 4-5(Q2) I/O 5-11 11-13(Q1) 13-15(Q2)完成 → 周转=15
//   B: 2-4(Q1) 5-9(Q2) 20-22(Q3)完成 → 周转=21
//   C: 9-11(Q1) I/O 11-15 15-17(Q1) 17-20(Q2)完成 → 周转=17
//   带权: A=15/7≈2.14, B=21/8≈2.63, C=17/5=3.40

#include <stdio.h>
#include <queue>
using namespace std;

struct PCB {
    int pid;
    int arrive;            // 到达时刻
    int cpu_need[10];      // CPU突发序列
    int io_need[10];       // 对应I/O时长序列
    int seg;               // 当前处于第几个CPU段
    int cpu_left;          // 当前CPU段剩余需求
    int level;             // 当前所在队列级别 0/1/2
    int tslice[3];         // 各级时间片 {2,4,INT_MAX}
    int slice_left;        // 当前时间片剩余
    bool blocked;
    int finish;
    int ran_total;
};

queue<int> rq[3];          // 三级就绪队列存pid
int cur = -1;              // 当前运行进程下标，-1为CPU空闲
PCB p[3];
int n = 3;

void admit_or_wake(int i, int t) {   // 新到达或I/O完成唤醒：入Q1队尾
    p[i].level = 0;
    p[i].slice_left = p[i].tslice[0];
    rq[0].push(i);
}

void schedule(int t) {               // 选取下一个运行进程：高级队列优先
    cur = -1;
    for (int l = 0; l < 3 && cur < 0; ++l)
        if (!rq[l].empty()) { cur = rq[l].front(); rq[l].pop(); p[cur].slice_left = p[cur].tslice[l]; }
}

void tick(int t) {                   // 时钟中断：1ms粒度
    if (cur < 0) { schedule(t); }
    if (cur < 0) return;
    p[cur].cpu_left--; p[cur].ran_total++; p[cur].slice_left--;
    if (p[cur].cpu_left == 0) {                       // 当前CPU段完成
        if (p[cur].seg == /*末段*/) { p[cur].finish = t + 1; cur = -1; schedule(t + 1); return; }
        p[cur].blocked = true;                        // 转入I/O（并行）
        cur = -1;
    } else if (p[cur].slice_left == 0 && p[cur].level < 2) {  // 用尽片→降级
        p[cur].level++;
        rq[p[cur].level].push(cur);
        cur = -1;
    }
    // 抢占判断：更高级队列非空则换出（Q3被Q2/Q1抢占）
    if (cur >= 0) {
        for (int l = 0; l < p[cur].level; ++l)
            if (!rq[l].empty()) { rq[p[cur].level].push(cur); cur = -1; break; }
    }
    schedule(t + 1);
}
// I/O完成事件：在事件驱动主循环中调用 admit_or_wake(i, t)（即规则⑤回Q1队尾），
// 随后立即执行抢占判断与schedule。
```

**【命题人解题思维点拨】**:
本题陷阱密集区：①MLFQ中Q1也是RR而非只在Q2/Q1间降级——B在t=2入Q1后与后续到达的C共享Q1时间片，很多考生会让B独占Q1到完成；②规则⑤『唤醒回Q1』是MLFQ奖励交互进程的关键设计，第(3)问的改动会让I/O多的进程迅速沉底，暴露MLFQ『以历史预测未来』的博弈本质——甚至有恶意进程故意在时间片将尽时发起I/O以永远留在高优先级队列（这是MLFQ的经典安全漏洞，可作为点评亮点）；③带权周转时间的分母是CPU突发总和（A为7ms、C为5ms），而非首次突发长度；④第(4)问代码核心是『降级条件=时间片耗尽且进程仍在就绪/被抢占』与『抢占条件=存在更高级非空队列』两个独立判断，混为一谈是最常见失分点。
