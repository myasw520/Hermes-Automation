## 🎯 高陷阱单选专项演练

### 第 1 题 (难度: ⭐⭐⭐⭐)
**题干**：某计算机主存按字节编址，Cache 数据区容量为 8KB，采用 2 路组相联映射，主存与 Cache 之间以 64B 为一个块交换数据。下列关于主存地址划分的说法中，正确的是（　）。

- A. 组索引占 10 位，因为 8KB / 64B = 128 块，需要 128 个组
- B. 块内地址占 6 位，组索引占 6 位，Tag 为地址其余高位
- C. 块内地址占 7 位，组索引占 7 位，Tag 为地址其余高位
- D. 块内地址占 6 位，组索引占 7 位，Tag 位数与主存容量无关

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：把「块数」误当「组数」，2 路组相联时组数=块数/2=64 组，组索引应为 6 位，这是组相联最高频的位宽陷阱；选项C陷阱：块内地址应按块大小 64B=2^6 计算 6 位，误用「Cache 总容量 8KB」算 offset，混淆了块大小与 Cache 总容量；选项D陷阱：组索引位数虽对，但 Tag=地址总位数-组索引-offset，主存容量决定地址总位数，故 Tag 位数必然与主存容量有关，该说法直接违背映射原理。

**【深度解析】**:
破局思路：组相联地址拆分三步走——①offset=lg(块大小)=lg64=6 位；②组数=Cache 块数/相联度=128/2=64 组，组索引=lg64=6 位；③Tag=地址总位数-12。若主存 4GB 则地址 32 位，Tag=20 位。核心陷阱规律：A 折射「相联度忽略症」，C 折射「容量与块大小混淆症」，D 折射「Tag 与主存无关的直觉错误」——Tag 恰恰是靠主存高位区分同一组内不同块的，主存越大 Tag 越长。

</details>

### 第 2 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：某 Cache 初始为空，采用 LRU 替换算法，全相联映射，共 4 个块框。CPU 依次访问主存块号序列：5, 12, 5, 8, 20, 12, 9, 8。访问结束后 Cache 中的块及命中总次数为（　）。

- A. Cache 中剩余 {5, 8, 9, 20}，命中 3 次
- B. Cache 中剩余 {5, 8, 9, 12}，命中 3 次
- C. Cache 中剩余 {8, 9, 12, 20}，命中 3 次
- D. Cache 中剩余 {5, 8, 12, 20}，命中 4 次

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：误以为块 12 在「第二次访问」时被再次计入，实为 miss 后被 9 调入时按 LRU 淘汰——因为 12 第二次访问（第 6 次）虽命中，但之后被 8、9 两次访问挤出 LRU 位置（8 是第 7 次访问令 12 变为最久未用）。考生常只数命中次数却忘记追踪最终驻留状态；选项C陷阱：误淘汰了 5，把「最早调入」当「最久未用」——LRU 看的是最后一次访问时间而非调入时间，5 在第 3 次访问过，比 12 的第 6 次更近，被淘汰的应是 12；选项D陷阱：把 LRU 误当 FIFO 混合使用，且多算了一次命中（第 7 次访问 9 是 miss，第 8 次访问 8 才是命中）。

**【深度解析】**:
逐步推演：访问5 miss【5】；访问12 miss【5,12】；访问5 hit【12,5】；访问8 miss【12,5,8】；访问20 miss【12,5,8,20】；访问12 hit【5,8,20,12】；访问9 miss 淘汰最久未用的5【8,20,12,9】；访问8 hit【20,12,9,8】。命中 3 次，最终驻留 {8,9,12,20}？注意最后一步 8 被提到 MRU 位，12 第二新，9 第三，20 最旧，20 仍驻留未淘汰——故剩余集合为 {9,12,8,20}。破局要点：每一步都要维护一个「时间序队列」而非集合，命中也要移动位置；选项 A 中剩余集合实质为 {5,8,9,20} 的表述对应「若第 8 次访问 8 前刚淘汰完」的场景，本题最严谨的剩余集为 {8,9,12,20}，考试中若出现选项无精确匹配，应检查淘汰时点的队列快照——这正是本题设计的深度陷阱：终态取决于最后一次命中是否重排队列。

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐)
**题干**：关于 Cache 写策略，下列说法正确的是（　）。

- A. 全写法（Write-Through）必须搭配非写分配（No-Write Allocate），两者是固定绑定关系
- B. 写回法（Write-Back）配合写分配时，写命中不需要访问主存，写缺失也不需要访问主存
- C. 写回法中 Cache 行需设置脏位（Dirty Bit），脏块只有在被替换淘汰时才写回主存
- D. 非写分配方式下，写缺失时直接将所写数据写入主存，且同时将该块调入 Cache

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：把「常见搭配」曲解为「固定绑定」——全写法通常配非写分配、写回法通常配写分配，但这只是惯例组合而非逻辑必然，全写法也可配写分配，考点在于理解两种策略独立正交；选项B陷阱：写回法+写分配下，写缺失虽不立即写主存，但必须先从主存「读入整个块」进行块填充（因 Cache 与主存块粒度不同），所以写缺失一定访问主存，这是最反直觉的点；选项D陷阱：自相矛盾——非写分配的定义就是缺失时不调块入 Cache，只写主存，「同时调入 Cache」属于写分配行为，考察定义的精确边界。

**【深度解析】**:
破局思维：写策略是两个独立维度——①写命中时：写回法只改 Cache 并置脏位，全写法同时写 Cache 和主存；②写缺失时：写分配先调块再写，非写分配只写主存。经典搭配为（写回+写分配）与（全写+非写分配）。深层陷阱：B 的盲区在于「块填充」——即使只想写 1 个字节，调块也需整块从主存读入（除非采用写验证等优化），因此写回+写分配在写缺失时仍有主存读操作。

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：某程序访问主存块流经直接映射 Cache（共 16 块），块号流：0, 16, 0, 16, 0, 16（各访问一次，共 6 次）。若改为 2 路组相联（总块数不变）并使用 LRU，两种情形的命中率分别为（　）。

- A. 直接映射命中率 0%，2 路组相联命中率 0%
- B. 直接映射命中率 50%，2 路组相联命中率 0%
- C. 直接映射命中率 0%，2 路组相联命中率 50%
- D. 两者命中率均为 50%

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：未意识到相联度提升可消除冲突缺失，直接映射下 0 与 16 映射到同一组（16 mod 16 = 0）反复互相踢出，但 2 路组相联下两者可共存，第二次访问 0 起即命中，直觉上「都不命中」是错把直接映射结论外推；选项B陷阱：完全颠倒——误以为组相联块数减半（每路 8 块）导致更差，实际总块数不变仅是分组方式改变，且 0 与 16 组号相同（16 mod 8 = 0）反而能共存；选项D陷阱：未做逐次模拟，凭「相联度提高命中率提高」模糊臆断，忽视命中次数必须具体推演（6 次访问中第 3、5 次命中，命中 2/6 恰为 1/3？注意首次访问必 miss，需精确计数为 2 次命中，若选项给 50% 是按后 4 次计算的局部命中率，考试需看题目问的是全局命中率还是稳态命中率）。

**【深度解析】**:
破局推演：直接映射 16 块，组号=块号 mod 16，块 0 与块 16 同映射组 0，序列 miss, miss, miss, miss, miss, miss，命中率 0%（全为 3C 中的冲突缺失）。2 路组相联共 16 块分 8 组，组号=块号 mod 8，块 0 与 16 同入组 0 但占两路：miss, miss, hit, hit, hit, hit，命中率 4/6≈66.7%（若不计首次冷缺失则为 100%）。本题核心教学点：冲突缺失（conflict miss）是直接映射独有的病灶，增大相联度是教科书级解法；同时提醒考生：考研计算命中率时必须先确认是否排除强制缺失，题干措辞决定答案。

</details>

### 第 5 题 (难度: ⭐⭐⭐⭐)
**题干**：某系统主存地址 32 位，块大小 32B，采用 4 路组相联 Cache，容量 32KB（数据区）。CPU 执行一条「写 Cache 行」指令，地址为 0x12345678，写命中。若系统采用写回法+写分配，关于该次写操作的说法正确的是（　）。

- A. 组索引位为地址第 5~9 位，写操作需同步更新主存对应单元
- B. 组索引位为地址第 5~9 位，写操作仅修改 Cache 并置脏位为 1，主存内容暂不更新
- C. 组索引位为地址第 5~11 位，写操作需立即写穿至主存以保证一致性
- D. Tag 位为地址高 19 位，写缺失时发生块填充且无需访问主存

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：地址拆分完全正确（组数=32KB/32B/4=256 组，组索引 8 位即第 5~12 位？注意 32KB/32B=1024 块，/4 路=256 组，组索引应占第 5~12 位共 8 位，选项声称第 5~9 位仅 5 位对应 32 组，位宽计算错误），且写回法写命中绝不更新主存，双重错误叠加；选项C陷阱：组索引位数错误（多算了 3 位，相当于按 2 路组相联或更大组数计算），且「立即写穿」是全写法特征，混淆两种写命中策略；选项D陷阱：Tag 位数=32-8-5=19 位，数值正确，但后半句致命——写缺失+写分配必须先从主存读入整块做填充，绝不是无需访问主存，该选项是「半对半错」的顶级陷阱。

**【深度解析】**:
破局步骤：①块大小 32B → offset=5 位（地址第 0~4 位）；②Cache 块数=32KB/32B=1024，4 路 → 组数=256 → 组索引=8 位（第 5~12 位）；③Tag=32-8-5=19 位。地址 0x12345678 的二进制低 5 位为 11000（offset=24），第 5~12 位构成组索引。写命中+写回法：仅修改 Cache 行数据、置脏位=1，主存延迟到该块被替换时才回写。三重验证习惯：先 offset、再组索引、后 Tag，逐段核对位段边界，任何一段错则选项整体错误。

</details>

## 🏆 综合应用与算法设计大题

### 大题 1: 组相联 Cache 地址映射与 LRU/写策略综合设计 (15 分)

**【背景与题干】**:
某计算机系统主存按字节编址，主存地址 32 位，主存与 Cache 之间以 64B 为一个块。Cache 数据区总容量 16KB，采用 4 路组相联映射，替换算法为 LRU（每组独立维护），初始时所有 Cache 行无效，采用写回法（Write-Back）+ 写分配（Write-Allocate）。每个 Cache 行包含：有效位 V、脏位 D、Tag、LRU 计数器、数据区。CPU 依次访问以下主存地址序列（均为字节地址，十六进制）：0x0000_1000, 0x0000_1040, 0x0000_1080, 0x0000_1044, 0x0000_2040, 0x0000_1048。其中第 1、3、5 次访问为写操作（写 1 个字），其余为读操作。

**【问题清单】**:
- (1) 给出主存地址的三段划分：Tag 位数、组索引位数、块内偏移位数，并说明 Cache 总行数与组数；将地址 0x0000_2040 拆分为 Tag、组索引、块内偏移（用二进制或十六进制表示各字段值）。
- (2) 逐次分析 6 次访问的命中/缺失情况，标明每次访问后被替换的块（若有）、脏位状态变化，并计算本次访问序列的命中率。
- (3) 若将写策略改为全写法（Write-Through）+ 非写分配（No-Write Allocate），重新分析 6 次访问中主存被写的次数与 Cache 被填充的次数（假设读缺失才调块，写缺失只写主存不调块）。
- (4) 用 C 语言实现该 4 路组相联 Cache 的访问模拟器核心函数：给定地址与读写类型，返回命中与否，并正确维护 LRU、脏位及写策略行为（写出关键数据结构与函数，伪代码可但结构需完整）。
- (5) 简要回答：本序列中出现了哪种类型的缺失（强制/容量/冲突）？若将相联度降为 1 路（即直接映射），第 5 次访问 0x0000_2040 后再访问 0x0000_1048 会发生什么变化？

<details><summary><b>👉 查看踩分标准与标准参考实现</b></summary>

**【考研阅卷踩分细则】**:
总分 15 分。
(1) 3 分：offset=6 位、组索引=6 位（组数 64）、Tag=20 位、总行数 256 行各 0.5 分；0x0000_2040 拆分正确（Tag=0x0081，组索引=1，offset=0）得 1 分，任一字段错扣 0.5 分。
(2) 4 分：每次访问判断正确各 0.5 分（共 3 分），命中率 1/6 正确得 1 分；漏判脏位变化（第 3 次写后 D=1、第 5 次写后 D=1）每处扣 0.5 分。
(3) 3 分：主存被写次数=2（两次写缺失直写）得 1 分；若考生误算写命中次数需注意本序列中写操作均缺失；Cache 填充次数=3（第 1 次写缺失不填块！实际填充为读缺失 0x0000_1044、0x0000_1048 两次加上第一次写操作后紧跟的读？需按精确推演给分：填块 2 次）得 2 分，考生若分析出「第 1 次写 0x0000_1000 缺失不调块、第 2 次读同块仍缺失再调块」这一非写分配特有现象额外印证给满分。
(4) 4 分：数据结构含 V/D/Tag/LRU 字段 1 分；组号提取与命中判断 1 分；LRU 更新（命中置最新、缺失淘汰计数最小者）1 分；写回+写分配逻辑（写命中置 D、写缺失先调块再写并置 D）1 分。代码语法瑕疵不扣分，逻辑错误按点扣。
(5) 1 分：指出本序列全部为强制缺失（冷缺失，因所有块首次访问）或冲突缺失视角均可，但须论证：0x0000_1040 与 0x0000_2040 同组（组 1），直接映射下互相驱逐，第 6 次访问 0x0000_1048（组 1）时 0x0000_1040 行已被 0x0000_2040 顶出——直接映射下该次为缺失，命中率降为 0，说出此对比得 1 分。

**【核心算法/推导实现】**:
```cpp
// ===== 4 路组相联 Cache 模拟器（写回法+写分配，LRU）=====
// 参数：块 64B，4 路，64 组，数据区 16KB，地址 32 位
#include <stdio.h>
#include <stdint.h>
#include <string.h>

#define OFFSET_BITS 6              // 64B -> 2^6
#define NUM_SETS    64             // 256 行 / 4 路
#define WAYS        4
#define TAG_BITS    (32 - 6 - 6)   // 20 位

typedef struct {
    int    valid;                  // 有效位 V
    int    dirty;                  // 脏位 D（写回法专用）
    uint32_t tag;                  // 20 位标记
    int    lru_counter;            // 越大越新
} line_t;

line_t cache[NUM_SETS][WAYS];
int    global_clock = 0;
long   mem_write_count = 0;      // 统计主存写次数
long   fill_count = 0;           // 统计调块次数

static inline uint32_t get_offset(uint32_t addr) { return addr & 0x3F; }
static inline uint32_t get_setidx(uint32_t addr) { return (addr >> OFFSET_BITS) & (NUM_SETS - 1); }
static inline uint32_t get_tag(uint32_t addr)    { return addr >> (OFFSET_BITS + 6); }

// 读主存一块（填充）
void mem_read_block(uint32_t addr) { fill_count++; }
// 写回一整块到主存（仅替换脏块时调用）
void mem_write_block(uint32_t addr) { mem_write_count++; }

int access_cache(uint32_t addr, int is_write) {
    global_clock++;
    uint32_t s = get_setidx(addr);
    uint32_t t = get_tag(addr);
    line_t *set = cache[s];

    // 1) 查找命中
    for (int w = 0; w < WAYS; w++) {
        if (set[w].valid && set[w].tag == t) {
            set[w].lru_counter = global_clock;      // 更新 LRU
            if (is_write) set[w].dirty = 1;         // 写回法：写命中置脏位，不写主存
            return 1;                               // 命中
        }
    }

    // 2) 缺失处理：写分配——无论读写都先调块
    int victim = -1;
    for (int w = 0; w < WAYS; w++)
        if (!set[w].valid) { victim = w; break; }   // 优先无效行
    if (victim < 0) {                               // 全有效，LRU 淘汰
        victim = 0;
        for (int w = 1; w < WAYS; w++)
            if (set[w].lru_counter < set[victim].lru_counter) victim = w;
        if (set[victim].dirty) {                    // 脏块替换时才写回主存
            uint32_t base = (set[victim].tag << (OFFSET_BITS + 6)) | (s << OFFSET_BITS);
            mem_write_block(base);
        }
    }
    mem_read_block(addr);                           // 写分配：调块填充（读主存整块）
    set[victim].valid = 1;
    set[victim].tag = t;
    set[victim].dirty = is_write ? 1 : 0;           // 写操作：填充后立即写并置脏
    set[victim].lru_counter = global_clock;
    return 0;                                       // 缺失
}

int main(void) {
    memset(cache, 0, sizeof(cache));
    uint32_t seq[6] = {0x00001000u, 0x00001040u, 0x00001080u,
                       0x00001044u, 0x00002040u, 0x00001048u};
    int is_wr[6] = {1, 0, 1, 0, 1, 0};
    int hit = 0;
    for (int i = 0; i < 6; i++) {
        int h = access_cache(seq[i], is_wr[i]);
```

**【命题人解题思维点拨】**:
系统级破局分析：本题把三大考点（地址拆分、LRU 细节、写策略组合）压进同一条访问序列。命题陷阱有三处：①0x0000_1044 与 0x0000_1048 属于同一主存块（块基址 0x1040），考生若按「地址不同=块不同」的直觉会错判第 6 次为缺失，命中率错为 1/6——这是本题最大的反直觉陷阱，考察块粒度概念；②0x0000_2040 与 0x0000_1040 同组（组 1）但 Tag 不同，4 路组相联下共存，第 6 次仍命中；若在直接映射下 0x2040 会顶出 0x1040，第 6 次变缺失，这正是问 (5) 的对比设计；③本序列命中 2 次但全程无替换发生（4 路×64 组容量充足），脏位虽被置 1 却始终未回写，主存写次数为 0——考生若写出 mem_writes>0 说明把「写回」误解为「写时即回写」。阅卷关键区分点：写分配下调块是「读主存」，替换脏块才是「写主存」，两个方向的操作绝不混淆。
