## 🎯 高陷阱单选专项演练

### 第 1 题 (难度: ⭐⭐⭐⭐)
**题干**：某同步总线的工作时钟频率为 200MHz，地址线与数据线复用，总线位宽为 32 位。采用突发传输方式，每个总线事务先花 1 个时钟周期传送地址，随后连续传送 4 个数据字（无等待周期）。若考虑地址周期开销，该总线的实际有效带宽最接近于：

- A. 800 MB/s
- B. 640 MB/s
- C. 320 MB/s
- D. 160 MB/s

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：直接用 200MHz × 4B = 800MB/s，这是「峰值带宽」，完全忽略了地址周期开销，属于最经典的偷懒算法；选项C陷阱：把 5 个周期当作只传 2 个数据字处理，或将 32 位误算成 2 字节，单位换算混乱所致；选项D陷阱：将地址周期数错误放大（如按 4 个地址周期计算），或误以为复用总线后数据只能半字传输；选项B正确：5 个周期传 4 字 × 4B = 16B，带宽 = 16B ÷ (5 ÷ 200MHz) = 640MB/s。

**【深度解析】**:
破局思维：同步总线有效带宽 = 单次事务传输的有效字节数 ÷ 该事务占用周期数 × 时钟周期。本题为 4 字×4B=16B，事务共 1（地址）+4（数据）=5 周期，故带宽 = 200MHz × 16B / 5 = 640MB/s。命题陷阱在于区分「峰值带宽」与「有效带宽」，并考察对突发传输与复用总线地址开销的理解。

</details>

### 第 2 题 (难度: ⭐⭐⭐)
**题干**：关于集中式链式查询（菊花链）总线仲裁方式，下列说法正确的是：

- A. 离总线控制器越近的设备优先级越低，可通过修改计数器初值灵活调整优先级
- B. 总线授权信号 BG 串行地逐个传递，若某设备接口电路发生故障且未能旁路 BG，其后所有设备将永远无法获得总线
- C. 采用独立请求线方式，设备通过让 BR 有效直接发起总线占用，无需控制器响应
- D. 菊花链方式对优先级固定的缺陷无任何补救手段，硬件上完全无法实现优先级动态改变

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：前半句颠倒——菊花链中离控制器越近优先级越高；且「修改计数器」是计数器定时查询方式的特征，属于两大仲裁方式的特征张冠李戴；选项C陷阱：独立请求方式中 BR 只是请求信号，必须等控制器通过 BG 应答后设备才能占用总线，该选项混淆了「请求」与「授权」；选项D陷阱：说法过于绝对，实际可用「物理位置重排」「加旁路（跨接）逻辑」或结合软件禁用等手段缓解，考察对边界方案的辨析；选项B正确：BG 串行传递且默认无旁路时，链上任一环节失效即断链，这正是菊花链可靠性差的根源。

**【深度解析】**:
菊花链三根控制线：BR（请求）、BG（授权，串行传递）、BS（总线忙）。设备获得 BG 后置 BS 并截断 BG 下传。优点是控制线少、易扩展；缺点是优先级固定（近者先）、授权速度慢（逐级延迟）、链路敏感（单点故障可能断链）。破局思维：抓住 BG 的「串行传递 + 单向逐级」这一物理本质即可推出其可靠性与速度缺陷。

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐)
**题干**：某系统采用计数器定时查询方式仲裁，设备编号为 0~15。若每次总线释放后计数器都清零，则设备 12 在设备 0 频繁请求的负载下的表现，与每次释放后计数器从上次终止点继续计数的方案相比：

- A. 两种方案下设备 12 的优先级完全相同，因为计数器查询本质是纯轮转仲裁
- B. 清零方案中设备 12 几乎恒被设备 0 压制（优先级固定），不清零方案则具有轮转公平性，设备 12 平均等待更短
- C. 清零方案反而更公平，不清零方案会使设备 12 永远拿不到总线
- D. 不清零方案下设备 12 优先级最高，因为计数器终值点下一轮最先轮到高编号设备

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：断言「本质是轮转」是概念性错误——计数器初值策略决定了它是固定优先级还是轮转，不能一概而论；选项C陷阱：因果颠倒，清零恰恰是不公平的根源，而不清零也不会让任何设备「永远」拿不到总线，绝对化表述是致命陷阱；选项D陷阱：轮转方案的公平性对所有设备均等，并非编号大的设备优先级更高，误以为计数器顺序等于优先级排序；选项B正确：清零后每次都从 0 开始查询，设备 0 恒最先被命中，等价于固定优先级；不清零则从上次终止点继续，形成轮转，各设备机会均等。

**【深度解析】**:
计数器定时查询：控制器收到 BR 后启动计数器，逐一与设备号比对，匹配者获得总线。计数器初值是本题命门：恒为 0 ⇒ 固定优先级（0 最高）；从上次终止点继续 ⇒ 轮转公平。这是考纲中「计数器查询兼具灵活性与复杂度」的深层机制，命题常以负载场景考察其公平性差异。

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：采用异步通信的全互锁（非互斥的非对称描述）方式在总线上传送数据，设一次握手全程需经历：主控发地址与读命令 75ns，从设备译码并准备数据 150ns，主设备随后发出请求信号，从设备在收到请求 50ns 后给出数据就绪（ACK 有效）并维持数据，主设备在 50ns 后检测到 ACK 撤销请求，从设备再经 50ns 感知请求撤销后撤销 ACK 与数据。若忽略总线传播延迟与信号沿建立时间，从主控启动总线事务到该事务完全结束所需时间约为：

- A. 275 ns
- B. 325 ns
- C. 375 ns
- D. 425 ns

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：只计算了 75+150+50=275ns，漏掉了全互锁中「撤销阶段」的两次反向确认，属于典型的半途计算陷阱；选项B陷阱：只算了一次撤销延迟（+50ns），误以为主设备撤销请求即事务结束，忽略了从设备确认撤销才是全互锁的完整闭环；选项D陷阱：额外多加了一次 50ns（如误把主设备检测 ACK 也按来回两次计算），反映了把单向延时算成双向延时；选项C正确：75+150+50（主请求）+50（从ACK）+50（主撤销请求）+50（从撤销ACK）=375ns。

**【深度解析】**:
全互锁握手的本质：每个信号发出方都必须等到对方的「确认已收到我撤销」才能结束，共 4 次握手事件（请求、应答、撤销请求、撤销应答）。半互锁只保证请求被确认（缺最后撤销确认），不互锁则完全不等。破局思维：画时序图，数清楚信号边沿个数，每个边沿间隔一个所给延时。全互锁最可靠但最慢，这正是 408 常考的「可靠性与速度权衡」。

</details>

### 第 5 题 (难度: ⭐⭐⭐⭐)
**题干**：下列关于总线定时方式与仲裁方式的组合描述中，错误的是：

- A. 同步定时方式中，从设备若来不及完成操作，只能通过「等待周期 TW」延长，而时钟周期本身不变
- B. 分布式仲裁无需中央控制器，各设备通过比较自身仲裁号与总线上竞争号来决定是否继续发送，获胜者号值通常更大
- C. 异步全互锁方式对噪声和速度差异大的设备适应性最好，且其传输速度通常快于同步定时方式
- D. 独立请求方式中每个设备需 2 根独立控制线（BR、BG），n 个设备共需 2n 根，控制器可动态改变优先次序

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：本选项本身正确，但易与「同步总线必然固定时序、完全无法适应慢速设备」的错误认知混淆，实际同步总线可插入 TW；选项B陷阱：本身正确，分布式自举仲裁（如 SCSI、CAN 隐含的思想）号大者胜，考察对分布式仲裁「自比较」机制的理解；选项D陷阱：本身正确，2n 根请求/授权线的代价与灵活优先级的收益是独立请求方式的核心权衡；选项C错误：全互锁虽然适应性最好，但由于多次握手开销，速度通常「慢于」同步定时方式，前半句对、后半句反，是组合式半对半错陷阱的典型。

**【深度解析】**:
命题手法：四个选项均为复合判断，C 前半句（适应性最好）正确以降低警惕，后半句（速度快于同步）彻底反向——全互锁恰恰以牺牲速度换可靠性。破局思维：对复合选项必须逐半句验证，正确选项与干扰项都可能正确，锁定「错误的是」这一反向设问。

</details>

## 🏆 综合应用与算法设计大题

### 大题 1: 总线带宽计算、仲裁方案对比与异步握手时序综合设计 (15 分)

**【背景与题干】**:
某 32 位系统中，CPU、主存与磁盘控制器通过一条同步系统总线互连，总线上还挂接 4 个具有不同速度的 I/O 设备。总线时钟频率为 250MHz，位宽 32 位，每个总线事务包含 1 个地址周期、1 个仲裁与命令周期，之后连续传送 8 个数据字（突发传输，无等待）。系统同时考虑两条改造路线：路线一，将数据线加倍至 64 位；路线二，将时钟频率加倍至 500MHz（数据字仍 32 位，周期结构不变）。（1）计算原总线及两条改造路线下的有效带宽（MB/s，按 10^6 进制）。（2）若磁盘控制器需要在 1ms 内传送 40MB 数据，判断三条总线中哪些满足需求。（3）4 个设备 D0~D3 分别在仲裁中请求频率之比为 8:4:2:1，分别计算采用「固定优先级（D0 最高）」与「轮转计数器（每次从上次终止点继续）」两种仲裁方案下，长时间运行时 D3 获得总线的时间占比，并说明哪种方案对实时性要求高的低速设备更有利。（4）若改用异步全互锁方式为慢速设备服务，一次握手需 4 次信号事件，每次事件间隔 40ns，试推导一次单字传输事务的握手总延时，并与同步方式单周期（4ns）比较，说明全互锁的适用场景。

**【问题清单】**:
- (1) 计算原总线与两条改造路线的有效带宽（MB/s），要求写出事务周期数与传输字节数的推导过程。
- (2) 判断三条总线中哪些能满足磁盘控制器 1ms 内传 40MB 的需求，并给出判据。
- (3) 分别计算固定优先级与轮转计数器方案下 D3 获得总线的时间占比，并对实时性影响作出结论。
- (4) 推导异步全互锁单字传输的握手总延时，并与同步单周期 4ns 比较，说明全互锁的适用场景。

<details><summary><b>👉 查看踩分标准与标准参考实现</b></summary>

**【考研阅卷踩分细则】**:
踩分标准（共 15 分）：
(1) 共 5 分：正确写出事务周期数 = 1（地址）+1（仲裁命令）+8（数据）=10 周期，得 2 分；原总线带宽 = 250MHz×32B/10 = 800MB/s，得 1 分；路线一 = 1600MB/s、路线二 = 1600MB/s，各 1 分。带宽计算错误但方法正确酌情给一半分。
(2) 共 3 分：写出需求带宽 40MB/1ms = 40MB/s 量级换算（40×10^6 B/s）得 1 分；三条总线均满足（均 ≥800MB/s > 40MB/s）得 1 分；指出磁盘瓶颈实际在于寻道与设备内部速率而非总线，得 1 分。
(3) 共 4 分：固定优先级下 D3 占比 = 1/(8+4+2+1) = 1/15 ≈ 6.67%，得 2 分（若误按权重相反的排序得出 D0 最低优先级则扣 1 分）；轮转方案下各设备占比均为 1/4 = 25%，得 1 分；结论：轮转（计数器不清零）对低速实时设备更有利，得 1 分。
(4) 共 3 分：总延时 = 4×40ns = 160ns，得 2 分（只写 2 次事件 80ns 得 1 分，说明漏计撤销阶段）；比较结论：全互锁慢约 40 倍但可靠性高、适应速度差异大的设备，适用于慢速、异构、可靠性优先的 I/O 总线，得 1 分。

**【核心算法/推导实现】**:
```cpp
// 总线带宽与仲裁占比计算（C++）
#include <cstdio>

int main() {
    const double f0 = 250e6;       // 原时钟频率 250MHz
    const int addrCyc = 1, cmdCyc = 1, burst = 8;
    const int cycles = addrCyc + cmdCyc + burst;   // 10 周期

    // (1) 带宽（B/s），按 1MB = 1e6 B
    double bw_orig = f0 * (burst * 4.0) / cycles;            // 32位=4B
    double bw_w64  = f0 * (burst * 8.0) / cycles;            // 64位=8B
    double bw_f500 = (2 * f0) * (burst * 4.0) / cycles;      // 500MHz
    printf(\'original: %.0f MB/s\', bw_orig / 1e6);
    printf(\'width64 : %.0f MB/s\', bw_w64 / 1e6);
    printf(\'freq500 : %.0f MB/s\', bw_f500 / 1e6);

    // (2) 磁盘需求 40MB per 1ms = 40e6 B/s
    double need = 40e6;
    printf(\'orig ok=%d, w64 ok=%d, f500 ok=%d\',
           bw_orig >= need, bw_w64 >= need, bw_f500 >= need);

    // (3) 仲裁占比
    int w[4] = {8, 4, 2, 1};   // 请求频率比
    int sum = 8 + 4 + 2 + 1;
    printf(\'fixed-prio D3 share = %.4f\', 1.0 / sum);  // 1/15≈6.67%
    printf(\'round-robin D3 share = %.4f\', 1.0 / 4);    // 25%

    // (4) 全互锁握手延时：4 次信号事件，每次 40ns
    double hand = 4 * 40.0;    // 160ns
    printf(\'full-handshake = %.0f ns, sync 1-cycle = 4 ns\', hand);
    return 0;
}

/* 推导矩阵
周期结构：1(地址) + 1(仲裁命令) + 8(数据) = 10 周期
原总线：250M × 32B / 10 = 800 MB/s
路线一：250M × 64B / 10 = 1600 MB/s（数据线加倍）
路线二：500M × 32B / 10 = 1600 MB/s（频率加倍）
需求：40MB / 1ms = 40 MB/s < 800 MB/s，三条总线均满足
固定优先级：D0>D1>D2>D3，D3 长期占比 = 1/15 ≈ 6.67%
轮转计数器：长期均分，D3 占比 = 1/4 = 25%
全互锁：请求+应答+撤请求+撤应答 = 4×40ns = 160ns，慢于同步但可靠 */
```

**【命题人解题思维点拨】**:
本题考查三线合一：带宽计算（区分峰值与有效带宽、计入地址与仲裁开销）、仲裁策略对公平性的量化影响（固定优先级 vs 轮转的占比差异）、同步与异步定时的速度-可靠性权衡。命题陷阱有四：其一，考生易漏掉仲裁与命令周期，把 8 周期当分母；其二，带宽换算 32 位 = 4B 的单位陷阱；其三，固定优先级占比按请求频率比归一化而非简单四等分，需理解「D0 恒被服务、D3 只在无人请求时才轮到」的排队直觉；其四，全互锁必须数满 4 次信号事件，漏计撤销阶段是最常见错误。破局思维：一切定时问题画时序图数边沿，一切仲裁问题算长期稳态占比。

</details>
