### 第 1 题 (难度: ⭐⭐⭐⭐)
**题干**：设入栈序列为 1,2,3,4,5，且入栈过程中允许任意时刻出栈。若已知元素 3 是第一个出栈的元素，则可能的出栈序列共有多少种？

- A. 4 种
- B. 6 种
- C. 5 种
- D. 9 种

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：误以为 1,2 被压在栈底后只能整体逆序输出，实际上 1、2 在栈中的相对顺序可以在 3 出栈后的任意交错时机弹出，与后续 4、5 的进出组合，并非只有 1 种；选项C陷阱：只考虑到 3 出栈后栈内剩 1、2 两种排列，漏算了 4、5 在 1、2 出栈过程中插入进出的情形；选项D陷阱：直接用卡特兰数 C(4)=14 的思路随意折半，缺乏约束推导依据，属于拍脑袋凑数。

**【深度解析】**:
3 第一个出栈，意味着入栈顺序为 1,2,3 后立即弹出 3，此时栈内自底向上为 1,2。此后 4、5 可在任意时机入栈。问题等价于：栈中已有 1,2 两个元素（1 在底），加上后续可入栈的 4,5，求合法出栈序列数。将 1,2 视为已入栈序列，4,5 待入栈，总方案数即 4 个元素（其中 1,2 已在栈内保持相对顺序 1→2，4,5 保持相对顺序 4→5）的出栈序列数。枚举：序列内 1,2 的相对次序固定、4,5 相对次序固定，等效于对 2 个『内部有序对』做栈合法交错，共有 C(4,2)/2 结构推导得 6 种。具体枚举：2,1,4,5 / 2,4,1,5 / 2,4,5,1 / 4,2,1,5 / 4,2,5,1 / 4,5,2,1，恰好 6 种。破局思维：将约束（3 先出）转化为栈初态+剩余待入元素，把复杂问题规约为标准栈交错计数问题。

</details>

### 第 2 题 (难度: ⭐⭐⭐)
**题干**：循环队列采用『牺牲一个存储单元』法区分队空与队满，数组容量为 m（下标 0~m-1），front 指向队头元素，rear 指向队尾元素的下一位置。下列说法正确的是：

- A. 队满条件为 (rear+1) mod m == front，此时队列中实际可存放 m 个元素
- B. 队满条件为 rear == front，队列最多可存放 m-1 个元素
- C. 队满条件为 (rear+1) mod m == front，队列最多可存放 m-1 个元素
- D. 若入栈和入队共用该判满逻辑，则顺序栈判栈满也可用 (top+1) mod m == top 实现

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：判满公式本身正确，但断言『可存放 m 个元素』是致命错误——牺牲单元法的本质就是用损失一个单元换取判空判满条件可区分，实际容量为 m-1；选项B陷阱：rear==front 是判空条件而非判满条件，把它当判满会导致队空队满不可区分，这是该知识点最高频的概念性陷阱；选项D陷阱：循环队列的 mod 运算判满是针对首尾相接的环形结构，顺序栈只有一个生长方向，栈满判据应为 top==m-1，混用公式暴露对两种结构本质差异理解不清。

**【深度解析】**:
牺牲单元法：front==rear 判空；牺牲 rear==front 那个位置不可存元素，使得队满时 (rear+1) mod m == front，两条件不再重合。由于始终空留一个单元，最大容量为 m-1。破局思维：看到循环队列先确认两件事——指针指向约定（指向元素还是空位）与判满方案（牺牲单元 / tag 标记 / 计数器），不同约定下公式完全不同，切勿套模板。

</details>

### 第 3 题 (难度: ⭐⭐⭐)
**题干**：循环队列用整型变量 tag（取值 0 或 1）配合 front、rear 判别队空队满，且不牺牲任何存储单元，数组容量为 m。每次成功入队后置 tag=1，成功出队后置 tag=0。则下列判断正确的是：

- A. 队满：front==rear 且 tag==1；队空：front==rear 且 tag==0，队列容量为 m
- B. 队满：front==rear 且 tag==0；队空：front==rear 且 tag==1，队列容量为 m
- C. 队满条件无需 tag，仅 front==rear 即可判满
- D. tag 的引入使队列容量变为 m+1

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：tag 语义弄反——只有刚发生过入队（tag=1）时 front==rear 才可能因『装满』所致；若刚出队（tag=0）则必是空，颠倒后判断全错；选项C陷阱：front==rear 时队列既可能是满也可能是空，仅凭指针无法区分，这正是必须引入 tag 或牺牲单元的根本原因；选项D陷阱：tag 只是一个状态标志，不占用环形存储空间，也不增加容量，容量仍为 m，此选项诱导考生把『辅助变量』误解为『扩容手段』。

**【深度解析】**:
tag 标记法：记录最后一次操作是入队还是出队。front==rear 时，若最后一次是入队（tag=1）则必满，若是出队（tag=0）则必空。由于不牺牲单元，容量可达满额 m。对比记忆：牺牲单元法用『空间换判别』，tag 法用『一个标志位换空间』，二者是同一问题的两种工程权衡。破局思维：从『最后一次操作』这一动态视角理解 tag，而非死背公式。

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐)
**题干**：将中缀表达式 A+B*C-(D-E/F) 转换为后缀表达式，转换过程中操作符栈内最多同时存在多少个操作符？

- A. 2 个
- B. 3 个
- C. 4 个
- D. 5 个

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：只跟踪了 A+B*C 阶段（栈内 + 与 *），忽略了括号 '(' 压栈后内部操作符 - 与 / 的叠加；选项B陷阱：漏算了 '(' 本身也占据栈空间，或漏算了 '-（外层减号）' 在 '(' 之前的驻留；选项D陷阱：误认为 ') ' 匹配后 '-' 仍与内部符号共存，或把已弹出的 '+' 重复计入。陷阱核心：括号 '(' 必须入栈充当屏障，且外层操作符在括号处理期间始终压在屏障之下。

**【深度解析】**:
逐步跟踪：遇 + 入栈[+]；遇 * 入栈[+ *]；遇 - ，* 高于 - 先弹 *，再弹 +，- 入栈[-]（栈内 1 个）；遇 ( 入栈[- (]（2 个）；遇 - 入栈[- ( -]（3 个）；遇 / 入栈[- ( - /]（4 个）——达到最大值 4；遇 ) 依次弹出 / 与 -，弹出 (，栈内剩 [-]。此后无操作符入栈。答案为 4。破局思维：手工模拟时为每个符号画出栈快照，特别注意 '(' 入栈这一步最易被忽略。

</details>

### 第 5 题 (难度: ⭐⭐⭐⭐)
**题干**：关于递归调用与系统栈，下列叙述正确的是：

- A. 递归函数改写为非递归时，若原递归中存在『调用后仍需使用局部数据回续执行』的语句，则必须借助用户自定义栈保存现场
- B. 递归深度只取决于递归函数代码长度，与每次调用开辟的栈帧大小无关
- C. 尾递归因为也要保存返回地址，其空间复杂度与普通递归完全相同，均为 O(n)
- D. 任何递归算法转换为非递归算法后，时间复杂度一定会降低

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：递归深度取决于递归调用链长度，而总栈空间 = 深度 × 单帧大小，局部变量与参数越多的函数单帧越大，栈溢出风险与其直接相关，此选项混淆了『深度』与『空间总量』；选项C陷阱：尾递归的返回地址与局部变量在编译器优化下可复用当前帧（空间 O(1)），断言『完全相同 O(n)』忽视了尾递归可被优化为循环的本质；选项D陷阱：递归转非递归通常只优化空间（从 O(n) 降到 O(1)），时间复杂度量级一般不变，『一定降低时间』是典型绝对化表述陷阱。

**【深度解析】**:
递归的本质是编译器用系统栈自动保存：返回地址、参数、局部变量。若回续点之后不再需要任何局部数据（如尾递归），可简单用循环改写；若回续后仍需使用之前的现场（如二叉树中序遍历回到双亲节点继续处理右子树），非递归版本必须自建栈保存这些数据。破局思维：判断一个递归能否用简单循环消除，就看『返回后还要不要用到调用时的局部信息』。

</details>

### 大题 1: 循环队列的 tag 法设计与中缀表达式求值器的综合实现 (15 分)

**【背景与题干】**:
某系统需实现一个基于循环队列的『符号缓冲区』与一个中缀算术表达式求值器。约定如下：(1) 循环队列使用整型数组 Q[MaxSize]（MaxSize=m），front 指向队头元素，rear 指向队尾元素的下一位置，使用 tag 标记法判空判满，不牺牲存储单元，入队成功置 tag=1，出队成功置 tag=0。(2) 求值器接收仅含正整数、+、-、*、/、(、) 的中缀表达式（表达式合法、不含负数与一元运算符），采用『先转后缀、再对后缀求值』的两步法，后缀表达式以字符串 token 序列暂存于符号缓冲区逻辑中。请完成各小问。

**【问题清单】**:
- (1) 写出 tag 法循环队列的判空与判满条件，并说明该方案相对『牺牲一个单元法』在容量与判别原理上的本质差异，推导队列中元素个数的计算公式。
- (2) 给出 tag 法循环队列的完整 C/C++ 实现：EnQueue、DeQueue、QueueLength 三个函数，要求处理满/空的边界并返回状态码。
- (3) 设中缀表达式为 3+4*(2-1)-5/2，手工写出①操作符栈状态变化（含 '('、')' 的处理）与最终后缀表达式；②再对该后缀表达式用操作数栈求值，写出每步栈变化并给出最终结果（除法为整除）。
- (4) 编写 C/C++ 代码：实现中缀转后缀（含优先级比较与括号处理）与后缀求值两个函数，并给出主函数对该表达式求值的完整可运行程序。

<details><summary><b>👉 查看踩分标准与标准参考实现</b></summary>

**【考研阅卷踩分细则】**:
总分 15 分。(1) 3 分：判空条件 front==rear 且 tag==0 得 1 分；判满条件 front==rear 且 tag==1 得 1 分；指出容量为 m（不牺牲单元）且本质是『用最后一次操作的方向信息区分同指针状态』得 1 分，元素个数公式 (rear-front+m) mod m 正确再得该分内要点（公式错误扣 1 分）。(2) 4 分：EnQueue 中满判断 1 分、入队后 rear=(rear+1)%m 且置 tag=1 共 1 分；DeQueue 中空判断 1 分、出队后 front=(front+1)%m 且置 tag=0 共 1 分；QueueLength 公式错误扣 1 分。(3) 4 分：转后缀过程栈变化与结果 3+4 2 1 - * + 5 2 / - 完全正确得 2 分（括号处理错误扣 1 分，运算符优先级错误扣 1 分）；后缀求值结果 5 正确得 2 分（整除 5/2=2 求成 2.5 导致最终结果错误的扣 1 分，仅符号顺序错扣 1 分）。(4) 4 分：转后缀函数中优先级表或比较逻辑正确 1 分，括号出入栈正确 1 分；求值函数中操作数弹出次序（先弹为右操作数）正确 1 分；主函数完整可编译运行、边界处理合理 1 分。

**【核心算法/推导实现】**:
```cpp
// ===== (1)(2) tag 法循环队列 =====
#include <cstdio>
#include <cstring>
#include <cstdlib>
#define MaxSize 100

typedef struct {
    int data[MaxSize];
    int front, rear;
    int tag; // 0: 最近出队/初始, 1: 最近入队
} CirQueue;

// 判空: front==rear 且 tag==0; 判满: front==rear 且 tag==1; 容量 m 不牺牲单元
void InitQueue(CirQueue &q){ q.front = q.rear = 0; q.tag = 0; }

int QueueLength(const CirQueue &q){
    return (q.rear - q.front + MaxSize) % MaxSize;
}

int EnQueue(CirQueue &q, int x){
    if (q.front == q.rear && q.tag == 1) return 0; // 队满
    q.data[q.rear] = x;
    q.rear = (q.rear + 1) % MaxSize;
    q.tag = 1;
    return 1;
}

int DeQueue(CirQueue &q, int &x){
    if (q.front == q.rear && q.tag == 0) return 0; // 队空
    x = q.data[q.front];
    q.front = (q.front + 1) % MaxSize;
    q.tag = 0;
    return 1;
}

// ===== (4) 中缀转后缀 + 后缀求值 =====
// token 序列以字符串数组表示, 每个元素是一个数字串或单字符运算符

int prio(const char *op){ // 栈内优先级
    if (op[0] == '(') return 0;      // 屏障
    if (op[0] == '+' || op[0] == '-') return 1;
    return 2;                        // * /
}

int isInfix(char c){ return c=='+'||c=='-'||c=='*'||c=='/'||c=='('||c==')'; }

// 中缀 token 数组 infix[n] -> 后缀 token 数组 post, 返回后缀 token 个数
int toPostfix(char *infix[], int n, char *post[]){
    char *opstk[MaxSize]; int top = -1; // 操作符栈
    int k = 0;
    for (int i = 0; i < n; i++){
        char *t = infix[i];
        if (!isInfix(t[0]) || (t[0]>='0'&&t[0]<='9')){ // 操作数(多位数)
            post[k++] = t;
        } else if (t[0] == '('){
            opstk[++top] = t;
        } else if (t[0] == ')'){
            while (top >= 0 && opstk[top][0] != '(') post[k++] = opstk[top--];
            top--; // 弹出 '('
        } else {
            // 栈顶优先级 >= 当前 则先弹出(左结合)
            while (top >= 0 && prio(opstk[top]) >= prio(t)) post[k++] = opstk[top--];
            opstk[++top] = t;
        }
    }
    while (top >= 0) post[k++] = opstk[top--];
    return k;
}

// 后缀 token 数组求值, 返回 1 成功
int evalPostfix(char *post[], int n, int &result){
    int stk[MaxSize]; int top = -1;
    for (int i = 0; i < n; i++){
        char *t = post[i];
        if (!(t[0]=='+'||t[0]=='-'||t[0]=='*'||t[0]=='/') || (t[0]>='0'&&t[0]<='9')){
            stk[++top] = atoi(t);
        } else {
            int r = stk[top--]; // 先弹出的为右操作数!
            int l = stk[top--];
            int v = 0;
            switch (t[0]){
                case '+': v = l + r; break;
                case '-': v = l - r; break;
                case '*': v = l * r; break;
                case '/': v = l / r; break; // 整除
            }
            stk[++top] = v;
        }
    }
    if (top != 0) return 0;
    result = stk[0];
    return 1;
}

int main(){
    // 表达式 3+4*(2-1)-5/2 的 token 序列
    char *infix[] = {(char*)"3",(char*)"+",(char*)"4",(char*)"*",(char*)"(",
                     (char*)"2",(char*)"-",(char*)"1",(char*)")",
                     (char*)"-",(char*)"5",(char*)"/",(char*)"2"};
    int n = 13;
    char *post[MaxSize];
    int m = toPostfix(infix, n, post);
    printf("后缀表达式: ");
    for (int i = 0; i < m; i++) printf("%s ", post[i]);
    printf("\n");
    int res;
    if (evalPostfix(post, m, res)) printf("求值结果 = %d\n", res); // 输出 5
    return 0;
}
```

**【命题人解题思维点拨】**:
本题系统级破局思路：第一层考察循环队列两种判满方案的深层权衡——牺牲单元法『空间换判别』，tag 法『状态信息换空间』，理解 front==rear 这一『重合态』的二义性是关键；元素个数公式 (rear-front+m) mod m 对两种方案通用但容量上限不同（tag 法 m，牺牲单元法 m-1）。第二层通过手工模拟逼出两个最易错的边界：转后缀中 '(' 必须入栈充当优先级屏障且弹出 ')' 时要丢弃 '('；后缀求值中先弹出的操作数是右操作数，减法除法次序颠倒即错。第三层陷阱是整除语义：5/2=2 而非 2.5，若按浮点计算最终得 3.5 而非 5，正是阅卷高频扣分点。代码中操作数识别需注意多位数（以首字符是否为数字判定），这与仅支持单位数的简化版是常见命题区分点。

</details>
