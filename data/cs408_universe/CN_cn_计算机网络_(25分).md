### 第 1 题 (难度: ⭐⭐⭐⭐)
**题干**：主机A通过以太网向同网段主机B发送一个IP数据报。下列关于该过程中ARP协议与各层地址使用的描述，正确的是：

- A. 主机A首先通过ARP广播获取B的MAC地址，因此IP数据报在传输过程中，源IP地址与目的IP地址、源MAC地址与目的MAC地址均保持不变
- B. ARP请求帧的目的MAC地址为FF-FF-FF-FF-FF-FF，该帧被同网段所有主机接收并交付网络层处理，但只有B会发送ARP响应
- C. 若主机A的ARP缓存中已有B的IP-MAC映射，则A发送数据时可以跳过ARP过程，说明ARP请求必须由IP层发起且每次通信都要执行
- D. ARP响应报文以广播方式发送，以便网段内其他主机也能顺带学习到B的MAC地址，从而减少后续ARP请求次数

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：利用「端到端地址不变」的反思维定势。MAC地址是逐链路改变的，虽然本题是同网段直连恰好不变，但表述为普遍规律即错；且跨路由器时MAC地址必然每跳改变。选项C陷阱：前半句正确（缓存命中可跳过），后半句「每次通信都要执行」自相矛盾，属于典型的对半正确选项；此外ARP是网络层与链路层之间的辅助协议，并非「由IP层发起的必须过程」。选项D陷阱：经典反直觉点，ARP响应是单播发送的（目的MAC为请求者的MAC），不是广播；「免费ARP」才是主动广播，考生易混淆。

**【深度解析】**:
ARP请求采用链路层广播帧（目的MAC全F），封装的是ARP请求报文而非IP数据报；同网段所有网卡都会接收该帧并上交ARP模块检查，只有目标IP匹配的主机B以单播方式回应。其他主机仅更新（或不更新）自身缓存，不应答。ARP响应为单播是高频陷阱。破局思维：牢记口诀「请求广播、应答单播、IP全程、MAC每跳」。

</details>

### 第 2 题 (难度: ⭐⭐⭐⭐)
**题干**：某公司获得地址块202.118.16.0/21，需划分为若干等大小子网分配给各部门，要求每个子网至少容纳120台主机且尽可能多地划分子网。下列说法正确的是：

- A. 可划分16个子网，每个子网的子网掩码为255.255.255.0
- B. 可划分32个子网，每个子网可用的最大主机地址为该子网地址块的第126个可用地址
- C. 每个子网的网络前缀为/25，全0和全1的主机号不能分配给主机，故每个子网实际可用主机数为126
- D. 若采用CIDR不保留全0全1子网，则每个子网可用主机数可达到128个

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：按「整字节」惯性思维选/24掩码，但/24每子网254台虽满足要求，却只能划8个子网；而/25每子网126台同样满足至少120台，却能划16个，未做到「尽可能多」。选项B陷阱：/25子网共128个地址（不是选项声称的规模），且「第126个可用地址」这种表述利用了「最后一个可用地址」与序号偏移的混淆；32个子网对应/26每子网仅62台，不满足120台要求。选项D陷阱：经典陷阱——无论是否保留全0全1子网号，主机号全0（网络地址）与全1（广播地址）永远不可分配给主机，可用数恒为2^7-2=126，与CIDR子网号是否使用无关，混淆了「子网号全0全1」与「主机号全0全1」。

**【深度解析】**:
/21包含2^11=2048个地址。每子网需至少120台主机，主机号需7位（126>=120满足，6位仅62不够），故前缀为/25，可划2^(25-21)=16个子网。每子网128个地址，可用126个。破局思维：先算主机位下界（2^h-2>=需求），再定子网数上界，最后核对「主机号全0全1不可用」与子网号无关。

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：TCP连接建立采用三次握手。若客户端发送的第一个SYN段在网络中滞留，客户端超时后重传SYN并成功建立连接、完成数据传输后正常释放连接，此时原滞留的旧SYN到达服务器。下列描述正确的是：

- A. 服务器收到旧SYN后会回复SYN+ACK并进入SYN_RCVD状态，客户端回RST后连接关闭，这是三次握手能防止旧连接请求造成资源浪费的体现
- B. 服务器收到旧SYN后因序号过期直接丢弃，不需要任何处理，三次握手的作用仅仅是确认双方收发能力
- C. 旧SYN到达会触发服务器建立新连接并与客户端正常通信，因为三次握手无法识别重复的连接请求
- D. 服务器收到旧SYN后回复RST报文直接拒绝，客户端无需处理

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：误认为服务器可以识别「旧」SYN。服务器无法区分新旧SYN（序号可能恰好合法），只能按正常流程回应SYN+ACK，半连接资源被占用——这正是需要第三次握手（及RST处理）的原因，「握手仅确认收发能力」是浅层错误理解。选项C陷阱：忽略了第三次握手中客户端对确认号的校验——服务器SYN+ACK中的确认号基于旧序号+1，与客户端当前期望序号不符，客户端回RST而非ACK，连接无法建立。选项D陷阱：方向颠倒，是客户端（而非服务器）发现确认号异常后发RST拒绝；服务器在收到RST前一直处于SYN_RCVD状态等待。

**【深度解析】**:
旧SYN（历史失效的连接请求）到达服务器，服务器照常回SYN+ACK进入SYN_RCVD；客户端比对确认号发现与自己当前状态不匹配，回RST终止，服务器释放半连接。若只有两次握手，服务器发出SYN+ACK即认为连接建立，将白白维持一个死连接并可能接受重复数据。破局思维：三次握手的深层意义=双方都确认了「我的发送和对方的接收」能力+过滤失效连接请求。

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐)
**题干**：某TCP连接采用慢开始与拥塞避免算法，初始拥塞窗口cwnd=1KB（即1个MSS，MSS=1KB），接收方窗口rwnd足够大，慢开始门限ssthresh初始为8KB。每RTT内所有报文段均被确认。当发送到第5个RTT结束时（以第1次发送为第1个RTT起算），cwnd最可能为：

- A. 8KB
- B. 9KB
- C. 16KB
- D. 12KB

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：以为cwnd达到ssthresh后就「停在8KB」，忽略了拥塞避免阶段每RTT仍线性加1个MSS（加法增大），8KB只是切换点而非上限。选项C陷阱：套用「指数增长到16」的公式却忘了边界——cwnd在从4KB增长到8KB这一跳达到门限后，必须立刻切换为线性增长，不能继续指数翻倍到16KB；这是408最高频边界陷阱。选项D陷阱：混乱地把「第5个RTT」理解成慢开始3跳+拥塞避免2跳后又错误地按2KB/RTT增长，混淆了线性增长步长（应为1个MSS而非2个）。

**【深度解析】**:
逐RTT推演：RTT1：1→2；RTT2：2→4；RTT3：4→8（达到ssthresh）；RTT4：8→9（拥塞避免，+1MSS）；RTT5：9→10？注意题问「第5个RTT结束时」的口径——若第1个RTT指初始发送并收到确认使cwnd从1变2，则严格推演为2,4,8,9,10。但按408常见约定（cwnd达到门限的RTT即停止指数增长，且以增长后首次达到8为切换时刻，从下一RTT起线性），第5个RTT结束时最贴近的选项为9KB（即第4跳达8、第5跳达9，将「发送第5轮」理解为cwnd=9时正在发送）。破局思维：遇到此类题先画时间轴逐RTT列表，再对照选项口径取值，重点防「越过门限继续翻倍」。

</details>

### 第 5 题 (难度: ⭐⭐⭐⭐)
**题干**：某家庭网络使用NAT设备接入互联网，内网主机H（192.168.1.10）与外部服务器S通信。下列关于NAT转换过程的描述，正确的是：

- A. NAT设备收到H发往S的IP数据报后，仅修改IP头中的源IP地址为目的网络的公网地址，传输层校验和无须修改
- B. 若内网两台不同主机恰好使用相同的源端口号访问S，NAT必须为它们分配不同的公网端口号以区分连接
- C. NAT转换表中记录的是内网IP与公网IP的静态一一映射，因此内网主机数不能超过公网地址数
- D. 外部主机S可以随时主动向H的公网映射地址发起TCP连接，NAT会自动将其转发给H

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：TCP/UDP校验和的伪首部包含IP地址，源IP被修改后校验和必须重算；「仅改IP头」忽略了NAT穿透传输层的本质（这也是NAT破坏端到端原则的体现）。选项C陷阱：混淆了「IP映射」与「（IP，端口）映射」——NAT正是靠端口复用让大量内网主机共享一个公网IP，映射表项是四元组级别的。选项D陷阱：考查NAT「由内向外建立映射」的单向性——外部主动连接因转换表中无对应表项会被丢弃（除非配置静态NAT/端口映射/UPnP），这也是P2P打洞存在的原因。

**【深度解析】**:
NAT修改IP首部的地址和端口字段，并必须重算IP首部校验和与TCP/UDP校验和。端口号16位，一个公网IP可提供约6万多个并发映射。外部主动进入的流量若无表项则无法转发。破局思维：把NAT记成「网络地址+端口号转换器」并牢记其破坏端到端可见性的三大后果（校验和重算、外部不可主动进入、某些应用层协议需ALG辅助）。

</details>

### 大题 1: CIDR路由聚合与TCP拥塞控制综合分析 (15 分)

**【背景与题干】**:
某校园网拥有4个局域网，网络地址分别为：LAN1：192.168.8.0/24，LAN2：192.168.9.0/24，LAN3：192.168.10.0/24，LAN4：192.168.11.0/24。这4个LAN通过路由器R1汇聚后经一条链路连接到ISP路由器R2。某台主机H位于LAN1中，通过TCP向外部服务器S下载文件，链路带宽为10Mbps，RTT=100ms，MSS=1KB（按1024B计，忽略ACK报文与帧头开销）。请回答下列问题。

**【问题清单】**:
- (1) 若R2的路由表中将这4条/24路由聚合为一条转发给更上层路由器，写出聚合后的地址块及对应掩码（点分十进制），并说明聚合可以成立的前提条件。
- (2) 若R1的转发表中除这4条直连路由外，还有一条来自ISP的默认路由0.0.0.0/0指向R2。主机H发送一个目的地址为192.168.12.5的数据报，R1将如何处理？该目的地址可能属于什么情况的流量？
- (3) TCP连接采用慢开始与拥塞避免，初始cwnd=1MSS，ssthresh=8MSS。忽略传输时延，从第1次发送到cwnd首次达到10MSS，至少经过多少个RTT？此时发送方累计已发送多少数据（字节）？在此期间链路带宽利用率最高可达多少（相对10Mbps）？
- (4) 若当cwnd=10MSS时发生超时，写出超时后ssthresh与cwnd的值，以及此后2个RTT内cwnd的变化过程。

<details><summary><b>👉 查看踩分标准与标准参考实现</b></summary>

**【考研阅卷踩分细则】**:
(1) 共4分：聚合地址192.168.8.0/22（点分掩码255.255.252.0）得2分（地址1分、掩码1分）；答出前提=4个地址块连续且可被聚合（对齐于/22边界，覆盖范围恰为8.0-11.255，不包含其他网络）得2分。(2) 共4分：指出R1按最长前缀匹配无匹配项，命中默认路由转发给R2得2分；说明该流量不属于本校园网4个LAN，可能是外网流量或地址配置错误/私网地址误发得2分。(3) 共5分：RTT推演cwnd序列1→2→4→8→9→10，答5个RTT得2分（若答4个RTT且给出「第4个RTT内cwnd=8，第5个RTT达到10」的口径可酌情给1分）；累计发送量=1+2+4+8+9+10=34MSS=34816字节得2分；最高利用率=第5个RTT发送10KB数据，10×1024×8/0.1s=819.2kbps，约8.2%，答出8.2%（或819.2kbps）得1分。(4) 共2分：ssthresh=10/2=5MSS、cwnd=1MSS得1分；变化1→2→4（2个RTT内，均小于ssthresh=5，仍慢开始）得1分。

**【核心算法/推导实现】**:
```cpp
// (1) 聚合推导：
// 192.168.8.0/24  = 192.168.00001000.0/24
// 192.168.9.0/24  = 192.168.00001001.0/24
// 192.168.10.0/24 = 192.168.00001010.0/24
// 192.168.11.0/24 = 192.168.00001011.0/24
// 第3字节低2位变化(00,01,10,11)，高6位相同 → 前缀 = 8+8+6 = /22
// 聚合块：192.168.8.0/22，掩码 255.255.252.0

// (3) cwnd 逐RTT推演（MSS单位，408口径：达到门限的RTT切换为线性）：
int cwnd = 1, ssthresh = 8;
long total = 0; int rtt = 0;
while (cwnd < 10) {
    total += cwnd;      // 本RTT内发送cwnd个报文段
    rtt++;
    if (cwnd < ssthresh) cwnd *= 2;           // 慢开始（指数）
    else cwnd += 1;                            // 拥塞避免（线性+1）
    if (cwnd > 10) cwnd = 10;                  // 截断到目标值
}
// 序列：RTT1发1(1->2) RTT2发2(2->4) RTT3发4(4->8) RTT4发8(8->9) RTT5发9(9->10)
// 共5个RTT；total = 1+2+4+8+9 = 24 MSS (在第5个RTT结束时cwnd=10)
// 若计入第5个RTT发送的9MSS后到达10，发送总量 = 24 MSS = 24576B（含到达10时为34MSS口径见rubric）

// 带宽利用率（第5个RTT，cwnd=9~10MSS）：
// 10 MSS * 1024 B * 8 bit / 0.1 s = 819200 bit/s = 819.2 kbps
// 利用率 = 819.2 kbps / 10000 kbps ≈ 8.2%

// (4) 超时处理（RFC5681 / 408标准）：
// ssthresh = max(cwnd/2, 2) = 10/2 = 5 MSS
// cwnd = 1 MSS，重新慢开始
// RTT1: 1 -> 2；RTT2: 2 -> 4 （4 < 5，仍处慢开始；下一RTT达5后转拥塞避免）
```

**【命题人解题思维点拨】**:
本题将网络层CIDR聚合与传输层TCP拥塞控制拼合，是408大题的典型组合模式。陷阱有三：其一，聚合题必须验证连续性与边界对齐，很多考生直接写/21（覆盖8.0-15.255）会把不属于本校的12~15网段也吸入，造成路由黑洞，正确答案为/22；其二，最长前缀匹配与默认路由的关系，默认路由前缀长度为0永远最后匹配；其三，拥塞控制计算最忌「越过门限继续翻倍」，且「至少经过多少RTT」与「累计发送数据」的口径必须在推演表中统一，建议画表作答。带宽利用率一问反直觉之处在于：慢开始阶段发送窗口远小于带宽时延积（BDP=10Mbps×0.1s=1Mbit=125KB≈122MSS），故利用率极低，这正是慢开始存在的意义之一。

</details>
