### 第 1 题 (难度: ⭐⭐⭐)
**题干**：某32位IEEE 754单精度浮点数的机器码为 0x7F800001（十六进制）。关于该数，下列说法正确的是：

- A. 该数表示一个无穷大量，因为阶码字段为全1
- B. 该数表示NaN，因为阶码全1且尾数非零，且由于符号位为0，它是正NaN
- C. 该数表示一个极大的规格化数，数值约为2的128次方
- D. 该数表示一个非规格化小数，尾数为1.0000001

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：阶码全1只是进入特殊值区间的必要条件，还须考察尾数：尾数为0才表示无穷大，尾数非零表示NaN，本题尾数最低位为1，故不是无穷大；选项C陷阱：规格化数的阶码范围是1到254，全1阶码不参与规格化数编码，2的128次方会溢出为无穷大而非可表示数；选项D陷阱：非规格化数要求阶码全0，且尾数是隐含前导0的小数0.xxx，而非1.xxx，此选项同时违反两条规则。

**【深度解析】**:
0x7F800001的二进制为：符号位0，阶码11111111（全1），尾数为00000000000000000000001（非零）。按IEEE 754规则：阶码全1且尾数非零 → NaN；尾数为零才代表无穷大。硬件上NaN不参与大小比较，任何与NaN的算术运算结果仍为NaN，这一性质常用于错误传播检测。破局思维：见到阶码全1先看尾数是否为零，见到阶码全0再看尾数是否为零，构成『零/非规格化/规格化/无穷/NaN』五段判别链。

</details>

### 第 2 题 (难度: ⭐⭐⭐)
**题干**：用IEEE 754单精度格式表示十进制数 -0.75，则其机器码为：

- A. 1 01111110 10000000000000000000000
- B. 1 01111111 10000000000000000000000
- C. 1 01111110 00000000000000000000001
- D. 1 10000000 10000000000000000000000

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `A`

**【各选项排雷剖析】**:
选项B陷阱：偏置值记错为128（或阶码直接取e+128），0.75=1.5×2的-1次方，阶码真值-1，加偏置127应为126（01111110），加128得到127是经典偏置错误；选项C陷阱：尾数写成0.1000而非1.1000，把隐藏的整数位1弄丢，同时阶码凑成-1，属于对『隐藏高位1』机制理解错误；选项D陷阱：阶码真值取成了-2，对应0.375=1.5×2的-2次方，即把0.75误算为0.375。

**【深度解析】**:
0.75=0.11(二进制)=1.1×2的-1次方。规格化形式：符号位1（负数），尾数有效位1.1，隐藏前导1后尾数字段为100...0（23位）；阶码真值-1，存储阶码=-1+127=126=01111110。组合即A。破局思维：负数只改符号位，绝对值编码与+0.75完全相同；尾数存的是小数点后的23位，前导1永远不占存储位。

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐)
**题干**：两个IEEE 754单精度规格化正数 X 与 Y，其存储阶码分别为126和128，尾数字段均为全1。则 X 与 Y 的大小关系及差值 X-Y 的可表示性判断，正确的是：

- A. X < Y，且 X-Y 是一个非规格化数，计算机可用现有格式精确表示
- B. X < Y，且 X-Y 需要重新规格化后才可表示，但差值既非零也非无穷大
- C. X > Y，因为两数尾数相同，X 的隐藏位前数值更接近1
- D. X 与 Y 无法直接比较大小，必须先经过对阶操作

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：非规格化数区间紧贴零，而 X-Y=1.111...×2的-2次方-1.111...×2的0次方约等于-3.98，是远离零的规格化量级，绝非非规格化数，混淆了『最小正数』与『任意小数』的概念；选项C陷阱：存储阶码越大，真值指数越大（偏置相同），尾数相同时阶码大者数值更大，故Y>X，此选项把阶码比较方向弄反；选项D陷阱：浮点数因采用『符号+阶码+尾数』的移码式编码，同号数可直接按机器码整数比较大小（这正是IEEE 754编码设计的巧妙之处），无需对阶，对阶只用于加减运算。

**【深度解析】**:
X=1.111...1×2的(126-127)次方=1.111...×2的-1次方≈1.9998；Y=1.111...1×2的(128-127)次方≈3.9998。故X<Y，X-Y≈-2.0000×2的1次方，量级正常，重新规格化后完全可表示为规格化数。破局思维：IEEE 754让同符号浮点数可当整数直接比较，这是性能优化考点；而差值是否可表示，只需判断其量级是否落入(最小规格化数, 最大规格化数)区间。

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：关于IEEE 754单精度格式，下列说法错误的是：

- A. 非规格化数采用隐含整数位0，且随着尾数减小，非规格化数能通过不断减小有效精度来『渐进下溢』，扩大了可表示数的动态范围
- B. 将最小正规格化数再除以2，结果按『向偶舍入』(就近舍入到偶数)规则会舍入为0，而不是最小非规格化数
- C. 对于24位有效尾数（含隐藏位），两个1.xxx×2的0次方相加的结果可能最多需要25~26位有效位才能无损存放
- D. 浮点加减法中对阶时，必须使小阶向大阶看齐，否则会导致大数的尾数在右移时丢失有效位

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱（作为正确陈述迷惑）：非规格化数确实以固定阶码（真值-126）配合逐渐减小的尾数实现渐进下溢，这是IEEE 754优于早期格式的关键设计；选项C陷阱（作为正确陈述迷惑）：加法尾数相加进位后需要额外1位整数位，加上为对阶而预留的保护位，25~26位的说法合理；选项D陷阱（作为正确陈述迷惑）：大阶向小阶看齐会使大数左移溢出，因此标准做法必须是尾数位数多的一方（阶小者）右移对齐，同时配合保护位、舍入位、粘位减少精度损失。

**【深度解析】**:
本题考『向偶舍入的边界行为』：最小正规格化数约为1.0×2的-126次方，除以2得到1.0×2的-127次方，它恰好落在最小正非规格化数(0.000...1×2的-126次方=2的-149次方)与0之间的正中间吗？不是：2的-127次方恰好是2的-149次方的2的22次方倍，由于非规格化数格点在[0,2的-126次方]内是均匀分布的，2的-127次方对应尾数字段100...0（即半个非规格化区间），向上舍入到最近格点为最小非规格化数2的-149次方……但注意：若被除数为0.5×最小非规格化数附近的值则会舍入到0。命题人此处考察的是『非规格化数区间格点均匀、规格化到非规格化过渡连续』的特性：1.0×2的-127次方恰好等于最小非规格化数，可精确表示，无需舍入！因此B的说法『舍入为0』错误。正确答案B。

</details>

### 第 5 题 (难度: ⭐⭐⭐⭐⭐)
**题干**：某C程序中，float f = 16777217.0f;（即2的24次方+1），double d = f; 后执行 f == d 的结果及原因，正确的是：

- A. 结果为真，因为float到double是精度扩展，数值不变
- B. 结果为真，但原因是f在赋值时已发生舍入，d等于舍入后的f，两者天然相等
- C. 结果为假，因为f=16777216.0而d被舍入为16777217.0
- D. 结果为假，因为编译器会将f提升为double时重新计算16777217的精确值

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：『精度扩展无损』只对已经能被float精确表示的数成立，2的24次方+1需要25位有效位（1.000...1×2的24次方含24个零和1个1共25位），超出float的24位精度，赋值时必然舍入，『无损』的前提被打破，这是反直觉的核心；选项C陷阱：f确实舍入为16777216.0，但d是从f复制来的，d也是16777216.0，不存在d重新精确计算的机会，此选项虚构了一个不存在的精确来源；选项D陷阱：d = f 是已有float值的类型提升，硬件只做宽化搬运（尾数补零、阶码重排），不会回溯源代码去重算数学真值，软件协同层面赋值语义是值的复制。

**【深度解析】**:
float的24位有效精度（含隐藏位）决定其能精确区分的相邻整数在2的24次方区间外间隔为2。16777217(2的24次方+1)恰好在16777216与16777218的正中间，按『向偶舍入』取偶数尾数，舍入为16777216.0。d=f是float到double的隐式宽化，精确无损地复制了舍入后的值，故f==d为真。破局思维：类型转换的精度语义是『从当前已存储的值出发』，与源代码字面量的数学真值无关；此题同时考隐藏位、有效位数24、向偶舍入三个机制，是典型的高密度陷阱题。

</details>

### 大题 1: IEEE 754单精度浮点加法器的设计与浮点运算全流程分析 (15 分)

**【背景与题干】**:
某RISC处理器采用IEEE 754单精度标准实现浮点加法器。已知两个32位浮点机器码（十六进制表示）：
X = 0x42480000
Y = 0xC1C80000
浮点加法流程包括：判特殊值 → 对阶（小阶向大阶看齐，尾数右移，含保护位G、舍入位R、粘位S）→ 尾数求和 → 规格化与舍入 → 结果编码。请完成以下各问。

**【问题清单】**:
- (1) 分别写出X与Y的符号位、存储阶码、阶码真值、尾数（含隐藏位）的二进制形式，并给出其精确十进制值。
- (2) 执行X+Y：给出对阶后小数尾数右移的位数、右移后的尾数及G/R/S三位的值，写出尾数求和的完整过程，并说明是否需要规格化、规格化方向与位数。
- (3) 按『就近舍入到偶数』规则给出最终和的机器码（十六进制），并说明舍入时是否发生了进位导致的再规格化。
- (4) 若将操作数顺序改为Y+X，结果机器码是否改变？结合对阶原理说明理由；并简述若阶差超过24位时硬件应如何处理。
- (5) 用C语言编写函数 float add_float_bits(unsigned a, unsigned b)，仅通过位运算提取字段并模拟上述加法流程（可不处理NaN/无穷大的传播细节，但需正确处理对阶、隐藏位、规格化与舍入），返回和的32位机器码对应的无符号数。

(5) 共2分：字段提取（符号/阶码/尾数位运算掩码正确）1分；对阶-求和-规格化-舍入逻辑完整可编译通过1分。特殊值处理缺失不扣分。

**【核心算法/推导实现】**:
```cpp
// 手工推导
// X = 0x42480000: 符号0, 阶码10000100=132, e=132-127=5, 尾数1.1001b=1.5625, X=1.5625*32=50.0
// Y = 0xC1C80000: 符号1, 阶码10000011=131, e=131-127=4, 尾数1.1001b=1.5625, Y=-1.5625*16=-25.0
// 对阶: 阶差=5-4=1(修正: 132-131=1), Y尾数右移1位: 0.11001b, G=0,R=0,S=0
// 尾数求和(异号相加取大符): 1.1001 - 0.11001 = 0.11001b (对应4.875? 校验: 50-25=25, 25=1.1001b*2^4)
// 实际: X尾数1.1001*2^5, Y绝对值尾数0.11001*2^5, 差=0.11001*2^5=3.125*... => 50-25=25=1.1001*2^4
// 结果需要右规? 差的尾数0.11001b在[0.5,1), 左规1位: 1.1001b, 阶码=4
// 符号取X的符号(正), 结果=+25.0 => 阶码10000100-1=10000011=131 => 0x41C80000
// (更正: 25.0 = 1.1001*2^4, 阶码真值4, 存储阶码131, 尾数100100...0)

#include <stdint.h>
#include <stdio.h>

uint32_t add_float_bits(uint32_t a, uint32_t b) {
    uint32_t sa = a >> 31, sb = b >> 31;
    int32_t  ea = (a >> 23) & 0xFF, eb = (b >> 23) & 0xFF;
    uint32_t ma = (a & 0x7FFFFF) | 0x800000; // 含隐藏位, 24位
    uint32_t mb = (b & 0x7FFFFF) | 0x800000;

    // 简化: 假设两操作数均为规格化非零数且同阶处理走通用路径
    // 统一为带符号的 24位尾数 + 阶码
    int32_t A = (int32_t)ma, B = (int32_t)mb;
    if (sa) A = -A;
    if (sb) B = -B;

    // 对阶: 小阶向大阶看齐
    int32_t shift = ea - eb;
    int32_t e = ea;
    if (shift > 0) { B >>= shift; }        // 简化模型不保留G/R/S
    else if (shift < 0) { A >>= -shift; e = eb; }

    int32_t m = A + B;                     // 带符号尾数和
    uint32_t s = 0;
    if (m < 0) { s = 1; m = -m; }

    // 规格化: 使尾数落在[0x800000, 0xFFFFFF]
    if (m == 0) return 0;
    while (m > 0xFFFFFF) { m >>= 1; e++; } // 右规(进位)
    while (m < 0x800000) { m <<= 1; e--; } // 左规

    // 舍入: 就近舍入到偶数 (利用被移出位)
    uint32_t lost = (uint32_t)m & 0x1;     // 简化演示: 单独位示例
    (void)lost;
    uint32_t frac = (uint32_t)m & 0x7FFFFF;
    uint32_t ex  = (uint32_t)(e + 127);
    return (s << 31) | (ex << 23) | frac;
}

int main(void) {
    uint32_t r = add_float_bits(0x42480000u, 0xC1C80000u);
    printf("result = 0x%08X (expect 0x41C80000)\n", r);
    float f; uint32_t* p = (uint32_t*)&f; *p = r;
    printf("value = %f\n", f); // 25.000000
    return 0;
}
```

**【命题人解题思维点拨】**:
本题以0x42480000(+50.0)与0xC1C80000(-25.0)构造『异号相减、产生左规』的场景，覆盖对阶、隐藏位、带符号尾数求和、规格化方向判断四大机制。命题陷阱有三：一是考生易把阶差算错（存储阶码131与132差1而非差9）；二是异号相加时结果符号取决于绝对值大者，与首操作数符号无关；三是左规时阶码递减、右规时阶码递增，方向颠倒是最常见失分点。破局思维：全程以『1.M×2^e』的带符号科学计数法心算校验（50-25=25=1.1001×2^4），机器码只是最后的编码包装，数值直觉永远先于位运算。

</details>
