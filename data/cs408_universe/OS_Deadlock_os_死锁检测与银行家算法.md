## 🎯 高陷阱单选专项演练

### 第 1 题 (难度: ⭐⭐⭐⭐)
**题干**：系统中有同类资源 5 个，进程 P1、P2、P3 分别已持有 2、2、1 个，P3 又提出了 1 个资源请求并立即得到满足。此时系统处于何种状态？

- A. 系统一定死锁，因为形成了环路
- B. 系统一定不安全，因为剩余可用资源为 0
- C. 系统可能不安全但一定未死锁，属于死锁避免策略失效的场景
- D. 系统仍处于安全状态，因为不存在循环等待

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：死锁需要环路且环路上进程均等待环内资源，此处 P3 已获满足并不等待，未形成环路；选项B陷阱：不安全不等于死锁，Available=0 只说明可能无安全序列，当前各进程未必进入阻塞等待；选项D陷阱：误把循环等待当作唯一条件，安全状态判定需构造安全序列而非只看有无环；选项C陷阱说明：正确——可用资源耗尽导致系统进入不安全区，但只要进程尚未因等待而阻塞就未死锁，这是『不安全状态是死锁的必要而非充分条件』的典型反例。

**【深度解析】**:
总资源5，分配 2+2+1=5，Available=0。若 P1 或 P2 的新 Need 大于 0，则无法完成任一进程，无安全序列，状态不安全；但此刻没有进程处于等待队列中，资源也已全部在用，不存在『持有并等待』的阻塞事实，故未死锁。破局思维：严格区分『状态判定』（静态矩阵）与『死锁判定』（动态等待图），不安全只是潜在风险。

</details>

### 第 2 题 (难度: ⭐⭐⭐)
**题干**：关于死锁的四个必要条件，下列说法正确的是：

- A. 破坏『请求保持』条件可采用一次性申请全部资源法，其资源利用率一定高于按序申请法
- B. 『循环等待』条件破坏后其余三个条件即使同时成立也不会死锁，故银行家算法本质上就是破坏循环等待
- C. 采用剥夺式调度破坏『不剥夺』条件时，若资源状态不可保存（如打印机），该策略不可行
- D. 互斥条件不可能被破坏，因此死锁预防策略在实际系统中均无效

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：一次性全申请虽破坏请求保持，但会长期占住闲置资源，利用率通常更低；选项B陷阱：银行家算法属于死锁避免（动态判断安全状态），并非破坏任一必要条件的预防策略；选项D陷阱：互斥可用 SPOOLing 技术把独占设备改造为共享，死锁预防并非无效，只是代价不同；选项C说明：正确——剥夺的前提是被剥夺资源的状态可以保存和恢复（如 CPU、内存页），打印机正在打印时被剥夺会输出错乱。

**【深度解析】**:
命题核心是辨析『预防（静态破坏必要条件）』与『避免（动态安全判定）』的边界，以及剥夺策略的硬件约束。SPOOLing 的存在证明互斥可被间接破坏；剥夺式只适用于状态可保存的资源。破局思维：把每条策略映射到具体资源和代价上，而非背结论。

</details>

### 第 3 题 (难度: ⭐⭐⭐⭐)
**题干**：某系统采用银行家算法，当前 Available=[3,3,2]。已知存在安全序列 <P1, P3, P4, P2, P0>，若此时进程 P0 发出请求 Request0=[0,2,0]，系统按银行家算法检查后的正确结论是：

- A. 因为试探分配后 Available 变为 [3,1,2] 仍可能找到安全序列，所以立即分配
- B. 只需比较 Request0 ≤ Available 即可决定分配，无需再检查 Request0 ≤ Need0
- C. 需要先试探分配并执行完整安全性检查，若找不到安全序列则让 P0 等待
- D. 因为存在已知安全序列，任何不超过 Available 的请求都必须被批准

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `C`

**【各选项排雷剖析】**:
选项A陷阱：『仍可能找到』是模糊表述，银行家算法要求试探后严格重算 Need/Allocation/Available 并穷举验证安全序列，不能凭直觉批准；选项B陷阱：漏掉 Request ≤ Need 检查会允许进程超量申请（申请超过声明的最大需求属于非法请求，应报错而非等待）；选项D陷阱：已有的安全序列在试探分配后可能失效，旧序列不能保证新状态安全；选项C说明：正确，银行家算法两道门槛（Need 检查、Available 检查）加一道安全验证缺一不可。

**【深度解析】**:
银行家算法流程：① Request ≤ Need？② Request ≤ Available？③ 试探分配后跑安全性算法。任何一步失败即回滚。陷阱在于考生常省略第③步或忘记回滚恢复数据结构。破局思维：把算法当作带回滚的事务，每一步都是必要检查而非充分直觉。

</details>

### 第 4 题 (难度: ⭐⭐⭐⭐)
**题干**：资源分配图中，若系统当前不含任何环路（即等待图为森林），则下列判断正确的是：

- A. 系统一定处于安全状态
- B. 系统一定不会死锁，但可能处于不安全状态
- C. 系统可能死锁，因为环路只是死锁的充分条件
- D. 系统一定不会死锁，且对每类资源仅一个实例的系统而言，无环等价于无死锁

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `D`

**【各选项排雷剖析】**:
选项A陷阱：无环只保证当前无死锁，不保证有安全序列，不安全状态也可能无环（进程尚未发出新请求）；选项B陷阱：混淆『安全状态』与『无死锁状态』——无环可推出无死锁，但推不出安全；选项C陷阱：方向反了，对每类单实例系统环路是死锁的充分必要条件，多实例下环路才是必要不充分；选项D说明：正确，无环⇒无死锁在任意系统中成立，且单实例时二者等价，这是死锁检测算法（资源分配图化简）的理论基础。

**【深度解析】**:
关键在于三组概念的蕴含关系：无环⇒无死锁（恒成立）；死锁⇒有环（恒成立）；有环⇒死锁仅在每类资源单实例时成立。安全状态是更强的静态保证，与有无环无关。破局思维：画蕴含链条，注意『单实例』这一限定词激活的充要关系。

</details>

### 第 5 题 (难度: ⭐⭐⭐)
**题干**：系统有 3 类资源和 4 个进程，若已知每类资源总数分别为 W1、W2、W3，各进程最大需求之和远超总数。有人断言：『只要任意时刻至少存在一个进程的 Need ≤ Available，系统就安全』。该断言：

- A. 正确，因为该进程可先完成并释放全部资源
- B. 错误，该进程完成后释放的是 Allocation，其余进程仍可能因 Need 满足不了而相继阻塞，需迭代验证全体进程能否完成
- C. 正确，因为银行家算法只需找到第一个可满足的进程即可终止
- D. 错误，因为安全性还取决于进程提出请求的时序先后

<details><summary><b>👉 查看答案与致命陷阱拆解</b></summary>

**【正确答案】**: `B`

**【各选项排雷剖析】**:
选项A陷阱：单个进程可完成≠全体可完成，必须把它释放的资源叠加后继续迭代，任一轮无新进程可完成则不安全；选项C陷阱：安全序列是一个完整排列，算法必须标记完成所有进程，中途停顿等于漏判；选项D陷阱：银行家算法的安全性检查与请求到达时序无关，它只关心当前快照下是否存在可行顺序——时序影响的是未来状态，不影响当前快照判定；选项B说明：正确，安全性检查本质是迭代不动点计算。

**【深度解析】**:
安全性算法：重复扫描所有未完成进程，找 Need_j ≤ Work 者，将其 Allocation 加回 Work 并标记完成；若所有进程完成则安全。断言错在把『一轮局部可行』当成『全局不动点可达』。破局思维：把 Work 看作滚动累加的池子，验证的是全流程闭环，而非单步可行。

</details>

## 🏆 综合应用与算法设计大题

### 大题 1: 银行家算法的手算安全性检查与代码实现 (15 分)

**【背景与题干】**:
某系统有 A、B、C 三类资源，总数分别为 Total=(10, 5, 7)。当前时刻有 5 个进程 P0~P4，其 Allocation 矩阵与 Max 矩阵如下（行序 P0~P4）：
Allocation：P0=(0,1,0)，P1=(2,0,0)，P2=(3,0,2)，P3=(2,1,1)，P4=(0,0,2)。
Max：P0=(7,5,3)，P1=(3,2,2)，P2=(9,0,2)，P3=(2,2,2)，P4=(4,3,3)。
此刻进程 P3 发出请求 Request3=(1,0,1)。请按银行家算法完整流程处理该请求，并对结果状态执行安全性检查。

**【问题清单】**:
- (1) 计算当前的 Need 矩阵与 Available 向量，并写出计算式。
- (2) 判断 Request3=(1,0,1) 能否立即满足？若能，给出试探分配后三个数据结构的新值。
- (3) 对试探分配后的状态执行安全性算法，给出安全序列或判定为不安全，要求列出每一轮 Work 向量的变化过程。
- (4) 若把 P3 的请求改为 Request3=(1,0,2)，结论有何不同？说明原因。
- (5) 编写 C 语言函数 int safety_check(int Need[][3], int Allocation[][3], int *Available, int n, int m)，返回是否存在安全序列，并在安全时通过参数输出其中一个安全序列。

<details><summary><b>👉 查看踩分标准与标准参考实现</b></summary>

**【考研阅卷踩分细则】**:
总 15 分。
(1) 共 3 分：Need=Max-Allocation 每行 0.5 分（共 2.5 分），Available=Total-ΣAllocation=(3,3,2) 得 0.5 分；任何一行算错该行不得分。
(2) 共 2 分：检查 Request3 ≤ Need3 得 0.5 分；≤ Available 得 0.5 分；试探分配后 Available=(2,3,1)、Need3=(0,1,0)、Allocation3=(3,1,2) 各 0.5 分（共 1.5 分，四舍五入计 2 分上限）；未做回滚说明不扣分但若后续结果与回滚不一致倒扣 1 分。
(3) 共 4 分：正确执行迭代 Work 变化（如 2,3,1→P1 完成后 4,3,1→P3 完成后 7,4,3→P0 后 7,5,3→P2 后 10,5,5→P4 后 10,5,7），每轮 0.5 分共 2.5 分；给出安全序列 <P1,P3,P0,P2,P4>（答案不唯一，合理即可）得 1 分；最终 Available 恢复 (3,3,2) 之验证或明确声明已回滚再判定得 0.5 分。
(4) 共 2 分：指出 Request3=(1,0,2) 虽满足 Request≤Need 但 Request≤Available 不成立（2>1）故 P3 必须等待得 1.5 分；只答『不安全』未区分检查步骤不得分；说明若盲目试探将导致 Available 为负/状态非法再加 0.5 分。
(5) 共 4 分：Finish 数组初始化 1 分；Need_j ≤ Work 的比较按向量逐分量实现 1 分；Work += Allocation 并标记 Finish、记录序列 1 分；函数有正确返回值与序列输出、边界处理（找不到可完成进程即返回 0）1 分。代码编译错误最多得 1 分。

**【核心算法/推导实现】**:
```cpp
/* 第(1)问 Need 矩阵 = Max - Allocation
   P0=(7,4,3)  P1=(1,2,2)  P2=(6,0,0)  P3=(0,1,1)  P4=(4,3,1)
   Available = (10,5,7) - (0+2+3+2+0, 1+0+0+1+0, 0+0+2+1+2)
             = (10,5,7)-(7,2,5) = (3,3,2)

第(2)问：Request3=(1,0,1) ≤ Need3=(0,1,1)? 逐分量 1>0 不成立!
   注意：Request3 的 A 分量 1 已超过 Need3 的 A 分量 0，
   该请求非法（超出声明最大需求），系统应报错拒绝。
   【修正讨论】若命题意图考察试探流程，假设 Request3=(0,1,0)：
   则 0≤0,1≤1,0≤1 成立且 ≤Available=(3,3,2) 成立。
   试探后：Available=(3,2,2)，Need3=(0,0,1)，Allocation3=(2,2,1)。

第(3)问 安全性检查（以试探 Request3=(0,1,0) 后为例）：
  Work=(3,2,2)，Finish 全 false
  轮1：P1 Need(1,2,2)≤(3,2,2) → 完成，Work=(3+2,2+0,2+0)=(5,2,2)
  轮2：P3 Need(0,0,1)≤(5,2,2) → 完成，Work=(7,3,3)
  轮3：P0 Need(7,4,3)≤(7,3,3)? 4>3 否；P2 Need(6,0,0)≤(7,3,3) → 完成，Work=(10,3,5)
  轮4：P0 Need(7,4,3)≤(10,3,5)? 4>3 否；P4 Need(4,3,1)≤(10,3,5) → 完成，Work=(10,3,7)
  轮5：P0 Need(7,4,3)≤(10,3,7)? 4>3 否 → 存在进程无法完成 → 不安全！
  （注意：P0 的 B 分量 Need=4 恒大于 Work 的 B 分量最大值 3，
    因为 B 类资源总量 5 中 P0 已占 1，Work 的 B 分量最多为 4-1=3+...
    实际上全回滚原始状态 Available=(3,3,2) 下：
    轮1：P1 Need(1,2,2)≤(3,3,2) → Work=(5,3,2)
    轮2：P3 Need(0,1,1)≤(5,3,2) → Work=(7,4,3)
    轮3：P4 Need(4,3,1)≤(7,4,3) → Work=(7,4,5)
    轮4：P0 Need(7,4,3)≤(7,4,5) → Work=(7,5,5)
    轮5：P2 Need(6,0,0)≤(7,5,5) → Work=(10,5,7) → 安全！
    安全序列 <P1,P3,P4,P0,P2>。可见 Request3=(0,1,0) 试探后反而使
    P0 永远差 1 个 B 资源，故银行家算法应拒绝该请求，令 P3 等待。）

最终结论：Request3=(1,0,1) 非法拒绝；Request3=(0,1,0) 合法但试探后
状态不安全，同样拒绝，P3 等待。原状态安全，安全序列 <P1,P3,P4,P0,P2>。 */

#include <stdio.h>
#include <stdbool.h>

/* 返回 1 表示安全并写入 safe_seq（长度 n），0 表示不安全 */
int safety_check(int Need[][3], int Allocation[][3],
                 int *Available, int n, int m, int *safe_seq)
{
    int work[3];
    bool finish[16] = { false };
    int i, j, k, cnt = 0;
    for (j = 0; j < m; j++) work[j] = Available[j];

    while (cnt < n) {
        bool found = false;
        for (i = 0; i < n; i++) {
            if (!finish[i]) {
                bool ok = true;
                for (j = 0; j < m; j++)
                    if (Need[i][j] > work[j]) { ok = false; break; }
                if (ok) {
                    for (j = 0; j < m; j++)
                        work[j] += Allocation[i][j];
                    finish[i] = true;
                    safe_seq[cnt++] = i;
                    found = true;
                }
            }
        }
        if (!found) return 0;   /* 一轮扫描无进展 → 不安全 */
    }
    return 1;
}

int main(void)
{
    int n = 5, m = 3;
    int Max[5][3]    = { {7,5,3},{3,2,2},{9,0,2},{2,2,2},{4,3,3} };
    int Alloc[5][3]  = { {0,1,0},{2,0,0},{3,0,2},{2,1,1},{0,0,2} };
    int Available[3] = { 3, 3, 2 };
    int Need[5][3], seq[5], i, j;

    for (i = 0; i < n; i++)
        for (j = 0; j < m; j++)
            Need[i][j] = Max[i][j] - Alloc[i][j];

    if (safety_check(Need, Alloc, Available, n, m, seq)) {
        printf('safe sequence: ');
        for (i = 0; i < n; i++)
            printf('P%d%s', seq[i], i == n - 1 ? '' : ' -> ');
        printf('\n');
    } else
        printf('unsafe state\n');
    return 0;
}
/* 输出：safe sequence: P1 -> P3 -> P4 -> P0 -> P2 */
```

**【命题人解题思维点拨】**:
本题三重陷阱：其一，Request3=(1,0,1) 的第一个分量 1 超过 Need3 的 A 分量 0，多数考生会跳过 Request≤Need 检查直接进入试探分配，掉入第一重陷阱；其二，即使假设合法请求 (0,1,0)，试探后 P0 的 Need B 分量 4 将永远大于 Work 的 B 分量上限，系统由安全转为不安全，考生若凭『原状态安全所以小请求可批准』的直觉必错——这正是银行家算法『不保证已批准请求后仍安全』的精髓；其三，安全性检查要求迭代到不动点，单轮找到可满足进程就宣布安全是高频失分点。破局思维：把试探分配当作事务，先验证合法性、再验证安全性、失败必回滚；手算时建议逐轮列表记录 Work 变化，避免口算出错。

</details>
