# 📚 408 考点深度剖析与变式题库：TCP滑动窗口与拥塞控制

## ⚡ 一、核心考点秒懂精髓

**底层机制**：
- 拥塞控制四种算法协同：**慢启动**（每 RTT cwnd 翻倍，指数增长，cwnd ≥ ssthresh 时切换）、**拥塞避免**（每 RTT cwnd + 1 MSS，线性加法增大）、**快重传**（收到 3 个重复 ACK 立即重传，不等超时）、**快恢复**（快重传后 ssthresh = cwnd/2，cwnd = ssthresh（Tahoe 为 1），进入拥塞避免）。
- 发生**超时**（网络严重拥塞）：ssthresh = 当前 cwnd/2，cwnd 重置为 **1 MSS**，重新慢启动。
- 实际发送窗口 = **min(rwnd, cwnd)**；零窗口时发送方启动**持续计时器**，周期性发送**零窗口探测报文**（1 字节数据，打破死锁）。

**口诀**：
> **“超时归一从慢启，门限减半记心间；三个重复走快恢，减半续跑拥避线。”**
> 折线图解题：每到一个**整数 RTT 节点**判断 cwnd 与 ssthresh 大小关系决定是×2 还是 +1。

## ⚠️ 二、考场高频杀手陷阱透析

**陷阱 1：cwnd 单位混淆（MSS vs 字节 vs 报文段）**
- 题目常给“cwnd = 16 KB，MSS = 1 KB”，考生直接写 cwnd = 16 个 MSS 没问题；但若 cwnd = 8192 B、MSS = 1000 B，则每个 RTT 只能发 8 个报文段而非 8.192 个，必须**向下取整**。408 真题（2009 年）即以“cwnd 从 1 开始按指数规律增长，到 16 个 MSS 时进入拥塞避免”考查切换点——切换条件是 **cwnd ≥ ssthresh 时改用拥塞避免**（含等号）。

**陷阱 2：“第几个 RTT 发送多少”的 off-by-one 与首次发送时点**
- “第 1 个 RTT 结束后 cwnd 翻倍”与“第 1 个 RTT 内发送 cwnd 个报文段”是两回事。经典真题问“从 cwnd=1 到 cwnd=16 需几个 RTT”——答案是 **4 个**（1→2→4→8→16），不是 5 个。慢启动共发送报文段数为 **2ⁿ − 1**（首 RTT 发 1 个）。
- 快恢复时 cwnd = 新 ssthresh（**不重新慢启动**），很多考生误设为 1。

**陷阱 3：窗口变化节点判定与 ACK 触发时机**
- 折线图题中，ssthresh 的更新发生在**丢包事件被检测到的 RTT**，而 cwnd 的增减以 **ACK 到达**为准：拥塞避免是每收到 1 个 ACK cwnd += MSS/cwnd（等效每 RTT +1），慢启动是每收到 1 个 ACK cwnd += MSS（等效每 RTT ×2）。若题目问“累计发送量”，需将各 RTT 的窗口值**求和**（等比数列求和 2ⁿ−1 + 等差数列求和），考生常漏加最后一轮。
- 零窗口探测：接收窗口为 0 后发送方**停止发送**但**不能撤销已发数据**，探测报文仍周期发送——选项中“连接关闭”/“等待 ACK 后重传全部数据”均为干扰。

## 🎯 三、经典真题同源变式题 1（单项选择）

【题目背景】
主机 A 与 B 建立 TCP 连接，MSS = 1 KB，A 的 cwnd 初始为 1 MSS，ssthresh 初始为 8 MSS。运行过程中 A 在 cwnd = 12 MSS 时发生**超时**，随后拥塞窗口按规则变化。假设此后到下一次事件前网络无丢包，则从超时发生后，A 的 cwnd 第一次达到 4 MSS 需要经过多少个 RTT？

- A. 1 个 RTT
- B. 2 个 RTT
- C. 3 个 RTT
- D. 4 个 RTT

【正确答案】：**B**

【深度解析】：
1. 超时 → ssthresh = 12/2 = 6 MSS，**cwnd = 1 MSS**，重新慢启动（排除 A：A 忽略了超时须归 1 重启慢启动）。
2. 第 1 个 RTT 后：cwnd = 2 MSS（仍 < 6，继续慢启动）。
3. 第 2 个 RTT 后：cwnd = 4 MSS，**首次达到 4**，选 B。
4. C（3 个 RTT）的陷阱：误把“cwnd 到 4 之后再继续走”或把切换时刻算错（若误认为 ssthresh = 4 会在 cwnd=4 切换，但结果仍是 2 RTT 达到 4，C 实为“还需再 +1 到下一节点”的多算）；D 是按“每次 +1”线性增长计算（误把超时当快恢复处理，cwnd = 3 → +1 逐步走），未区分超时与三重复 ACK 的处理差异。

## 🚀 四、经典真题同源变式题 2（综合应用大题）

【综合大题】
主机 A 通过 TCP 向 B 发送数据，MSS = 1 KB，RTT 固定为 100 ms，初始 cwnd = 1 MSS，初始 ssthresh = 16 MSS。传输过程中仅发生**一次**丢包事件：当 cwnd 首次达到 20 MSS 时发生**三重重复 ACK**（无超时）。此后网络不再丢包。
1. 画出/列出从连接建立（cwnd=1）起，每个 RTT 结束时的 cwnd 变化序列（单位：MSS），直至 cwnd ≥ 20 后再经历 2 个 RTT。
2. 计算从开始到丢包被检测时刻，A 最多可发送的数据总量（字节）。
3. 丢包后 ssthresh 与 cwnd 各变为多少？说明依据。
4. 若丢包是**超时**而非三重重复 ACK，重答第 3 问，并比较两种机制下 cwnd 恢复到 10 MSS 所需 RTT 数的差异。

【输出要求】：明确列出每个 RTT 节点的 cwnd 与 ssthresh 值，给出关键判断依据（cwnd 与 ssthresh 的比较）。

【解题思路】：
- 阶段划分：慢启动（1→16，指数）→ 拥塞避免（16→17→…→20，线性）→ 丢包分流（快恢复 vs 超时归 1）。
- 发送总量 = 慢启动阶段几何级数和 + 拥塞避免阶段算术和（注意首 RTT 发 1 个）。

【参考步骤（含伪代码验证）】：

```c
// 拥塞窗口演化模拟（以 MSS 为单位，每 RTT 一步）
long long cwnd = 1, ssthresh = 16, sent = 0; // 单位: MSS
int rtt = 0;
while (cwnd < 20) {
    sent += cwnd;              // 本 RTT 内可发送 cwnd 个报文段
    rtt++;
    if (cwnd < ssthresh) cwnd = cwnd * 2;      // 慢启动
    else cwnd = cwnd + 1;                       // 拥塞避免
    if (cwnd > 20) cwnd = 20;                  // 丢包前封顶
}
// 三重重复ACK:
ssthresh = cwnd / 2;   // 20/2 = 10
cwnd     = ssthresh;   // 快恢复: cwnd = 10
// 超时情形:
// ssthresh = 10; cwnd = 1; 重新慢启动
```

**详细答案**：

1. **cwnd 序列**：1 → 2 → 4 → 8 → 16（第 4 个 RTT，慢启动，因 16 < ssthresh=16 不成立，cwnd=16 时切换）→ 17 → 18 → 19 → 20（第 8 个 RTT，拥塞避免）→ 丢包后三重 ACK：20 → **10** → 11（再 2 个 RTT：10、11）。
   完整序列：**1, 2, 4, 8, 16, 17, 18, 19, 20, 10, 11**。

2. 发送总量 = (1+2+4+8+16) KB + (16+17+18+19) KB = 31 + 70 = **101 KB**（丢包在 cwnd 首次达到 20 的 RTT 被检测，该 RTT 内发送的 20 KB 计入与否取决于题设“检测时刻”，标准答案取检测前：若含该 RTT 则为 121 KB；408 惯例按“达到 20 时发生丢包”，总量 = **101 KB**，需在卷面注明口径）。

3. 三重重复 ACK → 快重传 + 快恢复：**ssthresh = 20/2 = 10 MSS，cwnd = 10 MSS**（Tahoe 才归 1，408 默认 Reno/Tahoe 需按题意判断；新 TCP 标准为 Reno）。

4. 超时 → ssthresh = 10 MSS，**cwnd = 1 MSS**，重新慢启动。
   - 快恢复路径：cwnd = 10，**0 个 RTT** 即恢复到 10。
   - 超时路径：1→2→4→8→16？不行，ssthresh=10，cwnd=8 < 10 继续慢启动到 16 ≥ 10 切换——实际序列 1→2→4→8→10（到 10 时达 ssthresh）：从 1 到 10 需 **4 个 RTT**（1→2→4→8→16 超过 10，第 4 个 RTT 时 cwnd=16 ≥ ssthresh；精确到“首次达到 10”：1→2→4→8→(8+1=9? 不) —— 严格按指数：RTT1:2, RTT2:4, RTT3:8, RTT4:16 但 cwnd 不能越过 ssthresh 后继续指数，故在 RTT4 起进入拥塞避免，达到 10 实际在 RTT4 与 RTT5 之间；按整数节点首次 ≥10 为 RTT4）。**差异：快恢复比超时至少节省 3~4 个 RTT**，体现了 Reno 对轻度拥塞（三重 ACK）不彻底重启连接、快速恢复吞吐的设计思想。

**时空复杂度分析**：
- 模拟代码：时间复杂度 **O(log₂(ssthresh) + (cwnd_max − ssthresh))**，即慢启动 O(log n) + 拥塞避免 O(n)，n 为目标窗口；空间复杂度 **O(1)**（仅维护 cwnd、ssthresh 两个标量）。
- 手算捷径：慢启动总和 = 2^(k+1) − 1（k 为慢启动 RTT 数），拥塞避免总和 = 等差数列公式，无需逐项累加，考场 30 秒出结果。
