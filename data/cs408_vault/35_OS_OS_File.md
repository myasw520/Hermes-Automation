# 📚 408 考点深度剖析与变式题库：文件系统与目录结构

## ⚡ 一、核心考点秒懂精髓

**底层机制：**
- **物理结构决定随机访问能力**：连续分配支持随机访问但难扩展；隐式链接只能顺序存取（第 i 块需 i 次磁盘 I/O）；显式链接（FAT）把链接表调入内存，支持随机访问；索引分配（inode）通过索引块实现随机访问，混合索引（直接块 + 一级/二级/三级间接块）是计算最大文件体积的核心模型。
- **混合索引最大文件公式**：`Max = (直接块数 + ⌊索引块容量/块地址⌋ + ⌊(索引块容量/块地址)²⌋ + …) × 物理块大小`，其中索引块容量 = 物理块大小，每项存一个块地址。
- **位示图法**：字号 n、位号 m（均从 0 开始），块号 = `n × 每行位数 + m`；反算：字号 = `⌊块号/每行位数⌋`，位号 = `块号 mod 每行位数`（若从 1 开始编号则需 ±1 调整）。
- **硬链接**：多个目录项指向同一 inode，引用计数值 +1，删除任一名字仅减计数，计数值为 0 才真正释放；不能跨文件系统。**软链接**：独立文件，内容是被指文件的路径名，原文件删除后软链接成“悬空链接”，可跨文件系统。

**记忆口诀：**
> 「连续随机链接顺，FAT 随机查内存表；inode 大小看间接，直接加幂次乘块长。」
> 「位图块号 = 行号×每行位 + 位号；硬链接计数为 0 才释放，软链接存路径可悬空。」

## ⚠️ 二、考场高频杀手陷阱透析

**陷阱 1：混合索引计算中“间接块本身也占一个物理块”被忽略**
- 一级间接块指针指向的那个块是**索引块**（也占一块磁盘空间但不计入文件数据），二级间接块需要**先读一级索引块，再读二级索引块**，两重开销。考生常把 `(b/a)²` 算成一级间接的延续，或忘记判断“文件只需部分间接块时，最大体积仍按满算”。**必须先算单个索引块能装多少地址：`a/b`（块大小/地址大小），向上取整无关，直接整除。**

**陷阱 2：位示图编号起点混乱（从 0 还是从 1）**
- 408 真题中行列编号可能从 0 或 1 开始，公式截然不同：从 0 开始为 `块号 = i×W + j`；从 1 开始为 `块号 = (i-1)×W + j`。题目不指明时默认从 0 开始，但必须回题干验证。另外注意“字号、位号”与“行、列”的对应关系，以及结果是否需要 +1（题目问“第几个块”而非“块号”）。

**陷阱 3：硬链接计数与目录共享混淆**
- 考生误以为删除原文件名后硬链接仍可用是因为“复制了文件”（错！它们共享同一 inode）；或误认为软链接删除原文件后软链接自动删除（错！软链接成为悬空链接，路径解析失败但不报链接错）；或在树形目录中通过硬链接形成**环路**导致遍历死循环，这是 UNIX 限制硬链接不能指向目录的原因。FAT 系统不支持硬链接也是易混点。

## 🎯 三、经典真题同源变式题 1（单项选择/计算题）

【题目背景】某文件系统采用**混合索引分配**方式，inode 中包含 8 个直接地址项、1 个一级间接地址项、1 个二级间接地址项。物理块大小为 **4 KB**，每个磁盘地址占 **4 B**。磁盘上文件数据区（不含索引块）总容量为 1 TB。问：该系统支持的**单个最大文件体积**最接近以下哪个值？

- A. 约 4 GB
- B. 约 8 GB + 32 KB
- C. 约 4 GB + 40 KB
- D. 约 1 TB（受磁盘总容量限制，理论计算无意义）

【正确答案】**B**

【深度解析】
- 每个索引块可容纳地址数：`4 KB / 4 B = 1024` 个。
- 直接块：`8 × 4 KB = 32 KB`。
- 一级间接：`1024 × 4 KB = 4 MB`。
- 二级间接：`1024 × 1024 × 4 KB = 4 GB`。
- 合计：`32 KB + 4 MB + 4 GB ≈ 4 GB + 4 MB + 32 KB`。

等等——严格计算应为 **4 GB + 4 MB + 32 KB**，但选项中最接近的是？重新核对：选项 B 写 "8 GB" 是干扰，正确精确值 = 4 GB + 4 MB + 32 KB。按题目规范修正选项：

- A. 约 4 GB（漏掉一级间接与直接块）✗
- B. **约 4 GB + 4 MB + 32 KB** ✓
- C. 约 4 GB + 32 KB（漏掉一级间接的 4 MB，最常见错误）✗
- D. “受 1 TB 限制无意义”——陷阱项：单个最大文件由 inode 结构决定，4 GB 远小于 1 TB，磁盘容量不构成约束，"1 TB" 诱导考生把文件系统总量与单文件上限混淆。✗

**正确答案：B**。核心陷阱在于 C 项：考生记住“直接块 + 二级间接”却遗漏一级间接项；D 项诱导混淆“文件系统容量”与“单文件最大体积”。

## 🚀 四、经典真题同源变式题 2（综合应用/大题设计）

【综合大题】某文件系统物理块大小 **2 KB**，磁盘共有 **1024 个盘块**（块号 0 ~ 1023，盘块 0 固定保留）。系统采用**位示图法**管理空闲盘块，位示图存放在内存中，每字 **16 位**，字号、位号均**从 0 开始**编号，"1" 表示占用，"0" 表示空闲。

1) 该位示图共需多少个字？
2) 若当前字号 5、位号 10 的位为 0，申请分配该块，求对应盘块号。
3) 若盘块号 800 被释放，写出其对应字号与位号。
4) 现要求实现 `int alloc_block()`：在位示图中寻找任意一个空闲块并分配，返回块号；若无空闲块返回 -1。要求时间复杂度尽可能低，不得开辟与位示图总大小同阶的额外数组。

【解题思路】
- 第 1 问：1023 个待管理盘块（去掉 0 号），每位管一块，共需 `⌈1023/16⌉ = 64` 个字。
- 第 2 问：块号 = 字号 × 16 + 位号 = 5 × 16 + 10 = **90**。
- 第 3 问：字号 = ⌊800/16⌋ = 50，位号 = 800 mod 16 = **0**。
- 第 4 问：维护一个“扫描指针” `next_hint` 记录上次分配位置，下次从该处开始找，均摊接近 O(1)；释放时置 0 并可回退指针。用位运算逐字检测：若整字为 `0xFFFF`（全占）则跳过，实现字级加速。

【参考代码/步骤】（C 实现）

```c
#define W 64            /* 位示图字数 */
#define TOTAL 1024      /* 管理块号 1..1023 */
unsigned short bitmap[W];
int next_hint = 0;      /* 扫描指针 */

int alloc_block(void) {
    for (int k = 0; k < W; ++k) {          /* 最多扫一整圈 */
        int i = (next_hint + k) % W;
        if (bitmap[i] != 0xFFFF) {         /* 字级快速跳过全占字 */
            for (int j = 0; j < 16; ++j) {
                if (!(bitmap[i] & (1u << j))) {
                    bitmap[i] |= (1u << j);
                    next_hint = i;         /* 更新提示指针 */
                    int blk = i * 16 + j;
                    return (blk >= 1 && blk <= TOTAL) ? blk : -1;
                }
            }
        }
    }
    return -1;                              /* 无空闲块 */
}

void free_block(int blk) {                  /* blk ∈ [1,1023] */
    bitmap[blk / 16] &= ~(1u << (blk % 16));
    next_hint = blk / 16;                   /* 指针回退加速复用 */
}
```

【时空复杂度分析】
- **时间**：最坏情况（仅剩 1 个空闲块且位于指针之前）需扫描全部 64 个字，即 **O(W) = O(磁盘块数/字长)**；但由于字级跳过（`!= 0xFFFF` 一次判断排除 16 块）与 `next_hint` 均摊效应，平均性能远优于逐位扫描。若再维护空闲块计数器，可在 O(1) 内判定“无空闲”。
- **空间**：仅使用 `next_hint` 一个额外变量与常数临时变量，**O(1) 辅助空间**，位示图本身不计入额外开销，满足“不得开辟同阶额外数组”的约束。
