# 📚 408 考点深度剖析与变式题库：TCP传输层与三次握手

## ⚡ 一、核心考点秒懂精髓

- **三次握手本质**：同步通信双方的初始序号（ISN）并确认双向信道可用。SYN=1 的报文段**消耗一个序号**，ACK 不消耗序号。seq 与 ack 的规则：**ack = 对方上一次发来的 seq + 数据长度（SYN/FIN 各计 1）**。
- **四次挥手本质**：双向独立关闭数据通道；主动方收到 ACK 后进入 FIN_WAIT_2，收到对方 FIN 并回 ACK 后进入 TIME_WAIT，停留 **2MSL**。2MSL 的两大意义：①保证最后一个 ACK 若丢失可重传（对方重发 FIN 时能应答）；②使本连接所有报文在网络中消逝，避免旧连接报文干扰新连接。
- **可靠传输**：累计确认（ack=n 表示 n 之前全部收到）；快速重传（收到 **3 个重复 ACK** 立即重传，不等超时）；RTO 由 RTT 加权平均计算（RFC6298：SRTT = (1-α)·SRTT + α·RTT，α=1/8；RTTVAR 及 RTO = SRTT + 4·RTTVAR）。
- **口诀**：*“SYN 消耗一个号，ack 等于对方号加一；FIN 同耗一号，TIME_WAIT 等两个 MSL；三个重复 ACK 快重传，数据号加长度等于确认号。”*

## ⚠️ 二、考场高频杀手陷阱透析

1. **SYN/FIN 是否消耗序号判断失误**：考生常误以为 SYN 或 FIN “不占序号”，导致握手第三段 seq=ISN+1 写成 ISN、挥手后确认号计算错误。**规则：SYN 和 FIN 均消耗 1 个序号，纯 ACK 不消耗**。若 SYN 段还携带 1 字节数据，消耗 2 个序号。

2. **ack 与 ACK 标志位混淆 / 大小写陷阱**：ack（确认号字段）= 期望收到的下一个字节序号，是**累计确认**；ACK 是控制位。考生在填表题中把“确认号”写成“对方发送的序号本身”，少加 1；或把累计确认误当成选择性确认。

3. **TIME_WAIT 出现的主体与时长错误**：TIME_WAIT 出现在**主动关闭方**（不是被动方），持续 **2MSL**（一个 MSL 保证最后 ACK 可达，一个保证迟到的重传 FIN 消逝）。被动关闭方进入 LAST_ACK → CLOSED，不经历 TIME_WAIT。此外：若服务器大量 TIME_WAIT，说明服务器是**主动关闭方**——这也是选择/简答陷阱。

4. **滑动窗口与拥塞窗口联动丢分**：快速重传后是“门限=ssthresh/2，cwnd=ssthresh（新版）”进入**拥塞避免**（快恢复），不是回到 1 开始慢启动——与“超时事件”后 cwnd=1 区分。

## 🎯 三、经典真题同源变式题 1（单项选择/计算题）

【题目背景】主机 A 与主机 B 建立 TCP 连接，A 的初始序号 ISN=2018，B 的初始序号 ISN=5060。握手完成后，A 连续发送了两个 TCP 报文段：第一个携带 100 字节数据，seq=2019；第二个携带 200 字节数据。B 正确收到第一个报文段，但第二个报文段丢失。随后 B 发送一个确认报文段。**问**：该确认报文段中，B 发送的是（　）

- A. seq=5061，ack=2119
- B. seq=5061，ack=2319
- C. seq=5060，ack=2319
- D. seq=5061，ack=2120

【正确答案】：**A**

【深度解析】：
- B 的 seq：握手第三段 B→A 的报文中，B 的序号为 ISN_B+1 = 5061（SYN 消耗一个序号）。排除 C（误用 ISN 原值）。
- B 的 ack：**累计确认**，B 只正确收到了 seq=2019 起 100 字节，即序号 2019~2118，故确认号 = 2019+100 = **2119**，即“期望收到的下一个字节”。排除 B（误以为收到全部，2119+200=2319，是“假设未丢包”的陷阱）；排除 D（多加 1，混淆 SYN 消耗序号规则，误把数据也当作报文段级加一）。

## 🚀 四、经典真题同源变式题 2（综合应用/大题设计）

【综合大题】主机 A 与服务器 B 建立 TCP 连接，双方 ISN：A 侧 ISN=1000，B 侧 ISN=8000。RTT 基础测量值与事件序列如下。假设 MSS=500B，初始 ssthresh=8（单位：KB，cwnd 初值 1KB），MSL=30s。请回答：

(1) 写出三次握手中三个报文段的 seq、ack、SYN/ACK 标志位（不含数据）。
(2) 连接数据传输阶段，A 依次发送序号 1001~1500 的报文段 S1 和 1501~2000 的 S2，S2 丢失，S3（2001~2500）到达。B 共发送多少个重复 ACK 后触发 A 的快速重传？快速重传时 B 最后一个 ACK 的 ack 值是多少？
(3) 采用 Reno 算法：当 cwnd 增长到 8KB 时发生快速重传，写出重传后 ssthresh 与 cwnd 的值；若随后又发生超时，写出再次后的 ssthresh 与 cwnd。
(4) 数据发送完毕，A 主动关闭连接，写出四次挥手各报文段标志位，并说明 A 在 TIME_WAIT 状态停留多久、为什么。

【解题思路】：
- (1) 套用“SYN 耗一号”规则逐段推导。
- (2) 失序报文 S3 到达时 B 每次发送重复 ACK（ack 停留在缺口处）；快速重传阈值 = 3 个重复 ACK。
- (3) Reno：快重传→ssthresh=cwnd/2，cwnd=ssthresh（新 ssthresh）；超时→ssthresh=cwnd/2，cwnd=1KB 慢启动。
- (4) TIME_WAIT=2MSL，从“保证 ACK 可重传”与“旧报文消逝”两个角度作答。

【参考答案/步骤】：

(1)
| 报文段 | 方向 | 标志 | seq | ack |
|---|---|---|---|---|
| ① | A→B | SYN=1 | 1000 | — |
| ② | B→A | SYN=1, ACK=1 | 8000 | 1001 |
| ③ | A→B | ACK=1 | 1001 | 8001 |

(2) S2 丢失，S3 失序到达，B 每收到一个失序段就发重复 ACK。收到 S3 后 B 发出的重复 ACK 携带 ack=**1501**（期望收到缺口起点）。加上后续可能到达的失序段，**累计 3 个重复 ACK** 即触发 A 快速重传 S2（第 1 个是正常确认 S1 的 ack=1501，随后 3 个重复才触发，注意“3 个重复”即共 4 个 ack=1501）。

(3) 快速重传时 cwnd=8KB：
- ssthresh = 8/2 = **4KB**，cwnd = **4KB**（进入拥塞避免）；
- 再次超时：ssthresh = 4/2 = **2KB**，cwnd = **1KB**（慢启动）。

(4) 四次挥手：
1. A→B：FIN=1, seq=u（A 数据最后一字节号+1）；
2. B→A：ACK=1, ack=u+1，B 进入 CLOSE_WAIT；
3. B→A：FIN=1, ACK=1, seq=w, ack=u+1；
4. A→B：ACK=1, ack=w+1，A 进入 TIME_WAIT。
A 在 TIME_WAIT 停留 **2MSL = 60s**。原因：①若最后的 ACK 丢失，B 会重传 FIN，A 处于 TIME_WAIT 可重新应答，保证可靠释放；②等待本连接产生的所有报文段在网络中消逝（最长存活期 MSL），防止旧报文串扰复用同一 (IP, port) 的新连接。

【时空复杂度分析】：本题为协议状态推导题。握手/挥手各报文推导为 O(1)；拥塞窗口演化按轮次推演为 O(轮数)，即 O(k)（k 为传输轮次），空间 O(1)——仅需维护 cwnd、ssthresh、两个 ISN 共四个状态变量，与数据总量 n 无关（常数空间），这也是 TCP 状态机“有限状态、无历史依赖（除累计确认号）”的体现。
