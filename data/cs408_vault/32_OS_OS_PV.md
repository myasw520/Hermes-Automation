# 📚 408 考点深度剖析与变式题库：PV信号量同步互斥

## ⚡ 一、核心考点秒懂精髓
- **底层机制**：记录型信号量 `S` 含整型值 `value` 与等待队列 `L`。`P(S)`：`value--`，若 `value<0` 则进程阻塞入 `L`；`V(S)`：`value++`，若 `value≤0` 则唤醒 `L` 中一个进程。**互斥**：同一互斥信号量初值为 1，临界区前 P 后 V，P/V 必须成对且在同一进程内；**同步**：前操作 V，后操作 P（“前V后P”），信号量初值为资源数或 0。
- **互斥四原则**：空闲让进、忙则等待、有限等待、让权等待。
- **口诀**：互斥“夹在中间同进程，先P后V不能反”；同步“前V后P，一个资源一个信号量”；多类信号量P操作顺序决定死锁，**资源号排序申请防死锁**。

## ⚠️ 二、考场高频杀手陷阱透析

1. **P 操作顺序颠倒引发死锁**（哲学家、多生产者多消费者）
   - 哲学家问题：五人同时 `P(chopstick[i])` 后再 `P(chopstick[(i+1)%5])`，形成循环等待。三种修正：①最多允许 4 人同时拿筷子；②奇数号先左后右、偶数号先右后左；③用互斥信号量包住“取两只筷子”的原子操作（注意：此法破坏并发度但可进大题答案）。
   - 盘子问题：父亲放苹果、母亲放橘子，女儿吃苹果、儿子吃橘子。**若先 P(plate) 再 P(mutex)，与消费者顺序交叉即可能死锁**；正确写法 P 顺序需一致（先资源信号量后互斥信号量，或反过来，全题统一）。

2. **同步信号量与互斥信号量混淆、初值错误**
   - 缓冲区大小为 n 的生产者-消费者：`empty=n, full=0, mutex=1`。**empty 在生产者 P、消费者 V；full 相反；mutex 夹住缓冲区读写，不能夹住 P(empty)/P(full)**——若把 P(mutex) 放到 P(empty) 之前，缓冲区满时生产者持锁阻塞，消费者永远进不来 → 死锁。

3. **读者-写者读优先问题中的计数器丢失**
   - `count` 是共享变量，**第一个读者 P(w) 与最后一个读者 V(w) 必须用 P(mutex)/V(mutex) 保护 count 的判断与修改**，只保护 `count++` 而不保护 `if(count==0) P(w)` 是经典扣分点。另外写优先需增加 `w_wait` 信号量使后续读者在写者到达时排队，否则写者饿死。V 操作顺序错误（V(w) 未在 mutex 保护内正确配对）会导致读进程永久阻塞。

## 🎯 三、经典真题同源变式题 1（单项选择）

【题目背景】桌上有一个盘子，一次只能放一个水果。父亲专放苹果，母亲专放橘子；女儿专吃苹果，儿子专吃橘子。信号量定义如下：

```c
semaphore plate = 1;   // 盘子空位
semaphore apple = 0;   // 苹果数
semaphore orange = 0;  // 橘子数
semaphore mutex = 1;   // 保护盘子
```

父亲进程代码：`P(plate); P(mutex); 放苹果; V(mutex); V(apple);`
女儿进程代码：`P(①); P(mutex); 取苹果; V(mutex); ②;`

问：①② 处应分别填入什么？该设计中 mutex 是否可省略？

- A. ①为 P(apple)，②为 V(orange)；mutex 可省略
- B. ①为 P(apple)，②为 V(plate)；mutex 可省略
- C. ①为 P(plate)，②为 V(plate)；mutex 不可省略
- D. ①为 P(apple)，②为 V(plate)；mutex 不可省略

【正确答案】：**B**

【深度解析】：
- 女儿吃苹果前必须确认盘中已有苹果 → 同步信号量 `P(apple)`，故排除 C（P(plate) 是放水果者的操作，会造成死锁）。
- 取走苹果后盘子空 → 必须通知放水果者 `V(plate)`，②为 V(plate)，排除 A（V(orange) 是儿子/母亲一侧的信号量，V 错对象）。
- 关键鉴别点：**mutex 可省略**。因为 `plate=1`，每次只允许一个“放/取”动作进行，缓冲区容量为 1 时，父亲放与女儿取天然互斥，plate 与 mutex 功能重叠。D 的前半句正确但后半句错误，是命题人利用考生“凡缓冲区必加 mutex”的定势思维设置的陷阱。**结论：容量为 1 的缓冲区，资源信号量本身即可充当互斥锁。**（对比：408 真题原题考查的正是“能否省略 mutex”这一判定。）

## 🚀 四、经典真题同源变式题 2（综合应用/大题）

【综合大题】某银行提供 1 个服务窗口和 10 个供等待客户坐的座位。客户到达时若有空座位则坐下取号等待，否则离开；柜员从座位上叫一位客户服务。要求：

1. 用信号量机制写出客户进程与柜员进程的同步/互斥代码（伪代码）；
2. 说明每个信号量的物理意义与初值；
3. 分析：若将 P mutex 语句置于 P seat 之后是否正确，说明理由。

【解题思路】
- 分层：①座位容量控制（同步，资源数 10）；②客户与柜员之间的“服务—完成”同步（两个 0 值信号量）；③座位状态的互斥访问（判断+入座是复合临界区）。
- 客户：`P(mutex)`（保护座位判断）→ 有座则 `V(customer)`、`P(service)` 接受服务、`V(finish)` 离开；无座则 `V(mutex)` 离开。
- 柜员：`P(customer)`（有客户才服务）→ `V(service)` 叫号 → `P(finish)` 等待服务完成 → `V(mutex)` 释放座位。

【参考代码/步骤】

```c
semaphore mutex = 1;      // 互斥访问座位区
semaphore seat   = 10;    // 空座位数（同步）
semaphore customer = 0;   // 等待服务的客户数
semaphore service  = 0;   // 柜员叫号，客户可入窗口
semaphore finish   = 0;   // 客户确认服务开始
int waiting = 0;          // 座位上等待的客户数（共享，受mutex保护）

Customer_i() {
    P(mutex);
    if (waiting < 10) {        // 有空座位
        waiting++;
        V(customer);           // 通知柜员有客
        V(mutex);
        P(service);            // 等待叫号
        接受服务;
        V(finish);             // 通知柜员服务开始完成
    } else {
        V(mutex);              // 无座，离开
    }
}

Barber() {                     // 柜员进程（循环）
    while (true) {
        P(customer);           // 无客户则睡眠
        V(service);            // 叫号
        P(finish);             // 等待该客户响应
        V(mutex);              // 释放一个座位
        提供服务;
    }
}
```

【时空复杂度分析】
- **时间复杂度**：单个客户进程的 PV 序列为常数次原子操作，O(1)；n 个客户到达总操作次数 O(n)。信号量阻塞/唤醒由内核队列实现，均为 O(1)。
- **空间复杂度**：5 个信号量 + 1 个共享计数器，O(1)（与客户总数无关，等待队列由 OS 维护）。
- **关键点解答（问题3）**：本设计中 `P(mutex)` 必须在判断 `waiting` 之前，且柜员通过 `V(mutex)` 释放座位而非客户自己——若让客户在 `P(service)` 后自行 `V(mutex)`，则当座位满时客户直接离开，`waiting` 判断与增减仍需互斥保护，逻辑可等效但**柜员侧 V(mutex) 与客户侧 P 顺序必须严格配对**，否则会出现 mutex 被多 V 或漏 V，破坏互斥，导致 `waiting` 计数错误（隐性越界：实际入座 > 10）——这是阅卷中最常见的逻辑扣分点。
