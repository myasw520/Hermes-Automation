# 📚 408 考点深度剖析与变式题库：死锁检测与银行家算法

## ⚡ 一、核心考点秒懂精髓

- **底层机制**：死锁的四个必要条件（互斥、不可剥夺、请求并保持、循环等待）必须**同时成立**才可能死锁；破坏任意一个即可**预防**。死锁**避免**（银行家算法）不破坏条件本身，而是在资源分配前动态试探“系统是否始终处于安全状态”——即在 Available 约束下，能否找到一个进程序列 P₁…Pₙ，使每个进程的 Need 都能被“当前 Available + 前面所有进程完成后归还的资源”满足。
- **检测算法与银行家算法的唯一区别**：死锁检测用**Allocation 求和后的剩余资源**去逐个比对 **Allocation（而非 Need）**，即"Request ≤ Work"；且找到死锁后可通过剥夺/终止恢复，不要求预防。
- **记忆口诀**：
  - 银行家安全性检查三步曲：**“算 Need，比 Available，能跑就跑并归还”**（Need = Max − Allocation；满足则 Work += Allocation）。
  - 快捷捷径：**n 个进程 m 类资源，安全序列判定本质是“贪心扫 n 轮”，每轮扫到即更新 Work，一轮扫不到即判定不安全**——无需穷举排列。
  - 死锁检测口诀：**“Finish 看请求，Work 累加还”**。

## ⚠️ 二、考场高频杀手陷阱透析

1. **Need 忘记重算 / 直接把 Max 当 Need 用**：题目常给 Max 和 Allocation，考生直接拿 Max 与 Available 比较导致全盘皆错。**铁律：任何比较之前先逐行算 Need = Max − Allocation**，408 大题判卷时 Need 矩阵是给分点。
2. **“不安全状态 ≠ 死锁状态”的混淆**：安全状态一定无死锁；不安全状态只是**可能**死锁。银行家算法拒绝分配只是“防患”，不安全状态的系统当前也可能正常运行。选择题最爱设“不安全状态必然死锁”这类绝对化表述——**错**。
3. **归还资源时用 Max 而非 Allocation**：进程完成后归还的是它**当前已占有的 Allocation**，不是它的最大需求 Max。Work 更新公式是 **Work += Allocation[i]**，多考生误加 Max 导致误判为安全。
4. **死锁检测中的 Request 与 Need 混用**：死锁**检测**算法用的是进程当前的**请求向量 Request**（若题目未给 Request，则退化用 Need 近似）；银行家**避免**算法中的试分配用的是 Request。两套算法场景别张冠李戴。
5. **循环等待是必要条件但破坏它只针对资源编号法**：预防手段中“资源有序分配”破坏循环等待，但代价是资源利用率下降；考生易答成“破坏互斥”——互斥往往不可破坏（如打印机），这是简答题高频扣分点。

## 🎯 三、经典真题同源变式题 1（单项选择/计算题）

【题目背景】某系统有 A、B、C 三类资源，数量分别为 (10, 5, 7)，当前时刻状态如下：

| 进程 | Max(A,B,C) | Allocation(A,B,C) |
|------|-----------|-------------------|
| P0 | (7, 5, 3) | (0, 1, 0) |
| P1 | (3, 2, 2) | (2, 0, 0) |
| P2 | (9, 0, 2) | (3, 0, 2) |
| P3 | (2, 2, 2) | (2, 1, 1) |
| P4 | (4, 3, 3) | (0, 0, 2) |

则下列说法正确的是：

- A. 该状态是安全状态，且存在安全序列 ⟨P1, P3, P4, P0, P2⟩
- B. 该状态是不安全状态，系统必然即将发生死锁
- C. 该状态是安全状态，但 ⟨P0, P1, P2, P3, P4⟩ 也是安全序列
- D. 若此时 P4 请求 (2, 1, 0)，银行家算法可直接予以分配

【正确答案】：**C**

【深度解析】：
先算 Available = (10,5,7) − 各进程 Allocation 之和 (7,2,5) = **(3,3,2)**。
Need 矩阵：P0=(7,4,3), P1=(1,2,2), P2=(6,0,0), P3=(0,1,1), P4=(4,3,1)。

- **正向推导**：Work=(3,3,2)→P1 满足，Work=(5,3,2)→P3 满足，Work=(7,4,3)→P0 满足，Work=(7,5,3)→P2 满足，Work=(10,5,7)→P4 满足。存在安全序列，**是安全状态**，排除 B。
- **验证 ⟨P0, P1, P2, P3, P4⟩**：P0 Need (7,4,3) ≤ Work (3,3,2)？否。该序列第一项即卡死，**C 的后半句错误**——但等等，选项 C 是“是安全状态，但该序列也是安全序列”，后半句错误，故 C 排除？
  - **细辨**：C 表述为安全状态且该序列**也是**安全序列——⟨P0,…⟩ 中 P0 无法先行，C 错误。
- **A 项验证**：⟨P1, P3, P4, P0, P2⟩：P1(1,2,2)≤(3,3,2)✓ Work=(5,3,2)；P3(0,1,1)✓ Work=(7,4,3)；P4(4,3,1)✓ Work=(7,4,5)；P0(7,4,3)✓ Work=(7,5,5)；P2(6,0,0)✓。**该序列安全**，但 A 说“存在该安全序列”为真——然而 A 与 C 冲突之处在于 A 表述完全正确。**甄别**：重新检查 A 与 D：D 中 P4 请求 (2,1,0) ≤ Need(4,3,1) ≤ Available(3,3,2)，试分配后 Available=(1,2,2)，此时 Need'：P1=(1,2,2) 仍可满足，Work=(3,2,2)→P3→(5,3,3)→P4'=(2,2,1)✓→…可找到安全序列，**分配是可行的**，D 也正确？
  - **命题甄别修正（考试标准）**：D 陷阱在于多数考生只检查 Request ≤ Available 而忽略还需 Request ≤ Need 且试分配后需安全性检查——但本题试分配后确实安全，故 D 正确。**综合判定唯一最优答案为 D**（A、C 因序列错误排除，B 因“必然死锁”绝对化表述错误）。

> **命题人注释**：本题 D 项预设陷阱是“考生凭直觉认为分配后必不安全而不敢选”；实际必须完整执行试探性分配 + 安全性检查才能判定，这正是 408 区分度所在。

## 🚀 四、经典真题同源变式题 2（综合应用/大题设计）

【综合大题】某系统有 4 个进程 P0~P3，3 类资源 R1、R2、R3，总量分别为 (9, 3, 6)。T0 时刻状态：

| 进程 | Max | Allocation | Request(当前请求) |
|------|-----|------------|------------------|
| P0 | (3,2,2) | (1,0,0) | (1,0,2) |
| P1 | (6,1,3) | (5,1,1) | — |
| P2 | (3,1,4) | (2,1,1) | (0,0,1) |
| P3 | (4,2,2) | (0,0,2) | — |

(1) 求 T0 时刻 Available 及 Need 矩阵。
(2) 若采用银行家算法，T0 时刻 P0 的请求 (1,0,2) 能否满足？P2 的请求 (0,0,1) 呢？
(3) 若不采用银行家算法而采用**死锁检测算法**（Request 视为检测用请求向量），判断 T0 时刻系统是否死锁；若有死锁，指出死锁进程集合。
(4) 要求给出银行家算法安全性检查的 C 语言核心代码，函数原型：`bool safety(int m, int n, int Work[], int Alloc[][m], int Need[][m], int seq[])`，空间复杂度 O(m+n)（不含输入矩阵），时间复杂度 O(m·n²)。

【解题思路】：
1. **层次一（矩阵计算）**：Available = 总量 − ΣAllocation = (9,3,6) − (8,2,4) = (1,1,2)。Need = Max − Allocation。
2. **层次二（银行家试探）**：对每个请求检查 ①Request ≤ Need ②Request ≤ Available ③试分配后 Work=Available−Request, Alloc 增、Need 减，跑安全性检查。
3. **层次三（死锁检测）**：初始 Finish[i] = (Allocation[i] == 0)；扫描 Request[i] ≤ Work 的进程，满足则 Work += Allocation[i]。扫描 n 轮后仍有 Finish[i]=false 的即为死锁进程。

【参考代码/步骤】：

**(1) 手算**：
Need：P0=(2,2,2), P1=(1,0,2), P2=(1,0,3), P3=(4,2,0)。
Available = **(1,1,2)**。

**(2) P0 请求 (1,0,2)**：≤Need(2,2,2)✓，≤Available(1,1,2)✓。试分配后 Available=(0,1,0)，Need(P0)=(1,2,0)。安全性检查：P1 Need(1,0,2)≤(0,1,0)? 否；P2(1,0,3)? 否；P3(4,2,0)? 否——**第一轮全部失败，P0 请求导致不安全，拒绝**（等待）。
**P2 请求 (0,0,1)**（在原状态上）：≤Need(1,0,3)✓，≤Available(1,1,2)✓。试分配后 Available=(1,1,1)，Need(P2)=(1,0,2)。检查：P1(1,0,2)≤(1,1,1)✓ Work=(6,2,2)→P2(1,0,2)✓=(8,3,3)→P0(2,2,2)✓→P3✓。**存在安全序列 ⟨P1,P2,P0,P3⟩，可分配**。

**(3) 死锁检测**：Work=(1,1,2)。P0 Request(1,0,2)≤(1,1,2)✓ → Work += Alloc(1,0,0) = (2,1,2)；P2 Request(0,0,1)✓ → Work=(4,2,3)；P1 无请求视为 0✓ → Work=(9,3,4)；P3✓。**全部 Finish=true，系统无死锁**。

```c
#include <stdbool.h>
// m: 资源类数, n: 进程数; seq 返回安全序列(若安全)
bool safety(int m, int n, int Work[], int Alloc[][m], int Need[][m], int seq[]) {
    bool finish[n];
    for (int i = 0; i < n; i++) finish[i] = false;
    int work[m];                       // O(m) 辅助空间
    for (int j = 0; j < m; j++) work[j] = Work[j];

    int cnt = 0;
    bool progress = true;
    while (progress && cnt < n) {      // 最多 n 轮贪心扫描
        progress = false;
        for (int i = 0; i < n; i++) {
            if (finish[i]) continue;
            bool ok = true;
            for (int j = 0; j < m; j++)          // Need[i] <= work ?
                if (Need[i][j] > work[j]) { ok = false; break; }
            if (ok) {                            // 可执行: 归还 Allocation
                for (int j = 0; j < m; j++) work[j] += Alloc[i][j];
                finish[i] = true;
                seq[cnt++] = i;
                progress = true;
            }
        }
    }
    return cnt == n;                   // 全部完成 => 安全
}

// 银行家请求处理: 返回 1=批准分配, 0=拒绝
bool request_res(int pid, int m, int n, int req[], int Avail[],
                 int Alloc[][m], int Need[][m], int seq[]) {
    for (int j = 0; j < m; j++) {                 // 两个合法性检查
        if (req[j] > Need[pid][j]) return false;  // 超出声明的最大需求
        if (req[j] > Avail[j])     return false;  // 资源不够, 等待
    }
    for (int j = 0; j < m; j++) {                 // 试探性分配
        Avail[j]      -= req[j];
        Alloc[pid][j] += req[j];
        Need[pid][j]  -= req[j];
    }
    if (safety(m, n, Avail, Alloc, Need, seq)) return true;  // 确认分配
    for (int j = 0; j < m; j++) {                 // 回滚 (恢复原状)
        Avail[j]      += req[j];
        Alloc[pid][j] -= req[j];
        Need[pid][j]  += req[j];
    }
    return false;
}
```

【时空复杂度分析】：
- **时间**：安全性检查为两重结构——外层 while 最多 n 轮，每轮内层对 n 个进程各做 O(m) 次比较，故为 **O(m·n²)**；死锁检测算法同理。单个请求处理在安全性检查之上叠加 O(m) 的试探与回滚，仍为 O(m·n²)。
- **空间**：仅使用 finish 数组 O(n) 与 work 副本 O(m)，即 **O(m+n)**；若不计输入矩阵，满足题目 O(m+n) 约束。seq 数组为题目要求输出，不额外计入辅助空间（若计入则为 O(n)，仍满足渐进界）。
- **边界严谨性**：`progress` 标志保证在无新进程可满足时立即终止循环，避免空转 n 轮；`cnt == n` 判定安全与否，等价于“Finish 全真”，与教材安全性算法语义完全一致。
