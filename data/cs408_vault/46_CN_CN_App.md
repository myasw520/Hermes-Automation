# 📚 408 考点深度剖析与变式题库：应用层协议(DNS/HTTP)

## ⚡ 一、核心考点秒懂精髓
- **DNS**：域名→IP 的分布式映射系统，采用**递归查询**（主机→本地域名服务器）+ **迭代查询**（本地域名服务器→根/顶级/权限服务器）。运输层用 **UDP 53**（响应报文超过 512B 或区域传送时用 TCP 53）。
- **FTP**：**控制连接全程保持（端口 21，带外传送）**，数据连接按需建立（主动模式服务器用 20 端口连客户端；被动模式由服务器开临时端口）。控制信息带外传输，数据传输可中断。
- **HTTP**：基于 TCP（80 端口）的**无状态**协议。HTTP/1.0 每对象一个 TCP 连接；1.1 默认持久连接（流水线/非流水线）；2.0 引入二进制分帧 + 多路复用（同一连接并行多请求）。状态码：2xx 成功、3xx 重定向（301 永久 / 302 临时 / 304 缓存有效 Not Modified）、4xx 客户端错（403 禁止 / 404 未找到）、5xx 服务器错（500 内部错误 / 502 网关错误）。

**记忆口诀**：
> “DNS 递归找本地，本地迭代问根域；UDP 53 常用兵，TCP 区域才点名。”
> “FTP 控制 21 不撒手，数据 20 用完丢；HTTP 无状态，304 靠缓存。”
> **往返时间速算**：非持久连接取 n 个对象总时间 = 2×RTT₀ + n×2×RTT + n×传输时延；持久非流水线 = 2×RTT₀ + n×（RTT + 传输时延）；持久流水线 ≈ 2×RTT₀ + RTT + n×传输时延。

## ⚠️ 二、考场高频杀手陷阱透析

1. **DNS 递归/迭代主体混淆**：递归查询只发生在“主机→本地域名服务器”之间；本地服务器向根/顶级/权限服务器发出的是**迭代查询**。陷阱选项常写“根域名服务器向顶级域名服务器发出递归查询”或“主机向根域名服务器直接发迭代查询”——均错。另注意：UDP 53 是默认，但**区域传送（主从服务器同步）必须用 TCP**，选项常以“DNS 全部使用 UDP”设坑。
2. **FTP 端口号与连接状态张冠李戴**：控制连接（21）**贯穿整个会话期间始终打开**；数据连接（主动模式 20）每传一个文件建立/关闭一次。陷阱：①“数据连接端口恒为 20”——被动模式下服务器使用**临时端口**，20 只是主动模式；②“传输文件期间控制连接暂时关闭”——错，控制连接从不关闭；③“FTP 控制信息与数据共用在同一连接”——错，FTP 是带外传送。
3. **HTTP 状态码与连接计算的边界坑**：①**301 vs 302**：永久移动 vs 临时移动，搜索引擎权重转移与否，选项常互换；②**304 不是错误**：是协商缓存命中（If-Modified-Since/ETag 匹配），报文**无实体主体**；403 是“有资源但拒绝访问”≠404“资源不存在”；③**连接计算题**：忽略“请求/响应各占 1 个 RTT”的隐蔽代价，或忘记 1.1 非流水线仍需**每个对象串行**经历一个 RTT，只有流水线/2.0 才近似“一次 RTT 发全部请求”。

## 🎯 三、经典真题同源变式题 1（单项选择/计算题）

**题目**：某浏览器一次访问 Web 服务器 S，页面由 1 个基本 HTML 文件和 4 个引用的小图片组成，文件传输时间均忽略不计。已知 RTT₁ 为浏览器到本地域名服务器的往返时间，RTT₂ 为本地域名服务器迭代查询到权限域名服务器（两级缓存均未命中，忽略根与顶级服务器访问时间归并计入）获得解析结果的往返时间，RTT 为浏览器到 S 的单向往返时延。分别计算采用 HTTP/1.0（每对象新建 TCP）与 HTTP/1.1 非流水线持久连接的总时间，正确的组合是：

- A. 1.0：RTT₁+RTT₂+2RTT+8RTT；1.1：RTT₁+RTT₂+2RTT+4RTT
- B. 1.0：RTT₁+RTT₂+2RTT+8RTT；1.1：RTT₁+RTT₂+2RTT+5RTT
- C. 1.0：RTT₁+RTT₂+4RTT+8RTT；1.1：RTT₁+RTT₂+4RTT+4RTT
- D. 1.0：RTT₁+RTT₂+RTT+8RTT；1.1：RTT₁+RTT₂+RTT+5RTT

**正确答案**：A

**深度解析**：
- DNS 解析阶段：主机→本地服务器递归 1×RTT₁；本地→权限迭代 1×RTT₂。合计 RTT₁+RTT₂（排除 C、D 中 DNS 部分多算）。
- TCP 建立：1 个 RTT；请求 HTML + 收响应：1 个 RTT。故基础部分 = 2RTT。
- 1.0 非持久：4 张图片各新建 TCP（1 RTT）+ 请求响应（1 RTT）= 4×2RTT = 8RTT。总 = RTT₁+RTT₂+2RTT+8RTT。
- 1.1 非流水线持久：连接只建一次，4 个对象串行各占 1 RTT = 4RTT。总 = RTT₁+RTT₂+2RTT+4RTT。
- **陷阱说明**：B、D 中"5RTT"是经典错误——把 4 个对象的请求响应算成“1 次总 RTT + 4 次请求”，混淆了流水线与非流水线模式；若为流水线模式，图片部分才约等于 1RTT。C 把 TCP 建立与首次请求重复计算为 4RTT，属“三次握手占用一个 RTT 却另加握手报文时间”的典型重复计费错误。

## 🚀 四、经典真题同源变式题 2（综合应用/大题设计）

**综合大题**：某校园网主机 H 通过本地域名服务器 L 完成域名 `www.cs.univ.edu.cn` 的解析，L 的缓存中仅有 `edu.cn` 顶级域名服务器记录（含 `univ.edu.cn` 无缓存）。回答下列问题：

1. 指出 H→L、L→各级服务器分别采用的查询方式，并写出迭代查询下 L 依次访问的域名服务器顺序。
2. 若根域名服务器返回的应答报文长 800 字节，L 与根服务器之间的 UDP 报文能否承载？应改用何种方式？
3. 该校园网同时提供 FTP 服务（FTP 服务器作为 Web 服务器同主机）。用户甲已完成 FTP 登录，此时管理员重启了 FTP 服务进程但控制连接未断，甲发起 `RETR file.zip` 下载（主动模式）。简述控制连接与数据连接的端口及建立过程，并指出“文件传输过程中删除另一文件”的控制指令能否并行传输。
4. 若浏览器请求 `http://www.cs.univ.edu.cn/index.html`，服务器返回状态码 302 且 Location 指向新 URL，浏览器应如何处理？若返回 304 又意味着什么？

**解题思路**：
- 第 1 问抓住“递归只到本地，迭代由本地发起”；
- 第 2 问抓住 UDP 报文 512B 上限阈值与 TCP 区域传送机制；
- 第 3 问抓住控制/数据连接分离、控制连接带外且全程保持；
- 第 4 问区分 3xx 各码语义。

**参考步骤**：
1. H→L 为**递归查询**；L→根、顶级、权限为**迭代查询**。顺序：根域名服务器→（管理 `.cn` 或该层级结构下）`edu.cn` 顶级域名服务器→`univ.edu.cn` 权限域名服务器，最终由权限服务器返回 `www.cs.univ.edu.cn` 的 IP。
2. 800B > 512B，超出 UDP DNS 应答的常规承载能力（DNS 规定 UDP 报文通常限制为 512 字节，超出部分截断并置 TC 标志）。应**改用 TCP 53 端口**重新进行该查询（或依赖 EDNS0 扩展，但 408 标准答案为 TCP）。
3. 控制连接：客户端以**临时端口**连接服务器 **21** 端口，全程保持；数据连接（主动模式）：服务器从 **20** 端口主动向客户端告知的临时数据端口发起 TCP 连接，传完即断。“删除另一文件”的指令（如 DELE）走**控制连接**，与数据连接相互独立，**可并行传输**——这正是 FTP“带外传送、控制与数据分离”的设计要点。
4. 状态码 **302**：请求的资源临时移到 Location 指定的新 URL，浏览器应**向新 URL 重新发起 GET 请求**（临时重定向，原 URL 仍有效）。状态码 **304**：协商缓存命中，服务器告知浏览器本地缓存副本未修改、仍然有效，响应**不含实体主体**，浏览器直接使用缓存，无需重新传输对象。

**复杂度分析（DNS 解析过程角度）**：
- 时间：迭代解析最多经历 根→顶级→权限 三级，查询次数 O(d)（d 为域名层级深度，通常 ≤ 3~4 级）；若全程递归则压力集中于上层服务器，这也是实际采用“递归+迭代”混合模式的原因——将查询负载 O(n×d) 分摊到各级服务器。
- 空间：本地域名服务器缓存命中可将 O(d) 次跨网查询降为 0，缓存空间 O(c)（c 为缓存记录数），体现以空间换时间的典型权衡。
